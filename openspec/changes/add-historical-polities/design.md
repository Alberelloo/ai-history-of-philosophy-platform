# Design

## Контекст

- Глобус (`web/src/map/geo/GlobeView.tsx`) рисует сушу, береговую линию и границы государств на canvas 2D из `world-atlas/countries-110m.json`, собранного в клиентский фрагмент (`world.ts`). Подписи стран — SVG-текст, раскладка — `layout.ts` по правилу «Политическая карта». На вход раскладке идёт список `{id, name, feature}` (`COUNTRY_INPUT`), сам алгоритм от источника названий не зависит.
- Слой мест приходит с `GET /v1/map/places` (`knowledge/geo.py`), кэш LRU по области, событие `knowledge.geo.built`.
- Доступ к Wikidata есть только через `knowledge/wikidata.py`: один домен, адреса строит код, повторы по `Retry-After`, `Fetch` внедряется (в тестах — словарь фикстур).
- Внешние данные с лицензиями описаны манифестами в `sources/` (`epochs.yaml`, `portraits.yaml`, `licenses.yaml` с видом `cc-by-4.0`).
- Ограничения сервера: 1 CPU, 1,9 ГБ ОЗУ (свободно ~650 МБ при работающем стенде), 13 ГБ диска.

## Выбор решения

Пять вопросов из задания ведущего. Вариантов по каждому не меньше двух, включая самый простой. Критерии — из `docs/process/working-principles.md`, раздел 5.

### 1. Упрощение геометрии

| Вариант | Оптимальность | Архитектура | Поддержка и масштаб |
|---|---|---|---|
| А. Без упрощения, только округление координат до 0,01° | Ноль кода. Слой года — мегабайты: береговые линии Cliopatria детальные. H2 почти наверняка не выполняется | Просто | Размер растёт с детальностью следующих версий датасета |
| Б. Свой Дуглас–Пекер на чистом Python | Без зависимостей. Сотни миллионов операций на 1 CPU — десятки минут. Нужно писать и тестировать обработку дыр, вырожденных колец и самопересечений | Правило в одном модуле | Свой геометрический код — постоянный источник дефектов (самопересечения после упрощения) |
| В. `shapely.simplify(tolerance, preserve_topology=True)` по записи, затем `make_valid`, округление, отбор колец по площади, сферический обход | GEOS на C: секунды–минуты на весь датасет. Одна зависимость сборки (колесо ~2,5 МБ) | Только в модуле сборки, сервис на пути читателя её не импортирует | Порог и точность — данные манифеста, а не константы кода. Валидность геометрии гарантирует библиотека |
| Г. mapshaper (Node) с топологией: общие границы соседей упрощаются один раз, без щелей | Лучшее качество стыков. Но mapshaper держит весь датасет в памяти Node — гигабайты при 1,9 ГБ ОЗУ | Сборка Python-проекта зависит от Node-CLI | Вторая среда исполнения ради одного шага |

**Выбрано: В.** Чем платим: соседние образования упрощаются независимо, поэтому на стыках возможны щели и нахлёсты порядка допуска (~0,05°, около 5 км). На масштабе глобуса (приближение 1–8, линия 0,5–1 px) это почти незаметно. Обвод по морю у Cliopatria не совпадает с береговой линией Natural Earth — это риск R2. Костыли, которых избегаем: ручная правка геометрии отдельных образований по имени; подбор допуска «под один год» — допуск один на весь артефакт и записан в манифесте.

Параметры (в `sources/cliopatria.yaml`, раздел `build`): `tolerance_deg` (начальное 0,05), `precision` (2 знака, 0,01° ≈ 1,1 км), `min_ring_deg2` (0,01). Многоугольники и дыры меньше порога отбрасываются, но **самый большой многоугольник записи остаётся всегда**: образование не пропадает из слоя (инвариант «Сборка исторических границ»). Сетка `10^-precision` одна для всех записей (`shapely.set_precision` сохраняет валидность). Если самый большой многоугольник вырождается на сетке (меньше клетки, например Ватикан при 0,01°), записывается клетка сетки, содержащая его центроид. Это наименьший невырожденный многоугольник той же сетки; так решил ведущий по ревью 7, вместо прежней «более мелкой сетки», которая нарушала точность и падала на квадрате 0,00004°. Если замер H2 (задача 8.3) покажет превышение, `tolerance_deg` увеличивается в манифесте, а сборка и замер повторяются. Каждая попытка записывается в `progress.md` и `verification.md`.

**Обход колец.** d3-geo считает многоугольник сферическим: внешнее кольцо по часовой стрелке. Кольцо против часовой стрелки (норма RFC 7946 для GeoJSON) d3 понимает как «вся сфера минус многоугольник» — заливка или обводка всего шара. Поэтому сборка ориентирует кольца под d3 (`shapely.geometry.polygon.orient(g, sign=-1.0)`), а инвариант проверяет `d3.geoArea < 2π` у каждого многоугольника ответа.

### 2. Формат артефакта

| Вариант | Оптимальность | Архитектура | Поддержка и масштаб |
|---|---|---|---|
| А. Один упрощённый GeoJSON, при старте сервиса читается в память | Проще всего. Десятки–сотни МБ объектов Python в процессе сервиса знаний — при 1,9 ГБ ОЗУ на весь продукт рискованно. Старт медленнее | Фильтр по году — перебор в Python | Память растёт с датасетом линейно |
| Б. Готовый JSON на каждый интервал постоянного набора (тысячи файлов) | Отдача — чтение файла | Тысячи файлов вне git, каталог сложно проверить целиком | Геометрия образования дублируется в каждом интервале его жизни: диск ×(число интервалов) |
| В. SQLite: таблица `polity_rows` (`id`, `from_year`, `to_year`, `name`, `name_status`, `original`, `wikidata`, `area`, `geometry` — готовый JSON-текст), индекс `(from_year, to_year)`, таблицы `meta` и `report` | `sqlite3` из стандартной библиотеки. Запрос года — индекс, память — только строки года. Один файл, чтение `mode=ro` | Формат и версия — в `meta`; сервис проверяет `format_version` | Масштабируется на любой объём датасета. Новые поля — миграция формата (версия в `meta`) |
| Г. FlatGeobuf или GeoParquet | Компактно, пространственный индекс | Новая зависимость и на пути читателя | Пространственный индекс не нужен: выборка только по году |

**Выбрано: В.** Чем платим: формат артефакта — свой. Его версия в `meta.format_version`, при несовпадении сервис отвечает 503 `polities_unavailable` (`reason = "format"`), а не падает. Геометрия хранится уже сериализованной: ответ собирается из готовых JSON-фрагментов без разбора и повторной сериализации.

### 3. Кэш

| Вариант | Оптимальность | Архитектура | Поддержка и масштаб |
|---|---|---|---|
| А. Без кэша | SQLite отдаёт год за десятки миллисекунд, но ответ в сотни КБ собирается при каждом шаге проигрывания | Просто | Нагрузка растёт с числом читателей |
| Б. LRU по году (предложение владельца) | Повторный год — из памяти. Соседние годы с тем же набором — отдельные записи: при проигрывании кэш забивается копиями одного слоя | Просто | Память ~ число лет × размер слоя |
| В. LRU по интервалу постоянного набора `[valid_from, valid_to]`, ограничение по числу интервалов и по сумме байт; в ответе — `valid_from`/`valid_to`, клиент держит свой кэш по тем же интервалам | Год внутри уже загруженного интервала не даёт запроса вовсе. Сервер хранит один слой на интервал. При проигрывании запрос идёт только на границе интервала | Интервал вычисляет сервер по тем же данным: правило «активна на T» в одном месте (`polities.py`) | Память ограничена явно (`PHILOGRAPH_POLITIES_CACHE`, `PHILOGRAPH_POLITIES_CACHE_BYTES`) |

**Выбрано: В.** Интервал: `valid_from` — наибольшее из `from_year` активных строк и `to_year + 1` строк, кончившихся до T; `valid_to` — наименьшее из `to_year` активных строк и `from_year − 1` строк, начавшихся после T. Это два запроса по индексу. В кэше лежит готовое тело массива образований (байты). Поля `year`, `cached` и событие подставляются на каждый запрос, поэтому один интервал обслуживает все годы внутри него без пересчёта. Чем платим: в клиенте второй кэш (по интервалам, ограничен `POLITY_CACHE` = 16 слоями). Правило «год в интервале» в клиенте не повторяет сервер: клиент только сравнивает T с присланными границами.

### 4. Рендер

| Вариант | Оптимальность | Архитектура | Поддержка и масштаб |
|---|---|---|---|
| А. Обводка многоугольников образований на том же canvas 2D, что суша, вместо сетки `BORDERS`; подписи — SVG-текст той же раскладкой `layout.ts`, вход `{id, name, feature}` из слоя | Ни нового кода проекции, ни новой зависимости. Кадр перетаскивания — те же `geoPath` по canvas | Правило подписей одно: «Политическая карта», правила 1–7. Пересечения с медальонами и `[data-geo-overlay]` проверяет та же функция | Число образований на год — сотни, контуров — тысячи вершин: canvas справляется, как с `countries-110m` |
| Б. SVG `path` на каждое образование | Удобно для наведения и проверок по DOM. Тысячи вершин перепроецируются в DOM на каждом кадре вращения — просадка кадра | Вторая отрисовка карты рядом с canvas суши | Плохо масштабируется по числу вершин |
| В. WebGL | Запрещено требованием «Глобус без WebGL» | — | — |
| Г. Тайлы-растр по годам, подготовленные на сборке | Быстро в клиенте | Растр не вращается на ортографической проекции без перерисовки; тысячи растров вне git | Нет |

**Выбрано: А.** Обводка — токеном `globe-border`, той же толщины, что у границ государств. Береговая линия и суша по-прежнему из Natural Earth: Cliopatria покрывает не всю сушу, а суша без образования на год T должна оставаться сушей. Наблюдаемость: у `[data-geo-land]` атрибуты `data-map-mode` (`historical` | `modern`), `data-polity-from` и `data-polity-to` (интервал `valid_from`–`valid_to` нарисованного слоя: слой актуален, когда `data-polity-from ≤ data-year ≤ data-polity-to`), `data-polities` (число образований слоя), `data-borders` (видимые кольца). Подписи — `[data-geo-polity="<id>"]`, `data-name-status`. Чем платим: обводка образования по морю дублирует береговую линию со сдвигом (R2).

**Подпись одна на QID** (R8, решение ведущего после замера 8.3). В v0.2.2 владения и колонии — отдельные строки `POLITY` с тем же QID, что у метрополии, и получают ту же русскую метку: на 1650 две подписи «Испанская империя».

| Вариант | Оптимальность | Архитектура | Поддержка и масштаб |
|---|---|---|---|
| А. Ничего не делать | Ноль кода. Повтор подписей съедает предел 24 и путает читателя | — | Повторов больше с каждой версией датасета |
| Б. Одна подпись на одинаковый текст `name` | Просто | Склеивает разные образования с совпавшей меткой (омонимы) | Зависит от строки |
| В. Одна подпись на QID: кандидат — первое в порядке ответа (площадь, затем `id`), без QID — каждое | Одна проверка при сборе кандидатов раскладки | Правило по данным (идентичность сущности Wikidata), порядок задаёт сервер одним правилом | Не зависит от имён; границы всех образований остаются |
| Г. Склеивать такие строки на сборке | Меньше данных | Теряются отдельные контуры владений, меняется ответ API | Необратимо в артефакте |

Выбрано: В (решение ведущего). Чем платим: у владения нет своей подписи, даже если метрополия не видна на этой стороне шара; принимается — подпись «метрополии» на другой стороне не ставится, а владение остаётся без подписи. Костыль, которого избегаем: список исключений по имени («(…)»).

**Смена года и проигрывание** (`web/src/map/geo/polities.ts`): кэш слоёв по интервалам. Если T внутри известного интервала — рисуется сразу, без запроса. Иначе — один запрос, следующий ждёт его окончания; ответ для года, который уже не текущий и не покрывает текущий, не рисуется. Пока новый слой не пришёл, остаётся нарисованным прежний: `data-polity-from`/`data-polity-to` показывают интервал нарисованного слоя, и тест видит момент замены.

### 5. Источник русских названий

| Вариант | Оптимальность | Архитектура | Поддержка и масштаб |
|---|---|---|---|
| А. Метка `ru` Wikidata на шаге сборки: `wbgetentities&ids=Q1|…|Q50&props=labels&languages=ru`, пачками по 50 (предел API), кэш `labels.ru.json`, запись в артефакт | ~1600 QID ≈ 32 запроса один раз на сборку. На пути читателя сети нет | Сеть — только общий `wikidata.py` (домен, `check_qid`, повторы). Модель не участвует | Обновление — пересборка. Кэш меток переиспользуется (`--refresh-labels` — принудительно) |
| Б. Поиск метки на лету в эндпоинте | Внешний запрос на пути читателя, задержка, зависимость от доступности Wikidata | Нарушает «без внешних запросов» слоя карты | Нет |
| В. Ручной словарь, как `countries.ru.json` | Полный контроль. 1600+ строк вручную, сверка с каждой версией датасета | Источник правды — человек, а не данные | Не масштабируется |
| Г. Заголовок статьи ru-Википедии (sitelink `ruwiki`) как единственный источник | Покрытие похоже на метки. В заголовках уточнения «(государство)», «(1569—1795)» — их пришлось бы срезать правилом | Ещё один разбор | Хрупче меток как основной источник |
| Е. А, а при отсутствии метки — Г (заголовок `ruwiki` той же записи, без одного завершающего уточнения в скобках) | Тот же запрос `wbgetentities` (`props=labels|sitelinks&sitefilter=ruwiki`), запросов не больше | Источник — та же сущность Wikidata, русский источник, не перевод. Правило снятия уточнения одно и общее, не по строке конкретного образования | Происхождение видно в `name_source`; если запасной путь окажется плохим, он отключается одной веткой |
| Д. Перевод моделью | Запрещено спецификацией владельца | — | — |

**Выбрано: Е** (пересмотрено в круге 1 до первого замера H3, по указанию ведущего: честные русские названия из тех же данных). Основной источник — метка `ru` (А), запасной — заголовок `ruwiki` (Г). Происхождение — `name_source` (`label` | `sitelink` | `original`), счёт — `ru_labels` и `ru_sitelinks` в событии сборки. Снимается только одно завершающее « (…)»: «Речь Посполитая (1569—1795)» → «Речь Посполитая». Заголовок без скобок берётся как есть. Чем платим за Г: заголовок иногда шире сущности (статья о стране в целом, а не о периоде); это видно по `name_source` и принимается. Берётся только язык `ru`, без запасных языков (`languagefallback` не передаётся; метка `mul` не берётся). Метка проверяется кодом: строка, после `strip` от 1 до 200 символов, без управляющих символов. Иначе метки нет. Запрошенный QID, ушедший перенаправлением на другую запись, ищется по `entities[*].redirects.from`, а при его отсутствии — по ключу ответа. Запись `missing` — метки нет. QID записи проверяется `check_qid` (`^Q\d+$`): пустое или испорченное поле `Wikidata` даёт `wikidata = null` и оригинальное название. Чем платим: зависимость сборки от сети. Тесты идут с внедрённым `Fetch`-словарём, сборку без сети даёт `--offline` (только кэш меток).

## Устройство

### Сборка

1. `fetch`: адрес из манифеста (`download.url`, схема `https` и хост `raw.githubusercontent.com` проверяются кодом, перенаправления не выполняются: `github.com/…/raw/…` сразу заменён в манифесте адресом, куда он перенаправляет), запись во временный файл, SHA-256, сверка с `download.sha256`. При расхождении файл удаляется, код выхода ≠ 0. Если в манифесте суммы ещё нет, `fetch --record` печатает её для внесения в манифест; это один раз, задача 8.1.
2. `build`: `zipfile.ZipFile(...).open("cliopatria.geojson")` → `ijson.items(f, "features.item")` — в памяти одна запись. Для каждой записи:
   - `Type != "POLITY"` — пропуск (`skipped_relation`);
   - нет `Name`, `FromYear`/`ToYear` не целые или `FromYear > ToYear`, геометрия не многоугольник — пропуск (`skipped_invalid`);
   - геометрия → `shape` → `make_valid` → `simplify` → отбор колец → `orient` → округление → JSON-текст;
   - `id` = первые 12 шестнадцатеричных знаков SHA-1 от `Name` (одно образование — один id во всех строках и годах).
   
   Записи пишутся в SQLite пачками по 200 в одной транзакции. QID собираются в множество, затем — метки (кэш + сеть пачками по 50), затем `UPDATE` названий. В конце — `meta` (`format_version`, `dataset_version`, `sha256`, `source` JSON из манифеста, параметры упрощения) и отчёт сборки (`report`): поля события `knowledge.polities.built`. Артефакт пишется во временный файл и переименовывается атомарно: сервис никогда не видит недописанный файл.
3. `measure`: по артефакту для каждого контрольного года — число образований, с русским названием, байты тела ответа и байты `gzip -9`. Тело собирается **той же функцией `PolityLayer`, что отдаёт эндпоинт**, а не отдельной копией. Результат — JSON в stdout. Параметр `--all-intervals` проходит все интервалы постоянного набора и даёт максимум размера (для H2 по всем годам, а не только по контрольным). Ещё два счётчика: `inactive` — образования ответа вне `from ≤ T ≤ to` (H1 на реальных данных, ожидается 0) и `full_sphere` — многоугольники со сферической площадью ≥ 2π (проверка обхода колец на образованиях через антимеридиан, ожидается 0). Площадь — своя функция сферического избытка по формуле d3 `geoArea`, без клиента.

### Эндпоинт

`GET /v1/map/polities?year=T`:

```json
{
  "year": 1650, "valid_from": 1648, "valid_to": 1653, "cached": false,
  "polities": [
    {"id": "3f2a…", "name": "Священная Римская империя", "name_status": "ru",
     "original": "Holy Roman Empire", "wikidata": "Q12548", "from": 1648, "to": 1700,
     "geometry": {"type": "MultiPolygon", "coordinates": [[[[5.87, 51.05], …]]]}}
  ],
  "source": {"title": "Cliopatria", "publisher": "Seshat Global History Databank",
             "authors": ["Ed Chalstrey", "James Bennett"], "version": "v0.2.2",
             "license": "CC BY 4.0", "license_url": "https://creativecommons.org/licenses/by/4.0/",
             "url": "https://doi.org/10.5281/zenodo.24518977"}
}
```

Порядок образований — по убыванию `area`, при равенстве по `id`. Если у одного `id` на T активны две строки (пересечение интервалов в датасете), их многоугольники сливаются в один `MultiPolygon`, `from` = наибольший `from_year`, `to` = наименьший `to_year` активных строк; название и QID — строки с наибольшим `from_year`. Это отмечается полем отчёта `overlapping_rows`.

### Клиент

- При открытии глобуса и смене года — `polities.ts` → слой; `GlobeView` получает `{mode, year, polities, source}`.
- `mode = "historical"`: canvas суши рисует сушу, береговую линию (Natural Earth) и обводку образований; подписи — вход раскладки из образований (`name`, `name_status`). Подпись с `name_status = "original"` — курсивом, с `<title>` «<название> — без русского названия» и `data-name-status="original"`. В подписи источника — «курсив — без русского названия».
- `mode = "modern"` (503 или ошибка): как сейчас, `BORDERS` и `COUNTRY_INPUT`.
- Пустой слой (`polities = []`): границ нет, подписей образований нет, современная карта **не** подставляется — это был бы тот же анахронизм.

## Решения без владельца

1. **Версия датасета — v0.2.2** (Zenodo 24518977, 2026-11-25), а не v0.0.1 из задания (49 МБ). Это последняя версия, архив `cliopatria.geojson.zip` 47,2 МБ — того же порядка. Загрузка — с тега GitHub: архив Zenodo 300 МБ из-за `original_map_images`. В манифесте — обе ссылки и DOI для цитирования.
2. **RELATION не берём.** Их многоугольники накладываются на образования (вассалитет, протекторат), подписи и обводки удвоились бы. Число пропущенных — в отчёте сборки.
3. **Поле «статус»** из задания владельца понято как статус названия: `name_status` ∈ {`ru`, `original`}. Статуса проверки человеком у данных Cliopatria нет: источник один. Пометка «одна из версий границ» относится ко всей карте, а не к образованию.
4. **H3 считается по числу образований** на контрольных годах (определение — в дельте, «Пределы исторического слоя»): Σ образований с `name_status = "ru"` / Σ образований по годам из `control_years` манифеста. Взвешивание по площади отвергнуто: крупные империи почти все с метками, такая доля завышала бы покрытие для читателя. Если порог 90% не достигнут, это фиксируется как результат в `verification.md`, а порог и набор лет не меняются.
5. **Контрольные годы:** −500, −300, 0, 400, 800, 1000, 1300, 1500, 1650, 1700, 1800, 1900, 2000 — эпохи пилотного раздела «теория познания» и годы сценариев владельца. Набор записан в манифест до первого замера.
6. **H2 — с запасом:** проверяется не только «типичный кадр», а максимум по контрольным годам; дополнительно `measure --all-intervals` даёт максимум по всем годам. Порог — 500 КБ = 512 000 байт после `gzip -9` тела ответа.
7. **Запасной режим.** Без артефакта (503) глобус показывает современную карту без новых пометок, как до изменения. Поэтому существующие тесты `tests/web` и e2e, которые идут без артефакта, проверяют прежнее поведение без правок. При ошибке загрузки (не 503) — тоже современная карта, но с пометкой «Исторические границы не загрузились — показаны современные».
8. **Страна места остаётся современной.** «Образование места на год T» — отдельное изменение: нужно правило принадлежности точки к образованию и подпись в блоке места. Подпись источника в историческом режиме прямо говорит, что страны мест — современные.
9. **`compose.yaml` не меняется** (файл развёртывания Lead'а). Путь артефакта настраивается `PHILOGRAPH_POLITIES_DB` (по умолчанию `data/cliopatria/polities.sqlite` от рабочего каталога). Подключение тома на сервере — задача 9.2, с согласия Lead'а.
10. **Предел года** запроса: целое в −9999…9999, иначе 400 `bad_year`. Годы вне датасета (раньше −3400, позже 2024) — 200 с пустым списком: это «пустой год» владельца.
11. **Зависимости сборки** (`shapely`, `ijson`) — в extra `geo-build`, он подключён в `dev`. Образ сервиса их не тянет: `polities.py` их не импортирует. Это проверяет нормативный тест.

## Критерии владельца → дельта

| # | Критерий | Где в дельте | Как проверяется |
|---|---|---|---|
| H1 | `FromYear ≤ T ≤ ToYear` у каждого образования, 100% | «Слой политических образований на год»: инвариант активности и полноты | нормативный тест на фикстуре (перебор всех лет фикстуры) + поле `inactive` в `measure` на реальном артефакте (ожидается 0) |

| H3 | ≥ 90% русских, остальные с пометкой | «Пределы исторического слоя», «Русские названия образований» | правило пометки — тест; доля — замер 8.3 |
| H4 | набор меняется при смене года | «Исторические границы на глобусе», сценарий «Смена года» | браузерный тест на фикстуре |
| H5 | 0 наложений подписей на медальоны и UI на 1024×576 | «Исторические границы на глобусе», инвариант подписей | браузерный тест на фикстуре, 3 размера окна |

| H9 | данных Cliopatria нет в git | «Сборка исторических границ», инвариант «данные вне git» | нормативный тест по `git ls-files` и манифесту |

## Риски

- **R1. H3 может не достигаться.** У части образований Cliopatria нет Wikidata-id или нет метки `ru` (малые древние политии). Порог не подгоняется, результат записывается. Возможное следствие — отдельное изменение (подбор QID по `Wikipedia`-полю).
- **R2. Обводка по морю.** Контуры Cliopatria по побережью не совпадают с береговой линией Natural Earth, у берега видна двойная линия. Принимаем в этом изменении. Улучшение — обрезка обводки по суше Natural Earth на сборке — отдельной задачей, если владелец сочтёт это заметным.
- **R3. Память сборки.** Потоковое чтение держит одну запись. Пик — самая крупная запись (геометрия Российской империи или Британской) и `shapely`. Ожидаем < 600 МБ; замер `/usr/bin/time -v` — задача 8.2. Если превысит, сборку запускать при остановленном стенде.
- **R4. Wikidata недоступна или ограничивает частоту.** Повторы по `Retry-After` уже есть в `wikidata.py`. Сборка с частью меток не падает: без метки — оригинальное название. Число запросов и меток — в событии.
- **R5. Щели на стыках** от независимого упрощения (см. выбор 1).
- **R6. Дисковое место:** zip 47 МБ + артефакт (ожидаем 30–100 МБ) + кэш меток. Свободно 13 ГБ.
- **R8. Повторяющиеся подписи** (замер 8.3; решено — «Подпись одна на QID» в выборе 4): в v0.2.2 владения — отдельные строки `POLITY` с именем в скобках и тем же QID, что у метрополии, поэтому на один год приходятся две строки с одной русской подписью («Испанская империя»). Решение — в 4.2, правилом раскладки по данным (например, одна подпись на одинаковый `name` — у большей площади), а не особым случаем по имени. Если правило меняет наблюдаемое поведение, оно вносится в дельту до кода.
- **R7. Тесты без артефакта не видят исторического режима.** Поэтому `tests/web` получают фикстурный артефакт, собранный в сессии теста из фикстурного GeoJSON (секунды), — задача тестировщика 6.1.
