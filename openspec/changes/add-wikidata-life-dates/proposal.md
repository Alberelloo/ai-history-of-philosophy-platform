# Proposal

## Why

П3 задания владельца: на таймлайне пусто. Датированы 10 сущностей из 1889: 4 персоны (Кант, Юм, Локк, Лейбниц), 1 труд и 5 эпох.

У Wikidata даты есть, но:
- `geo_enrich` даты жизни (P569/P570) не берёт, только места;
- `Filling.import_wikidata` берёт годы срезом строки `claims["P569"][0][1:5]`. Знак эры теряется: Платон `-0427-…` записался бы как 427 год н. э. Кроме того, даты жизни пишутся, только если есть обе;
- у большинства персон стенда нет внешнего QID, поэтому обогащать нечего.

Приёмка: А5 (датированных персон ≥ 20) и А6 (философов на таймлайне ≥ 10).

## What Changes

- **Новая команда оператора** `python -m philograph.knowledge.life_dates`, по образцу `geo_enrich` и `epoch_dates`:
  - `suggest`. Подбирает кандидатов QID для персон и произведений без QID поиском Wikidata по названиям и вариантам. Оставляет только записи с `P31 = Q5` (человек) для персон и с P577 для произведений. Пишет их в манифест `sources/person_qids.yaml`. QID подтверждает человек. Есть флаг `--auto-exact`: кандидат отмечается `decision: auto`, если подходит ровно один, его подпись ru/en совпадает с названием сущности и даты не противоречат. Отметку видно в манифесте, и её можно снять.
  - `apply [--dry-run] [--linked] [--from-file F]`. Записывает подтверждённые QID (`add_external`), затем для персон и произведений с QID:
    - P569 + P570 → `lifespan`;
    - P577 → `dating`;
    - P106 → `person_role` по существующей таблице ролей.

    Импортированное получает атрибуцию `wikidata:<QID>` со ссылкой на запись, статус «по источникам», происхождение «импорт» с `run_id`. Существующая дата не перезаписывается: совпадение — `unchanged`, расхождение — `conflict` в отчёте.
  - `rollback <run_id>`. Убирает утверждения запуска (кроме проверенных человеком) и QID, которые записал запуск.
- **Время Wikidata** разбирается только общим `knowledge/wikidata.py` (`claim_date`, `wikidata_time`, `format_original`). Годы до н. э. — в астрономическом счёте.
- **Таблица ролей** `WIKIDATA_ROLES` переносится из `filling.py` в `wikidata.py`. `filling.py` её импортирует (одна строка, файл Lead'а).
- **Ошибка знака эры.** `Filling.import_wikidata` переходит на общий разбор времени. Это MODIFIED-требование «Импорт из Wikidata» `ontology-extraction`: даты до н. э. и персона с одной датой.
- **Учёт запуска.** Новая таблица `run_actions` (миграция схемы `knowledge:8`): что запуск записал вне утверждений (QID). Её же использует `migrate-ontology-quality`.
- **Журнал:**
  - `knowledge.life_dates.suggested`;
  - `knowledge.life_dates.run`;
  - `knowledge.life_dates.skipped`;
  - `knowledge.life_dates.rolled_back`.

## Out of scope

- Русские названия из Wikidata — шаг миграции `migrate-ontology-quality`. Он переиспользует записи и кэш этой команды.
- Места и координаты — `geo_enrich`, без изменений.
- Сеть в тестах: только фикстуры (`--from-file`, словарь `fetch`).
- Подтверждение QID человеком на стенде — за Lead'ом (5.2).

## Вопросы владельцу (решены, см. progress.md)

1. **«Подтверждённый QID»** — это QID, уже записанный у сущности, или QID в манифесте с решением `accepted` (человек) или `auto` (правило `--auto-exact`, только по флагу). Без флага автоматика ничего не подтверждает.
2. **Персона только с годом рождения** (или только смерти) даты жизни не получает. Причина пропуска — `partial`: «годы жизни» — интервал, полуоткрытого в модели нет.
3. **Платон.** Wikidata `-0427` даёт астрономический −426. Владелец записал −427/−347 в историческом счёте. В сценарии: `span = (−426, −346)`, исходная запись «427 до н. э. – 347 до н. э.».
