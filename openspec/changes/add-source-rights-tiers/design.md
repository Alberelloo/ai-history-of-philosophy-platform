# Design: правовой статус источников (rights tiers)

## 1. Текущее состояние — где зашито ограничение «70 лет / public domain»

Правило «только общественное достояние / открытая лицензия» держится на нескольких точках; все они меняются в этом изменении.

| Файл (строки) | Что ограничивает |
|---|---|
| `src/philograph/library/registry.py:26` | `COPYRIGHT_YEARS = 70` — порог срока охраны в коде. |
| `src/philograph/library/registry.py:23` | `Basis = Literal["public_domain", "open_license", "rightsholder_permission"]` — нет значений `in_copyright`/`unknown`. |
| `src/philograph/library/registry.py:321-364` | `_validate_license` для `public_domain` требует годы смерти авторов/переводчика и возвращает «права ещё действуют», если `год_смерти + 70 >= текущий_год` (строки 326-341); `rightsholder_permission` требует `document_url`. |
| `src/philograph/library/registry.py:366-424, 791-808` | `register` пишет причину блокировки в JSON лицензии (`blocked`); `publish` отказывает при `not display` или `blocked`. |
| `src/philograph/library/catalog/model.py:19, 134-153, 255-283` | Импорт `COPYRIGHT_YEARS`; `license_of` дотягивает годы смерти; `validate` для одобренной записи `public_domain` падает, если нет годов смерти или `год_смерти + 70 >= год`. |
| `src/philograph/library/catalog/adapters.py:98-103, 620, 680-709` | `death_year` из Wikidata P570; подсказка лицензии с сайта; `LICENSE_HINTS` распознаёт только CC; `suggest_license` предлагает public domain только при `d + 70 < year`, иначе `None` — тира «под охраной» не существует. |
| `sources/licenses.yaml` | 9 видов, у всех `display: true`; нет видов для `in_copyright`/`unknown`; `public-domain-ru` — регионы `[RU]` + `external_processing: false`. |
| `sources/catalog.schema.json:51-69` | `license.basis` — перечисление из трёх значений; обязательны `kind`, `basis`, `evidence`; поля «тир» нет. |
| `openspec/specs/source-registry/spec.md` | «Лицензия с основанием и разрешениями» (основание — одно из трёх), «Права на перевод» (+70), «Разрешения управляют обработкой и показом». |
| `openspec/specs/source-catalog/spec.md` | Одобрение записи и «Правило публикации обновлений»; понятия тира нет. |
| `src/philograph/library/catalog/service.py:122-135, 237-276` | `ensure_license_kinds` заносит виды из `licenses.yaml`; `_sync_entry` регистрирует одобренные записи и возвращает `blocked`, если лицензия не позволяет. |

Итог: ограничение — это **не отдельная настройка**, а жёсткая константа плюс отсутствие в модели статусов «под охраной» и «неизвестно». Чтобы собирать in-copyright, нужно (а) ввести тир как поле, (б) перестать блокировать обработку по 70 годам, (в) гейтить только показ читателям.

## 2. Целевой дизайн

### 2.1 Модель правового статуса

Новое обязательное поле источника `rights_tier` (правовой статус) — макро-класс, от которого зависят разрешения по умолчанию. Четыре значения:

- `public_domain` — общественное достояние по юрисдикционным критериям (сроки истекли) либо явная передача CC0.
- `open_license` — открытая лицензия: CC BY / BY-SA / BY-NC / BY-NC-SA / OGL / GFDL и разрешение правообладателя.
- `in_copyright` — свободно доступно в сети, но формально ещё под охраной (срок не истёк, открытой лицензии нет).
- `unknown` — статус не удалось определить (нет годов смерти, сайт молчит).

Соотношение с существующими полями:

- `license.kind` (вид из `sources/licenses.yaml`) остаётся — это конкретный вид лицензии (CC BY 4.0 и т.п.). Каждый вид получает поле `tier` (какой тир он означает по умолчанию).
- `license.basis` (основание) расширяется значениями `in_copyright`, `unknown`; `rights_tier` — агрегирующее гейтящее поле, `basis`/`evidence` — детали доказательства.
- Итоговый `rights_tier` источника по умолчанию берётся из вида лицензии, может быть перемаркирован оператором (только с доказательством; расширение в более «открытую» сторону требует evidence, сужение — всегда).

### 2.2 Где поле живёт в БД

- `library.sources.rights_tier` — отдельный столбец `VARCHAR(30) NOT NULL` (как прецедент с `regions`: отдельный столбец, чтобы старый код при откате не падал на неизвестном ключе JSON-лицензии). Миграция `library` № 6.
- `library.license_kinds.tier` — тир по умолчанию у вида лицензии (заносится из `sources/licenses.yaml`).
- Новая таблица `library.rights_log` (id, source_id, time, actor, old_tier, new_tier, evidence, note) — журнал перемаркировок. Дублирует сведения ActionLog для операторских действий, но хранит именно смену тира с доказательством.

### 2.3 Тир → разрешения (данные, не код)

Соответствие «тир → разрешения по умолчанию» живёт в `sources/rights-tiers.yaml` (см. п. 3), разрешения конкретного источника можно только сужать относительно тира (как сейчас сужаются относительно вида). Базовые значения:

| rights_tier | display (читателям) | external_processing (эмбеддинги/LLM) | quoting (цитаты) |
|---|---|---|---|
| `public_domain` | true | true | true |
| `open_license` | true | true | true |
| `in_copyright` | **false** | true | **false** |
| `unknown` | **false** | **false** | **false** |

`in_copyright`: внешняя обработка разрешена, чтобы строить онтологию как производные данные (сущности, связи, утверждения); полный текст читателям не отдаётся, цитаты не приводятся (кроме коротких ссылок по усмотрению оператора — отдельный флаг). `unknown`: консервативно — ни показа, ни внешней обработки до классификации.

### 2.4 Конвейер загрузки: что качать и как классифицировать

- Адаптер (`catalog/adapters.py`) при `harvest` собирает метаданные и, дополнительно, **классифицирует тир** (`classify_rights(harvest, year, jurisdiction)`): по подсказке лицензии сайта, годам смерти из Wikidata, году издания и юрисдикции. Результат — черновик `rights_tier` (+ `rights_evidence`).
- Запись каталога получает `license.rights_tier` и `license.rights_evidence`/`rights_jurisdiction`. Оператор в `review` подтверждает тир (аналогично сегодняшнему подтверждению лицензии).
- Синхронизация (`catalog/service.py`) регистрирует и обрабатывает **все одобренные** записи независимо от тира: загрузка файлов, разбор, проверки качества, версия — как сегодня. Блокировка «70 лет» на этапе обработки снимается.
- Разница появляется на публикации:
  - `display: true` (`public_domain`, `open_license`) → обычная читательская публикация (`source.published`), как сейчас.
  - `display: false` (`in_copyright`, `unknown`) → читателям версия не публикуется; вместо этого уходит новое событие `source.processed` (с `external_processing: true` для `in_copyright`), которое потребляет только сервис знаний для извлечения онтологии.
- `unknown` дополнительно не отправляется внешним сервисам: событие `source.processed` для него не эмитится (или эмитится с `external_processing: false`), пока оператор не классифицирует.

### 2.5 Гейтинг читателям (в перспективе)

- **library** (`reading.py`, `app.py`): список источников, чтение глав и `resolve_paragraph` уже фильтруют по регионам; добавляется фильтр по `display` (тир). Источники `in_copyright`/`unknown` отсутствуют в библиотеке читателя; ссылка на их абзац отвечает «источник недоступен» (как при закрытом регионе).
- **search** (`searching.py`, `indexing.py`): полнотекстовый индекс читателя строится только по опубликованным (`display: true`) источникам; внутренние интерфейсы поиска по-прежнему видят всё (прецедент — внутренний `/internal/access` для регионов).
- **assistant** (`service.py`, `grounding.py`): текст `in_copyright`/`unknown` не уходит модели и не цитируется; ассистент опирается на производные факты (утверждения онтологии) и ссылки только на легальные абзацы. Прецедент — уже реализованный режим `external_processing: false` (пометка «найдено в источниках, не пересказывается»).
- **gateway** (`app.py`): лимиты/регион без изменений; по желанию — защитная проверка «не отдавать наружу тела источников с `display: false`» на уровне шлюза (defense-in-depth).
- **knowledge** (`knowledge/…`): потребляет и `source.published`, и `source.processed` (все источники с `external_processing: true`), извлекая сущности/связи/утверждения; полные тексты наружу не отдаёт — только производные данные, а `where_to_read`/карточки/граф ссылаются на легальные источники.

### 2.6 Конфиг vs код

- **Данные** (`sources/rights-tiers.yaml`): юрисдикционные пороги (70 лет, США pre-1930 / 95 / 120, РФ ст. 1281–1282), список распознаваемых открытых лицензий и соответствие тира разрешениям. Меняется без пересборки кода, ревьюится вместе с каталогом.
- **Код** (`library/catalog/rights.py` или в `adapters.py`): функция классификации — порядок проверок и вывода тира; читает пороги из YAML. Константа `COPYRIGHT_YEARS` удаляется.

Граница статуса явная и аудируемая: итоговый тир всегда в БД (`sources.rights_tier`) + в журнале `rights_log` с доказательством; критерии — в файле данных с версией.

## 3. Критерии классификации

### 3.1 Общественное достояние

- **Срок автора (ЕС/РФ/Берн)**: все авторы умерли ≥ 70 лет назад → `public_domain` (глобально, кроме нюансов США). Если автор один и год смерти неизвестен — см. `unknown`.
- **Перевод**: произведение может быть в ОД, но перевод охраняется отдельно — переводчик умер ≥ 70 лет назад. Научное издание/комментарий — аналогично по редактору/составителю.
- **США**: издание до 1930 г. (1929 и ранее) — ОД в США независимо от даты смерти; порог «95 лет с публикации» сдвигается ежегодно. Издание 1930–1977 без уведомления об охране — ОД; с уведомлением — 95 лет с публикации. 1978+ — автор +70 (или 95/120 для work-for-hire и анонимных).
- **РФ (ст. 1281–1282 ГК РФ)**: автор +70; работавшие в годы ВОВ — +74; посмертно реабилитированные — +70 с реабилитации; анонимно/под псевдонимом — публикация +70. До 1917 г. — как правило ОД.
- **CC0** — явная передача в общественное достояние → `public_domain`.

### 3.2 Открытая лицензия

- `CC BY`, `CC BY-SA`, `CC BY-NC`, `CC BY-NC-SA`, `OGL`, `GFDL`, разрешение правообладателя → `open_license`.
- Копилефт (`BY-SA`, `GFDL`) и `ND` помечаются в evidence: производные данные (пересказ/разметка) могут требовать той же лицензии или запрета производных — решение владельца для некоммерческого использования.

### 3.3 In-copyright

- Свободно доступно в сети, но срок охраны не истёк и открытой лицензии нет → `in_copyright`. Сбор полного текста — **решение и правовой риск владельца** (см. п. 4). Обрабатывается как производные данные; читателям не показывается.

### 3.4 Unknown и ручная перемаркировка

- Нет данных (годов смерти, лицензии, года издания) → `unknown`; по умолчанию консервативно: `display: false`, `external_processing: false`.
- Оператор перемаркирует тир с `evidence` (ссылка на документ / годы смерти / примечание) — запись в `rights_log`. Расширение в более открытый тир требует доказательства; сужение — без него.

## 4. Явные договорённости (фиксируются)

1. **Раздача читателям** ограничивается только легальными тирами (`public_domain`, `open_license`); `in_copyright`/`unknown` читателям не показываются.
2. **`rights_tier` — обязательное поле** источника; источник без статуса не регистрируется и не публикуется.
3. **`unknown` по умолчанию консервативный**: ни показа, ни внешней обработки до классификации оператором.
4. **Сбор полных текстов `in_copyright`** — решение и правовой риск владельца; система хранит их серверно только для производной онтологии и не раздаёт полные тексты.
5. Критерии — данные (`sources/rights-tiers.yaml`), а не код; граница статуса аудируема (`rights_log`).
