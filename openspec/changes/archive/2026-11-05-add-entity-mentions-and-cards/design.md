# Design

## Context

Мотивация в [proposal.md](proposal.md), устройство упоминаний и карточек — разделы 10.3 и 11.1 [ontology.md](../../../../docs/product/ontology.md), требования в `entity-mentions` и `entity-cards`. Модель онтологии — [add-ontology-core](../2026-11-05-add-ontology-core/design.md), наполнение — [add-ontology-filling](../2026-11-05-add-ontology-filling/design.md).

## Decisions

### 1. Упоминания хранит сервис знаний, текст остаётся в библиотеке

Таблица `knowledge.mentions` (миграция 3) хранит абзац, сноску или заголовок, точные границы фрагмента, сущность и способ нахождения. Библиотека ничего не знает об онтологии. Сервис знаний читает текст версии через внутренний адрес `internal/versions/{id}/paragraphs`, который теперь отдаёт ещё заголовки, сноски и названия глав. Клиент получает главу из библиотеки и упоминания отдельным запросом `/api/knowledge/v1/mentions?targets=…`. Без сервиса знаний глава показывается без выделений.

### 2. Сопоставление по ключам слова, а не по строке

Название и текст разбиваются на слова. У каждого слова есть ключи: лемма (pymorphy3 для русского, Snowball для латиницы), а у слова с заглавной буквы ещё и основа словоформы (русский Snowball). Указатель названий хранит все сочетания ключей, а поиск берёт самое длинное совпадение. Так «трансцендентального идеализма» даёт одно упоминание, а «Юма», «Гоббсом» и «Локка» находятся, хотя словарь их не знает или принимает «Юма» за топоним. Нарицательные слова сравниваются только по лемме, поэтому «верю» не совпадёт с «вера».

### 3. Общеупотребительные слова — только как термин

У сущности есть признак `common_word`. Такое упоминание ставится, если в абзаце есть другие термины или слово взято в кавычки. В остальных случаях оно пропускается: ложная ссылка хуже пропущенной.

### 4. Неоднозначность — по контексту главы, затем модель, иначе пропуск

Сначала по всей версии собираются однозначные упоминания по главам. Кандидат неоднозначного названия выбирается, если он связан утверждениями с сущностями главы или жил одновременно с людьми главы. Современниками считаются, только если периоды жизни пересекаются при любом уточнении размытых дат. Если кандидатов не остаётся ровно один, решает внешний `resolver` (модель офлайн). Если и он не решил, упоминание не ставится, а в журнал пишется `knowledge.mentions.unresolved`.

### 5. Пересчёт точечно

Новая версия источника пересчитывает добавленные и изменённые абзацы, а также все заголовки и сноски, потому что их мало. Новая сущность из наполнения пересчитывается только по своим названиям во всех опубликованных версиях. Слияние переносит упоминания вместе с названиями и утверждениями, а отмена слияния возвращает их.

### 6. Карточка собирается из утверждений, разделы — данные

Разделы по типам сущностей заданы таблицей `SECTIONS`: код, заголовок, типы связей с подтипами, направление. Пустой раздел не попадает в ответ. Каждая строка несёт атрибуцию, статус, спорность с несогласными, подтверждающие абзацы и пометку сгенерированного. Отклонённые утверждения не показываются. Отвергнутые (`rank = deprecated`) с атрибуцией «распространённое мнение» попадают в раздел «Часто считают, но…». Показы строк уходят в приоритет очереди проверки.

### 7. Описание — отдельный поток

Карточка отдаётся сразу из готовых данных, а если описания нет, в ней стоит `description_pending`. Клиент запрашивает `POST /entities/{id}/description` и получает NDJSON-поток из сервиса LLM (шаблон `card.description`, бюджет `site`). Готовое описание сохраняется утверждением со статусом «сгенерировано», и второй раз модель не вызывается. Если генерация выключена, модель недоступна или исчерпан лимит, поток завершается событием `unavailable`, и карточка остаётся без описания.

### 8. Названия глав в указателе хранятся вместе с упоминанием

У упоминания записаны названия источника и главы, поэтому «Где читать» показывает «Глава 3. Ответ Канта — Теория познания…, упоминаний: 3» без запросов к библиотеке.

## Risks / Trade-offs

- [Основа словоформы у имён с заглавной может дать ложное совпадение в начале предложения] → основа сравнивается только с названиями сущностей. Метрика точности на размеченных абзацах покажет, если это станет заметно.
- [Пересчёт всей библиотеки при каждой новой сущности дорог] → пересчёт идёт только по названиям этой сущности. Если библиотека вырастет, понадобится инвертированный указатель по ключам.
- [Названия глав в упоминаниях устаревают при правке главы] → новая версия пересчитывает заголовки, а вместе с ними обновляются и названия.
