# Design

## Context

Мотивация в [proposal.md](proposal.md), модель — [ontology.md](../../../../docs/product/ontology.md), требования в `ontology-registry`, `ontology-entities`, `ontology-statements`.

## Decisions

### 1. Реестр как данные в той же базе

Типы сущностей, связей, уточнители и рецепты лежат в таблицах схемы `knowledge`. Начальный набор — `registry_data.py` по разделам 5–7 и 11.2 `ontology.md`, он загружается один раз. Проверки, запросы и схема вывода для LLM читают реестр, поэтому новый тип не требует кода. Изменения пишутся в `registry_versions`. Предложения модели ждут человека в `type_proposals`.

### 2. Утверждение с ключом для объединения повторов

Ключ — отпечаток (субъект, тип, объект или значение, уточнители). У симметричных связей концы упорядочены, поэтому они хранятся один раз. Повтор добавляет атрибуции и подтверждения к существующей записи. Повтор отклонённого остаётся отклонённым: модель не может «протолкнуть» его снова.

### 3. Цитата проверяется по тексту библиотеки

Подтверждение записывается, только если цитата есть в абзаце. Текст сервис знаний получает через внутренний интерфейс библиотеки (`/api/v1/internal/paragraphs/{id}`), а не из её таблиц.

### 4. Выведенное считается при запросе

Влияние из идейных событий («участник испытал влияние исходного материала») не хранится, а вычисляется в `about()`. Его статус — слабейший из посылок. Обратные связи — те же записи, прочитанные с другой стороны.

### 5. Обход в ширину по рецепту

Обход идёт по семействам рецепта, с направлением, глубиной и пределом узлов. Узлы с уже пройденными идентификаторами не повторяются, поэтому циклы не страшны. Порядок «по времени» — по самой ранней границе основной даты. На наших объёмах (тысячи утверждений) обход в коде достаточно быстр. Рекурсивные запросы SQL оставлены на случай роста.

### 6. Подписка на события библиотеки

Сервис знаний разбирает задачи `knowledge:*` из очереди сам:
- удалённый абзац — подтверждение утрачено;
- изменённый — цитата перепроверяется;
- перенаправленный — подтверждение переносится;
- снятый источник — его атрибуции скрываются.

Утверждение без живых подтверждений возвращается из «по источникам» в «сгенерировано» с предупреждением.

## Risks / Trade-offs

- [Обход в коде при росте онтологии] → интерфейс `traverse` не зависит от способа; переход на рекурсивный SQL или графовую копию (решение О1, раздел 16 `ontology.md`).
- [Эвристика дублей по последнему слову названия] → только кандидаты; решение за человеком на странице проверки (`add-ontology-filling`).
