# Spec Delta

## Purpose

Находит абзацы библиотеки, относящиеся к запросу, по смыслу и по словам, в пределах заданных источников и видимости. Возвращает абзацы с идентификаторами, на которые потом ссылаются ответы ассистента.

## ADDED Requirements

### Requirement: Гибридный поиск

Поиск SHALL искать абзацы и по смыслу, и по словам, а результаты объединять в один список по общему правилу ранжирования. Каждый результат SHALL содержать идентификатор абзаца, источник, главу, текст, оценку и то, каким способом он найден.

#### Scenario: Вопрос своими словами

- **WHEN** запрос «почему из прошлого нельзя вывести будущее»
- **THEN** находятся абзацы о проблеме индукции, даже если этих слов в них нет

#### Scenario: Точный термин

- **WHEN** запрос «tabula rasa»
- **THEN** абзацы с этим выражением есть среди первых результатов

### Requirement: Нормализация слов

Поиск по словам SHALL учитывать морфологию: запрос «причинность» находит «причинности» и «причинностью». Он SHALL не различать регистр, «е» и «ё», дореформенное и современное написание.

#### Scenario: Склонение

- **WHEN** запрос «Канту»
- **THEN** находятся абзацы со словами «Кант», «Канта», «Кантом»

#### Scenario: Дореформенный текст

- **WHEN** запрос «познание»
- **THEN** находится абзац со словом «познанія»

### Requirement: Запросы на других языках

Поиск по смыслу SHALL находить абзацы на другом языке, чем запрос. Поиск по словам SHALL работать с языком абзаца.

#### Scenario: Русский запрос, английский абзац

- **WHEN** запрос на русском о «чистой доске», а в библиотеке есть английский абзац о «blank slate»
- **THEN** этот абзац есть в результатах

### Requirement: Фильтры

Поиск SHALL принимать фильтры: список источников, языки, виды разделов, исключаемые абзацы. Без фильтра по источникам поиск идёт по всей видимой библиотеке.

#### Scenario: Только выбранный учебник

- **WHEN** поиск запрошен с фильтром по одному учебнику
- **THEN** все результаты из этого учебника

### Requirement: Видимость и публикация

Поиск MUST NOT возвращать абзацы неопубликованных версий, снятых источников и источников вне области видимости запрашивающего.

#### Scenario: Снятый источник

- **GIVEN** источник снят с публикации
- **WHEN** запрос совпадает с его абзацем
- **THEN** этого абзаца нет в результатах

### Requirement: Соседний контекст

Поиск SHALL по запросу возвращать вместе с абзацем соседние абзацы той же главы и заголовок раздела, чтобы ответ не опирался на вырванную фразу.

#### Scenario: Контекст

- **WHEN** поиск запрошен с одним соседним абзацем
- **THEN** у результата есть предыдущий и следующий абзацы главы и заголовок раздела

### Requirement: Разнообразие результатов

Поиск SHALL ограничивать число результатов из одной главы, чтобы один длинный раздел не вытеснил остальные источники. Ограничение задаётся параметром запроса.

#### Scenario: Ограничение по главе

- **GIVEN** ограничение три результата на главу
- **WHEN** десять подходящих абзацев из одной главы
- **THEN** в результатах из неё не больше трёх

### Requirement: Расширение запроса

Поиск SHALL принимать вместе с запросом дополнительные термины и приоритетные абзацы, например от онтологии, и учитывать их в ранжировании. В результате SHALL быть видно, какие результаты пришли через расширение.

#### Scenario: Синонимы

- **WHEN** к запросу «Юм» добавлен термин «Хьюм»
- **THEN** находятся абзацы с написанием «Хьюм», а в результате видно, что они найдены через расширение

### Requirement: Деградация

Если смысловой индекс или провайдер эмбеддингов недоступен, поиск SHALL отвечать по словам и сообщать в ответе, что смысловой поиск не использовался.

#### Scenario: Провайдер эмбеддингов недоступен

- **WHEN** провайдер эмбеддингов не отвечает
- **THEN** поиск возвращает результаты по словам с отметкой «только поиск по словам»

### Requirement: Пустой результат

Если подходящих абзацев нет, поиск SHALL возвращать пустой список, а не наименее плохие совпадения. Порог релевантности задаётся настройкой.

#### Scenario: Ничего нет

- **WHEN** запрос о теме, которой нет в библиотеке
- **THEN** поиск возвращает пустой список

### Requirement: Скорость поиска

Поиск SHALL отвечать достаточно быстро, чтобы ассистент укладывался в требование к скорости. Числовую границу зафиксируем после замеров на прототипе; поиск SHALL отдавать в журнале время каждой части: эмбеддинг запроса, смысловой поиск, поиск по словам, объединение.

#### Scenario: Время по частям

- **WHEN** выполнен поиск
- **THEN** в журнале событие с длительностью каждой части
