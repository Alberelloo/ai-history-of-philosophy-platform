# Design

## Контекст

- Карточку строит `Cards.card()` в `src/philograph/knowledge/cards.py`, адрес — `GET /v1/entities/{id}/card`. Разделы задаёт словарь `SECTIONS`: тип → `(код, заголовок, связи, направление)`. Утверждения, которые не попали ни в один раздел, клиенту не отдаются.
- Клиент: полная карточка `web/src/FullCard.tsx` в правой панели `SidePanel` (общая с ассистентом, стек «Назад»). Компактное окно `web/src/CardPopup.tsx` берёт до двух строк из `sections`. Шаблон один на все типы. У персоны есть `Lifeline` и сводка-счётчики. У строки — `StatusMark` с подписью, «— так считает: …», «не согласны: …» и ссылки `pg-cite`. Внизу — «Где читать» и рецепты графа.
- Ширина панели — токен `--panel: 28rem` (`docs/design/tokens.json` → `web/src/styles/tokens.css`). Та же величина записана константой `PANEL = 28` в `web/src/layout.ts`: раскладка K1–K4 считает свободную ширину `A = окно − навигация − панель`. Колонка текста — 62–68ch шрифта чтения (≈ 684–750px при 19px).
- Диагноз пустых карточек — [docs/audit/card-design-diagnosis.md](../../../docs/audit/card-design-diagnosis.md). Главная причина — код: нет разделов для `term`, `group` и `place`, у `work` только `context`, перечисления не показаны. Вторая причина — редкие данные.
- В реестре (`registry_data.py`) у `lived_in` есть уточнитель `place_role` (`birth`, `death`, `activity`, `residence`). У места есть значение `coordinates` (`{lat, lon}`), но нет страны. Поля «интересы» нет.

## Контракт ответа карточки

Прежние поля сохраняются с прежним смыслом: `id`, `type`, `title`, `names`, `dates`, `portraits`, `description`, `description_pending`, `sections`, `where_to_read`, `recipes`. По `grep` в `web/src` ими пользуются `FullCard.tsx` и `CardPopup.tsx` (`sections[].rows`, `dates`, `description`, `portraits`). Ни одно прежнее поле строки не удаляется и не меняет тип.

Новое на верхнем уровне:

| Поле | Тип | Смысл |
|---|---|---|
| `layout` | `"person" \| "entity" \| "epoch"` | Шаблон карточки. Решает сервер по таблице типов: `person` → `person`, `epoch` → `epoch`, остальные → `entity` |
| `summary` | объект или `null` | Только у `layout = "person"`: `roles` (строки `person_role`), `place` (строка основного места или `null`), `years` (`dates.original` или `null`), `years_row` (строка утверждения `lifespan` для отметки годов: с `mark`, атрибуциями, подтверждениями; `null`, если видимого `lifespan` нет; из нескольких — совпадающая с `years`, иначе самая сильная), `polity` (историческое образование в точке основного места на год рождения: `{name, name_status, year}` или `null`) |
| `geo` | `{lat, lon}` или `null` | Только у `type = "place"`: координаты из утверждения `coordinates` |
| `legend` | список кодов | Отметки, которые есть в карточке (строки разделов, `summary` и описание: сгенерированное описание даёт `generated`), в порядке `verified`, `sourced`, `generated`, `disputed`. Нет ни строк, ни описания — пустой список |
| `empty` | bool | `true`, если нет ни строк разделов, ни описания, ни непустой `summary`, ни координат места `geo` (D4: координаты — тоже сведения, по ним клиент показывает инфобокс места) |

Новое у раздела `sections[]`:

| Поле | Тип | Смысл |
|---|---|---|
| `display` | `"facts" \| "list" \| "inline"` | Как показывать: инфобокс (подпись — значение), список или одна строка через запятую |
| `visible` | int или `null` | Сколько строк видно до «Показать все». `null` — все |
| `total` | int | Число строк раздела (= `len(rows)`) |
| `inferred` | bool | В разделе есть выведенные строки (подпись раздела «по трудам и связям») |

Новое у строки `rows[]`:

| Поле | Тип | Смысл |
|---|---|---|
| `mark` | `"verified" \| "sourced" \| "generated" \| "disputed"` | Единая шкала. `disputed`, если `consensus = "disputed"`, иначе `status`. У выведенной строки — самое слабое звено цепочки. **Изменение показа:** утверждение `sourced` без подтверждений (импорт Wikidata, `statements.py:387`; или подтверждение снято регионом) получает `mark = "sourced"`. Раньше клиент рисовал «по источникам» только при непустом `evidence`. Отметка описывает статус утверждения, а не наличие видимой ссылки. Для читателя вне РФ статус не пересчитывается (regional-access) |
| `inferred` | bool | Строка — вывод из других утверждений, а не утверждение. Признак вывода — только это поле. Остальные поля строки у неё есть, с прежним смыслом (ниже) |
| `via` | список `{entity_id, label}` | Только у выведенной строки: через какие сущности сделан вывод (труды, термины), не больше трёх |
| `note` | str или `null` | Краткое пояснение кодом сервера: год труда (`dating.original`) в разделе «Труды». Роль места (`qualifiers.place_role`) в этом изменении не показывается — отложено (см. «Отложено») |
| `geo` | `{lat, lon}` или `null` | Только у строки основного места в `summary.place` и у строк «Где жил»: координаты места |
| `also` | список `statement_id` | Другие утверждения о той же сущности, свёрнутые в эту строку (правило «одна строка на сущность»); иначе `[]` |

**Выведенная строка — полная строка.** Прежние поля у неё такие:

- `statement_id` — `"inferred:<код раздела>:<entity_id>"`: строка, как у всех, и уникальная в карточке. Приставка повторяет уже имеющийся образец производных утверждений `derived:…` (`statements.py`);
- `type` — код связи последнего звена: `author` у авторов трудов, `introduced_by` у персон через термин, `discusses` или `expresses` у интересов;
- `relation` и `inverse` — подпись этой связи, как у утверждения;
- `entity_id` и `label` — показанная сущность, `value = null`, `qualifiers = {}`;
- `status` — самое слабое звено, `consensus` — `disputed`, если спорно хоть одно звено, иначе `consensus` звеньев. `disputed = (consensus == "disputed")`, `generated = (status == "generated")`;
- `derived = true`: очередь проверки (`on_view`) производные строки уже пропускает;
- `evidence = []`, `attributions = []`, `attributed_to = []`, `disputed_by = []`, `in_textbook = null`;
- новые поля — `inferred = true`, `via`, `mark`, `also = []`.

Компактное окно (`CardPopup.topStatements`) выведенные строки отбрасывает (`!row.inferred`): оно показывает только утверждения. Это одна проверка в клиенте, её закрепляет нормативный тест.

Клиент не вычисляет ни отбор, ни порядок, ни статус. Он показывает то, что прислал сервер. Исключения два: перевод кодов через `i18n` и современная страна по `geo` (модуль `countries.ts`) — она нужна только как запасной путь без исторического образования.

## Разделы по типам (данные `SECTIONS`)

Порядок в таблице — порядок в ответе. `F` — `display = "facts"`, `L` — `list`, `I` — `inline`. Число в скобках — `visible`.

| Тип | Разделы |
|---|---|
| `person` (`layout = person`) | `places` «Где жил» I(3) `lived_in` out; `influenced_by` «Повлияли» L(5) `influenced_by`* out; `influenced` «Повлиял на» L(5) `influenced_by`* in; `teachers` «Учителя и ученики» L(5) `studied_with` both; `schools` «Школа и направление» I `member_of`, `founded` out; `positions` «Учения» L(5) `holds`, `advanced` out; `interests` «Интересы» I(6), вывод; `works` «Труды» L(6) `author` in; `biography` «Биография» L(5) `participated`, `worked_at` out; `epoch` «Эпоха» I `belongs_to_epoch` out; `context`; `other` |
| `concept` | `definitions` «Определения» L(3); `relates_to` «К кому относится» I(5), вывод; `words` «Термины» I `denotes` in; `conceptions` «История: концепции» L(5); `related` «Связанные понятия» L(5); `problems` «Проблемы» L(5); `in_works` «В трудах» L(5) `discusses` in; `epoch`; `context`; `other` |
| `doctrine`, `problem`, `position`, `argument`, `conception` | `facts` «Сведения» F: `part_of` out, `conception_of` out; `relates_to` «К кому относится» I(5): `holds`, `advanced` in и вывод; `parts` «Состав» L(5) `part_of` in; `answers` «Ответы» L(5) `answers` both; `arguments` «Аргументы за и против» L(5); `in_works` «В трудах» L(5) `expresses`, `discusses` in; `influence` «Влияния» L(5) `influenced_by`* both; `epoch`; `context`; `other` |
| `term` | `facts` «Сведения» F: `denotes`, `introduced_by`, `derives_from` out; `translations` «Переводы» I `translated_as` both; `in_works` «В трудах» L(5) `discusses` in; `epoch`; `other` |
| `work` | `facts` «Сведения» F: `author` out, `dating` out, `work_part_of` out; `topics` «Вопросы и сферы» I(8) `discusses`, `expresses` out; `cites` «Ссылается на» L(5) `cites` both; `response` «Ответы и отклики» L(5) `written_in_response` both; `influence` «Влияния» L(5) `influenced_by`* both (кроме `written_in_response`); `parts` «Состав» L(5) `work_part_of` in; `epoch`; `context`; `other` |
| `event`, `phenomenon`, `idea_event` | `when` «Дата и место» F: `event_kind`, `dating`, `happened_in` out; `participants` «Участники» I(6) `participated` in; `genesis` «Как возникло» L(5) `source_material`, `result`, `in_work`, `circumstance` out (только `idea_event`); `effects` «На что повлияло» L(5) `stimulated` out; `epoch`; `other` |
| `group` | `facts` «Сведения» F: `group_kind` out; `membership` «Состав» I(8) `member_of` in; `founders` «Основатели» I `founded` in; `positions` «Учения» L(5) `holds` out; `debated` «Полемика» L(5) `debated` both; `staff` «Работали» I(6) `worked_at` in; `epoch`; `context`; `other` |
| `place` | `residents` «Жили здесь» I(8) `lived_in` in; `events` «Что произошло» L(5) `happened_in` in; `other`. Координаты — в поле `geo`, страна — на клиенте |
| `epoch` (`layout = epoch`) | как есть: `dating` «Датировка», `members` «Относятся к эпохе». Раздела `other` нет |

`*` — связь с подтипами (`relation_subtypes`). В `influenced_by` и `influenced` персоны не входит `studied_with`, у неё свой раздел `teachers`. Код `influence` у персоны больше не используется.

**Раздел `other` «Другие связи»** L(5) собирает утверждения о сущности, которые не попали ни в один раздел. Исключения: `description`, `lifespan` (годы в шапке), `person_role` (в `summary`), `coordinates` (в `geo`), производные утверждения (`derived`) и отвергнутые. Так данные больше не теряются молча (причина 1 диагноза). У эпохи раздела нет: по задаче владельца её карточка «как есть».

**Одна строка на сущность.** В разделах персоны `influenced_by`, `influenced`, `teachers`, `places`, `works` и в `relates_to` утверждения об одной и той же сущности сворачиваются в одну строку: строку утверждения с самой сильной отметкой (`verified` > `sourced` > `generated`; при равенстве — больше подтверждений, затем раньше записано). Тип связи остаётся полем строки (`relation`), остальные утверждения — в `also` (список `statement_id`). Влияние читается списком имён, без повторов.

**Основное место персоны** (`summary.place`): из строк `lived_in` выбирается одна. Сначала смотрится `place_role`: `activity` > `residence` > `birth` > `death` > без роли. Дальше — сила отметки, затем число подтверждений, затем порядок записи. В разделе `places` основное место стоит первым, остальные идут по тому же порядку.

**Выводы.**

- `interests` персоны. Берутся труды персоны (`author` in). У каждого труда — объекты `discusses` и `expresses` типа `concept` или `problem`. Объекты ранжируются по числу трудов, при равенстве — по названию. Сущности, уже показанные в `positions`, исключаются. Видно не больше шести. Просматривается не больше `INFER_SCAN = 30` трудов.
- `relates_to` идеи. Прямые строки — `holds` и `advanced` in. К ним добавляются выведенные строки: авторы трудов, которые рассматривают или выражают идею (`discusses`/`expresses` in → `author` out), а у понятия ещё и персоны через термин (`denotes` in → `introduced_by` out). Если для персоны есть прямая строка, выведенной для неё нет.
- Отметка выведенной строки — самое слабое звено её лучшей цепочки. Пример: проверенный автор и сгенерированное «рассматривает» дают `generated`. Вывод никогда не показывается сильнее, чем его основания (модель предлагает, код проверяет). Отвергнутые и скрытые по региону утверждения в цепочки не входят.

## Клиент

- **Шапка.** У персоны: портреты, затем имя (`h3`). Под именем — строка сводки `[data-card-summary]` с частями `[data-summary=role]`, `[data-summary=place]`, `[data-summary=country]` и `[data-summary=years]`, через « · ». Годы показаны один раз, только здесь: строки `lifespan` нет, `Lifeline` нет, `.card-dates` у персоны нет. У остальных типов шапка прежняя: метка семьи, `dates.original`. Части сводки из утверждений — роли (`summary.roles`) и основное место (`summary.place`) — помечаются так же, как строки: `button.card-mark[data-mark]` с тем же доступным именем, подробности по нажатию, `data-unverified` у сгенерированного (обёртка `.card-summary-part`). Так каждый пункт легенды соответствует видимой метке. Годы помечаются по `summary.years_row` (утверждение `lifespan`; решение ведущего, круг 4): `summary.years` остаётся строкой, отметка — рядом, чтобы не ломать поле. Отметки ролей, места и годов входят в `legend`.
- **Инфобокс** `dl.card-facts` — разделы с `display = facts`: подпись `dt`, значения `dd`. От 32rem панели — две колонки (подпись 9rem и значение), до 32rem — подпись над значением.
- **Список** — `ul`, **строка через запятую** — `p.card-inline` с элементами `span.card-row`. Пока строк больше `visible`, видно `visible` строк и кнопка `[data-card-more]` «Показать все (N)» с `aria-expanded="false"`. Нажатие показывает все строки и меняет подпись на «Свернуть».
- **Отметка.** У каждой строки — `button.card-mark[data-mark=<mark>]` без видимого текста, форма зависит от статуса: `verified` — круг цвета `--ok`, `sourced` — кольцо цвета `--accent`, `generated` — ромб цвета `--generated` (как прежний значок сгенерированного), `disputed` — треугольник цвета `--danger`. Цвет вместе с формой: различимо и без цветового зрения (WCAG 1.4.1). Доступное имя (`aria-label` и `title`): «<статус>. Так считает: …. Не согласны: …» (у выведенной строки — «<статус>. Вывод: через …»). Нажатие раскрывает `.card-row__details` (`hidden` до нажатия, `aria-expanded`): кто так считает, кто не согласен, через что сделан вывод. Ссылки на абзацы `a.pg-cite` остаются у строки видимыми номерами, без текста. У сгенерированной строки остаётся атрибут `data-unverified="true"`.
- **Легенда** — один элемент `[data-card-legend]` под шапкой. В нём пункты `[data-legend=<mark>]` из `legend` ответа: та же форма и цвет и подпись статуса с кратким описанием («проверено человеком», «по источникам», «сгенерировано моделью, не проверено», «источники расходятся»). Это единственное видимое место карточки, где статус написан словом. Доступные имена (`aria-label`, `title`, `<title>` у svg) — не видимый текст. Сгенерированное описание помечается той же меткой `generated` (ромб), и `legend` его учитывает.
- **Пустое состояние.** `empty = true` (у места с координатами его нет: `empty` учитывает `geo`) → `[data-card-empty]` «Об этом пока известно мало» и подсказка: если `where_to_read` не пуст, «где об этом читать» ниже, иначе — «Сведения появятся, когда онтология пополнится; спросите ассистента». Белого экрана нет.
- **Государство.** У персоны:
  - если есть `summary.polity`, `[data-summary=country]` показывает `polity.name` с `data-country-kind="historical"` и `title` «на <год> год»;
  - иначе, если у `summary.place.geo` есть координаты, клиент вызывает `import("./map/geo/countries")` и `countryAt(lat, lon)`. Показывает «ныне <страна>» с `data-country-kind="modern"`.

  У места исторического года нет. Инфобокс места при `geo` всегда показывает координаты `[data-card-coordinates]` («Координаты», «54,71° с. ш., 20,51° в. д.», в EN «54.71° N, 20.51° E»; формат — в i18n), поэтому тело карточки не пусто при любом исходе поиска страны. Страна — `[data-card-country]` «ныне <страна>» с `data-country-kind="modern"`, только когда найдена. Страна не найдена, модуль не загрузился или ещё грузится — страны нет, заглушки нет. Современная страна без пометки «ныне» MUST NOT показываться: это анахронизм. Модуль границ попадает в отдельный фрагмент сборки (динамический `import`), основной фрагмент не растёт.
- **Тексты.** Названия, значения, атрибуции и подписи выводятся текстовыми узлами React. `dangerouslySetInnerHTML` и `innerHTML` в карточке не используются.

## Ширина панели

Ширина — по свободному месту. Её считает одна функция `panelWidth(m)` в `web/src/layout.ts` из ширины окна, корневого кегля, ширины 1ch шрифта чтения и закрепления навигации. Пределы: 28rem и 36rem. Результат округляется вниз до 0,5rem.

- **Полоска (окно 1024–1279px):** `min(36rem, окно − навигация − 2rem)`. Панель при развороте лежит поверх текста, раскладку не меняет и навигацию (56px) не закрывает.
- **1280–1439px:** `clamp(28rem, окно − навигация − потребность K4, 36rem)`. При открытой панели раскладка K4: на 1366 полоса оглавления уступает место кнопке «Оглавление» (было K3). Так решил владелец: ширина важнее.
- **От 1440px:** `clamp(28rem, окно − навигация − потребность R, 36rem)`, где R — раскладка, которая помещается при панели 28rem. Раскладка при открытой панели остаётся той же, что при 28rem.

Навигация считается после правила временного сворачивания. Его порог по-прежнему проверяется при панели 28rem (`A` меньше потребности K4 из `needs()`, а не отдельной константы 744px: иначе на окнах 1472–1475 с закреплённой навигацией колонка выходила уже 62ch), иначе правило зависело бы от результата, который само определяет. Потребности (при 1ch = 11,03px, 62ch ≈ 684px): K4 — 748, K3 — 844, K2 — 1004, K1 — 1332.

| Окно | Навигация | Панель | Раскладка при открытой панели | Сейчас (28rem) |
|---|---|---|---|---|
| 1024 (полоска развёрнута) | 56 | 36rem = 576 | K3, раскладка не меняется | 448, K3 |
| 1280 | 56 | 29,5rem = 472 | K4 | 448, K4 |
| 1366 | 56 | 35rem = 560 | K4 | 448, K3 |
| 1440 | 56 (временно свёрнута, если закреплена) | 33,5rem = 536 | K3 | 448, K3 |
| 1680 | 56 | 36rem = 576 | K2 | 448, K2 |
| 1680 | 280, закреплена | 34,5rem = 552 | K3 | 448, K3 |
| 1920 | 56 | 33rem = 528 | K1 (поле сносок остаётся) | 448, K1 |
| 1920 | 280, закреплена | 36rem = 576 | K2 | 448, K2 |

На каждом из размеров владельца (1024×576, 1366×768, 1920×1080) панель шире 448px. Правый отступ колонки — по действующему правилу K4/K3 (≥ 24px), поэтому сценарий visual-design «Открытая панель» (край текста ≤ край панели − 24px) выполняется. Выше 1920px всё растёт вместе с корневым кеглем (Р9).

`computeLayout` берёт ширину панели из `panelWidth`. `SidePanel` выставляет `--panel` (px) на `document.documentElement` из той же функции и по тем же замерам: общий хук `useLayoutMetrics` (корневой кегль, 1ch, ширина окна) вынесен из `ReaderPage`. При закрытии панели `SidePanel` снимает `--panel`. CSS (`.side-panel`, `.first-run`) по-прежнему читает `var(--panel)`. Токен `panel` (28rem) остаётся значением до первого замера.

На карте `/graph`, в справочнике и на странице эпох панель лежит поверх правой части экрана, как и сейчас. Ширина та же. Сценарий «Карточка на карте» проверяет только «не ломается и шире»: нет горизонтальной прокрутки, панель в окне, ширина больше 448px.

## Журнал

`knowledge.card.served` (уже есть). Обязательные поля: `entity_id`, `type`, `sections`, `rows` и новые `layout`, `empty`, `inferred`:

- `sections` — число разделов в ответе, как раньше;
- `rows` — сумма строк разделов, как раньше, выведенные строки входят; строки `summary` не входят;
- `layout` — код шаблона;
- `empty` — bool, как в ответе;
- `inferred` — число выведенных строк;
- `polity` — исход поиска образования для `summary.polity`: `found`, `none` (слой есть, образования в точке на год нет), `unavailable` (нет артефакта слоя), `skipped` (не персона, нет координат или года рождения).

Личных данных и текстов в событии нет. Новых событий нет. Действия клиента («Показать все», раскрытие отметки) — интерфейсные результаты без клиентского журнала; их серверный якорь — `knowledge.card.served` с `request_id` запроса карточки.

### 4. Государство основного места

| Вариант | Оптимальность | Архитектура | Поддержка и масштаб |
|---|---|---|---|
| А. Простейший: страну не показывать | Ноль кода | — | C2 частично: только город |
| Б. Современная страна на клиенте (`countries.ts`) без пометки | Основной бандл не растёт | Правило одно, уже проверенное | Анахронизм как факт: «Кёнигсберг · Россия» у Канта. Нельзя |
| В. Клиент запрашивает `/map/polities?year=T` и ищет образование в точке | Сотни КБ на открытие карточки ради одной строки | Правило «образование в точке» в клиенте, сервис-владелец слоя — knowledge | Тяжело при многих карточках |
| Г. Сервер: `PolityLayer.at(lat, lon, year)` — образование, чей многоугольник содержит точку основного места на год рождения. Без слоя, вне покрытия или без года — современная страна на клиенте с пометкой «ныне …» | Один SQL-запрос по индексу лет. Рамки образований интервала разбираются один раз и держатся в кэше по интервалу (≤ 8 интервалов). Многоугольник разбирается только у тех, чья рамка содержит точку | Правило «активно на T» уже живёт в `polities.py`, поиск в точке — рядом, в том же модуле. Модель не участвует. Современная страна — запасной путь, всегда подписан | Без новых зависимостей (точка в многоугольнике — лучевой алгоритм на плоскости lon/lat). Нет артефакта — честный запасной путь |

**Выбрано: Г.** Год — год рождения (`dates.earliest_start`, если он совпадает с `latest_start`, иначе середина интервала). Если точку содержат несколько образований, берётся меньшее по площади (более частное). Чем платим:

- первое открытие карточки на новый интервал лет разбирает геометрии слоя: десятки миллисекунд;
- лучевой алгоритм на плоскости верен только для колец, разрезанных по ±180° (RFC 7946). Допущение закреплено проверкой сборки: `polities_build.check_antimeridian` — ребро со скачком долготы больше 180° или долгота за ±180° дают `BuildError`;
- повреждённый артефакт (нет таблицы, битая геометрия) в `PolityLayer.at` переводится в `PolitiesUnavailable("format")`: карточка получает `polity = unavailable` и запасной путь «ныне …», а не 500;
- кэш интервалов (≤ 8) вытесняет по давности использования (LRU). Геометрия строки разбирается один раз на запись кэша, когда её рамка впервые содержит точку, и хранится только у таких кандидатов;
- у места год неизвестен, поэтому там только современная страна с пометкой «ныне».

Костыли, которых избегаем: страна от модели, словарь «город → страна», современная страна без пометки.

Колонка текста ≥ 62ch, без перекрытий и горизонтальной прокрутки. Вариант Г это выполняет: на 1280–1439 раскладка K4, где оглавление открывается кнопкой «Оглавление».

- ассистент тоже шире (вопрос владельцу 1).

Костыли, которых избегаем: вторая константа ширины в TS и в CSS, медиазапросы с числами, повторяющими формулу.

## Режим «только выбранный учебник» и выводы

Решение ведущего (круг 4): в режиме `attributed_to` фильтр атрибуции проходят все звенья вывода, а не только утверждения о самой сущности. Выведенная строка показывается, только если каждое звено её цепочки проходит фильтр. Так требует source-scope («показываются только утверждения с атрибуцией выбранного учебника»): выведенная строка показывает утверждения, и режим обещает только учебник.

Реализация: `_work_facts(work_id, attributed_to)` (звенья через труд — `author`, `discusses`, `expresses`) и чтение `introduced_by` у термина в `_relates_to` вызывают `statements.about` с тем же `attributed_to`. Первое звено уже отфильтровано, потому что `statements` сущности читаются с ним. Цена: в режиме учебника выводов меньше. Правило — в дельте «Выведенные строки».

## Отложено

- **Роль места** (`qualifiers.place_role`: родился, умер, работал, жил) у строк «Где жил» и у основного места не показывается. Порядок основного места её учитывает (выше), показ — отдельной задачей.

## Риски

- **R1. Данных мало.** После изменения многие карточки будут из одной-двух строк. Это честно и предусмотрено (`empty`, `other`), но может выглядеть бедно до переизвлечения.
- **R2. Изменение ширины трогает раскладку чтения.** Эталоны снимков (Windows) на 1440 и 1920 устареют, их обновляет владелец (`visual_check.py --update`). На Linux остаются проверки по DOM.
- **R3. Выводы на больших карточках.** У персоны с десятками трудов вывод ограничен `INFER_SCAN = 30`. Какие труды берутся первыми — порядок записи, поэтому интересы — оценка, а не полный список. Это записано в подписи раздела.
