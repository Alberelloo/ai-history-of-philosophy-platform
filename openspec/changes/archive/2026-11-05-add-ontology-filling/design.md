# Design

## Context

Мотивация в [proposal.md](proposal.md), порядок наполнения — раздел 12 [ontology.md](../../../../docs/product/ontology.md), требования в `ontology-extraction` и `ontology-review`. Модель онтологии — [add-ontology-core](../2026-11-05-add-ontology-core/design.md).

## Decisions

### 1. Извлечение — подписчик события публикации

Подписка `knowledge:source.published` обновляет подтверждения и запускает извлечение. Для первой версии источника — по всем абзацам, для следующих — только по фрагментам с добавленными и изменёнными абзацами. Источник без разрешения на внешнюю обработку пропускается.

### 2. Фрагменты с перекрытием, повторы сводит модель утверждений

Фрагмент — несколько абзацев одной главы. Соседние фрагменты перекрываются на один абзац, чтобы связь на стыке не потерялась. Одно и то же утверждение из двух фрагментов объединяется ключом утверждения, а не отдельной логикой.

### 3. Схема вывода из реестра и общий тип

Модель получает схему структурированного вывода, собранную из реестра. Если частный тип не подходит концам, код поднимается по иерархии к родителю («развивает» → «испытал влияние»). Предложенный моделью новый тип уходит на проверку, а утверждение записывается с общим типом.

### 4. Сбой модели отбрасывает фрагмент, а не запуск

Ответ не по схеме или недоступность модели — событие `knowledge.extraction.dropped` и счётчик отброшенного. Запуск идёт дальше.

### 5. Нормализация без угадывания

Название ищется среди названий и вариантов с учётом типа. Если кандидатов несколько, выбирается тот, что уже связан с сущностями этого фрагмента. Иначе вопрос уходит в очередь проверки (`ambiguous_link`), а утверждение не записывается.

### 6. Проверка — те же данные, что и онтология

Очередь собирается из утверждений с предупреждениями, утраченными подтверждениями и статусом «сгенерировано», а также из `review_items` (неоднозначные привязки, дубли) и предложенных типов. Приоритет — взвешенная сумма показов, спорности, предупреждений и статуса, веса — настройка. Решения пишутся в журнал утверждения и в журнал действий оператора.

### 7. Выборка для метрик экспортируется в оценку

Решения по выборке выгружаются в формате набора `statements` из `add-evaluation-harness`. Метрики онтологии считает оценка, не сервис знаний.

## Risks / Trade-offs

- [Извлечение по всей библиотеке дорого] → оценка стоимости на пробе, лимит запуска в сервисе LLM, откат запуска.
- [Очередь проверки растёт быстрее, чем её разбирают] → приоритет по показам: сначала то, что видят читатели.
