# Proposal

## Why

Диагноз [docs/audit/extraction-diagnosis.md](../../../../docs/audit/extraction-diagnosis.md) (26.11.2026) по задаче [spec-ontology-reextraction.md](../../../../docs/process/spec-ontology-reextraction.md):

- Отброшено ~95% (20 557 против 1099 созданных). Почти всё — не утверждения, а целые фрагменты: строгая схема шлюза бракует весь ответ из-за одного поля (П2), клиент знаний рвёт вызов раньше, чем шлюз заканчивает повторы (П1).
- 639 из 817 запусков навсегда «running»: исключение внутри `extract_version` не завершает запуск.
- В базе нет ни модели (`model="main"` — имя роли), ни причин отбраковки, ни токенов, ни длительности (П9, П10). Ветка «ответ шлюза не 200» отбраковку не считает (П11).
- Сверка цитаты не находит цитату в кавычках, с многоточием-пропуском, с другим тире, мягким переносом и ударениями (П4).
- Сущности создаются до проверки цитаты — остаются сироты (П7).
- Персонажи «Заратустры» становятся персонами (П8), фрагменты по 4 абзаца дают и 500, и 3000 символов (П12).

Переизвлечение всех 208 источников делает Claude (`claude-opus-5-5`) вне шлюза: код выдаёт фрагменты, Claude отвечает по схеме, код проверяет и записывает тем же путём, что ответы шлюза (задача, раздел 2.4).

## What Changes

- **Проверка ответа по утверждениям.** Шлюзу уходит мягкая схема (массив объектов с обязательными полями, без перечней и типов необязательных полей). Каждый элемент проверяет сервер знаний: `null` в необязательном поле — отсутствие, `paragraph: "4"` — число 4, код связи вне реестра — предложение нового типа и «испытал влияние», тип сущности вне реестра — отказ элемента. Плохой элемент не бракует остальные.
- **Коды причин.** Каждое `knowledge.extraction.dropped` несёт `code` из закрытого перечня; сводка `{код: число}` хранится в запуске (`drop_reasons`). Ответ шлюза не 200 считается в `dropped`.
- **Сверка цитаты.** Одна нормализация (кавычки, тире, мягкий перенос, ударения, NBSP, `ё`, регистр, пробелы) во всех местах сверки; внешние кавычки снимаются; многоточие делит цитату на части, каждая — дословно и по порядку. Пересказ по-прежнему отбрасывается.
- **Проверки до сущностей.** Абзац и цитата проверяются до привязки и создания сущностей.
- **Запуск всегда завершается.** Исключение → статус `failed`, `failure`, `finished_at`, событие `knowledge.run.failed`.
- **Модель и метрики запуска.** `filling_runs.model` и `Provenance.model` — идентификатор модели. Новые поля `filling_runs` (миграция `knowledge:10`): `extractor`, `source_id`, `fragments`, `duration_seconds`, `input_tokens`, `output_tokens`, `drop_reasons`, `failure`. Стоимость — по тарифу модели.
- **Внешний извлекатель.** Модуль и команда `python -m philograph.knowledge.external_extraction` с подкомандами `export` (задание JSONL), `ingest` (ответы через общий путь проверки) и `report` (таблица запусков в `docs/audit/`).
- **Промпт `ontology.extract`.** Персонажи художественного текста — не персоны; высказывания персонажа, излагающие учение автора, атрибутируются автору произведения.
- **Фрагмент по объёму.** Окно растёт до ~3000 символов (не меньше одного абзаца, в пределах главы, предел числа абзацев, перекрытие в один абзац).
- **Таймаут вызова шлюза.** Таймаут клиента знаний на вызов извлечения — не меньше бюджета шлюза на все попытки; шлюз сообщает бюджет и модель роли (`GET /v1/roles/{role}`).

## Capabilities

- `ontology-extraction` — MODIFIED: «Фрагменты из нескольких абзацев», «Цитата у каждого утверждения», «Запуски наполнения»; ADDED: «Проверка ответа по утверждениям», «Коды причин отбраковки», «Внешний извлекатель», «Отчёт о запусках извлечения», «Таймаут вызова модели при извлечении», «Художественный текст».

## Out of scope

- Само переизвлечение 208 источников и отчёт `docs/audit/extraction-run-2026-11-26.md` — работа ведущего после принятия изменения (данные на его машине).
- Продолжение прерванного запуска (возобновление с фрагмента): повтор задания очереди начинает новый запуск, но прежний уже `failed`, а не `running` — см. design.md, «Открытые вопросы».
- Проверка типов концов до создания сущностей (П7 полностью): тип найденной сущности известен только после привязки.
- Пометка художественных текстов в каталоге источников.
- Клиент не меняется.

## Impact

- Код: `knowledge/filling.py`, `knowledge/statements.py`, `knowledge/dating.py`, `knowledge/entity_items.py`, `knowledge/schema.py`, `knowledge/main.py`, новые `knowledge/quotes.py`, `knowledge/extraction_codes.py`, `knowledge/external_extraction.py`, `knowledge/extraction_prices.yaml`; `llm/app.py`, `llm/gateway.py`, `llm/store.py` (маршрут роли, токены в сводке расходов); `prompts/__init__.py`.
- Схема базы: `knowledge:10` — новые столбцы `filling_runs` (Postgres и SQLite).
- Тесты, ожидающие прежний контракт (строгая схема шлюза с перечнями; точное множество ключей `knowledge.extraction.dropped` без `code`), меняются тестировщиком по новой дельте — список в `progress.md`.
