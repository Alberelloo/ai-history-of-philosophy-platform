## N1. Фокус теряется после «Выбрать все» / «Снять все», Esc не закрывает окно (заметно)

### Где в коде

`web/src/ui.tsx`, компонент `FilterMenu` (строки 369–457):

- `ui.tsx:386` — `all = items.every(selected.includes)`; `ui.tsx:385` — `count = selected.length`.
- `ui.tsx:425-441` — кнопки окна:
  - «Выбрать все»: `disabled={all}` (`:429`), `onClick={() => onChange(items.map(...))}`;
  - «Снять все»: `disabled={count === 0}` (`:437`), `onClick={() => onChange([])}`.
- `ui.tsx:399-404` — обработчик Esc `onKeyDown`: закрывает окно и `button.current?.focus()`.
- `ui.tsx:409` — обработчик повешен на корневой `<div className="pg-filter" onKeyDown={onKeyDown}>`, то есть ловит только keydown, всплывающий из потомков этого `div`.
- `ui.tsx:388-397` — при открытии фокус ставится на `button:not([disabled]), input`; внешний щелчок закрывает окно через `pointerdown` на `document` (поэтому щелчок вне окна у тестировщика работал).

`LibraryPage.tsx:74-85` подключает два экземпляра (`Вид`, `Язык`), поэтому эффект одинаковый у обоих.

### Почему так происходит

1. Пользователь нажимает «Выбрать все» (щелчком — Chromium фокусирует кнопку при нажатии мыши; Enter/пробелом — фокус уже на ней).
2. `onChange` → `setKinds` в `LibraryPage` → перерисовка; теперь `all === true`, и React ставит на ту же кнопку атрибут `disabled`.
3. По HTML (focus fixup rule: «focused area becomes inert or disabled») браузер убирает фокус с отключённого элемента. Chromium делает это сразу (blur без события `focusout` на новое место), и `document.activeElement` становится `body`. Ровно это зафиксировано в отчёте: `activeElement = BODY`.
4. Keydown всегда отправляется в элемент с фокусом. Теперь это `body`; путь всплытия `body → html → document`. `div.pg-filter` в этот путь не входит, и React-обработчик `onKeyDown` на нём не вызывается. На уровне `document` обработчика Esc нет, поэтому окно остаётся открытым.
5. При выборе флажка фокус остаётся на `input` внутри окна, Esc всплывает до `div.pg-filter`, всё работает. Так же со «Снять все» (`count === 0` после щелчка).

Побочно: после потери фокуса Tab начинает обход заново с начала страницы, клавиатурный пользователь теряет место. То есть это не только Esc, а потеря фокуса вообще.

Тот же приём (кнопка отключает сама себя) есть у «Сбросить поиск и фильтры» (`LibraryPage.tsx:87`, `disabled={!filtered}`): после нажатия фокус тоже уходит на `body`. Окна там нет, Esc не нужен, но место фокуса теряется. В N1 не входит; при исправлении стоит решить тем же способом (см. ниже), чтобы приём был один.

### Почему тест не поймал

`tests/web/test_library_reading.py:105` `test_kind_filter_select_all_clear_all_and_closing` — проходит. Он жмёт «Выбрать все» (`:110`), проверяет `is_disabled()` (`:114`), жмёт «Снять все» (`:115`), а проверку Esc (`:119-123`) делает только **после** `menu.get_by_label("Учебник").check()`. `check()` ставит фокус на флажок, то есть тест проверяет ровно тот путь, который работает. Сразу после «Выбрать все» или «Снять все» Esc не нажимается нигде. В `tests/e2e/test_visual_design.py` сценариев с фильтром нет (Esc проверяется только у панели, `:445`). Фильтр «Язык» вообще не проверяется на Esc.

### Варианты

**(а) `aria-disabled` вместо `disabled`.** Кнопка остаётся в фокусе и в порядке Tab, экранный диктор читает её как «недоступна», щелчок ничего не делает. Esc и Tab работают без особых случаев, потому что фокус никуда не уходит. Это приём, который WAI-ARIA APG советует для элементов, которые становятся недоступны, пока на них фокус. Минусы: нужно самим блокировать действие (иначе «Выбрать все» при уже выбранных всех вызовет `onChange` с новым массивом и лишний запрос) и продублировать стиль `[disabled]` для `[aria-disabled="true"]`.

**(б) Переводить фокус на соседнюю кнопку или первый флажок.** После «Выбрать все» активна «Снять все» и наоборот, так что сосед всегда есть. Но в момент `onClick` сосед ещё `disabled` (до перерисовки), значит переводить фокус надо после коммита: `useEffect` по `all`/`count` или `flushSync`. Это гонка с перерисовкой родителя и неожиданный прыжок фокуса для пользователя (нажал одну кнопку — оказался на другой). Больше кода, хрупче.

**(в) Esc на уровне `document`, пока окно открыто.** Окно закроется, но фокус всё равно потерян (Tab с начала страницы), и `button.focus()` при закрытии лишь маскирует это. Лечит признак, а не причину. Плюс два открытых фильтра теоретически оба слушали бы `document` (сейчас открыт один, но правило держится на внешнем щелчке).

**Выбор: (а).** Устраняет причину (фокус не теряется), не зависит от порядка перерисовки, не меняет внешний вид, подходит и для кнопки сброса. Playwright 1.64.1 (в `.venv`) считает `aria-disabled="true"` неактивностью, так что существующая проверка `is_disabled()` (`:114`) остаётся верной.

### Исправление

`web/src/ui.tsx:425-441`:

```tsx
<button
  type="button"
  className="pg-btn pg-btn--ghost pg-btn--sm"
  aria-disabled={all || undefined}
  onClick={() => { if (!all) onChange(items.map((item) => item.value)); }}
>
  {t.filter.selectAll}
</button>
<button
  type="button"
  className="pg-btn pg-btn--ghost pg-btn--sm"
  aria-disabled={count === 0 || undefined}
  onClick={() => { if (count > 0) onChange([]); }}
>
  {t.filter.clearAll}
</button>
```

`web/src/ui.tsx:391` — при открытии по-прежнему пропускать неактивные:
`button:not([disabled]):not([aria-disabled="true"]), input`.

`web/src/styles/components.css:33-41` — неактивный вид для обоих атрибутов:

- `:35` `.pg-btn[disabled], .pg-btn[aria-disabled="true"] { opacity: .45; cursor: not-allowed; }`
- `:33, :37, :39, :41` — в `:not([disabled])` добавить `:not([aria-disabled="true"])`, чтобы у неактивной кнопки не было подсветки при наведении и сдвига при нажатии.

Внешний вид не меняется (та же прозрачность), эталоны снимков пересниматься не должны.

По желанию, тем же приёмом: `LibraryPage.tsx:87` — `aria-disabled={!filtered || undefined}` и `onClick={() => filtered && reset()}`.

### Тест

В `tests/web/test_library_reading.py` новый тест (или параметр к существующему) для обоих фильтров, имя с `filter`, чтобы шёл под `-k filter`:

```python
@req(SL, "Фильтр по виду источника")
@pytest.mark.parametrize("name", ["Вид", "Язык"])
def test_filter_escape_after_select_all_and_clear_all(page, site, name):
    open_library(page, site)
    for action in ("Выбрать все", "Снять все"):
        button, menu = filter_menu(page, name)
        target = menu.get_by_role("button", name=action)
        target.click()
        assert target.is_disabled()                                    # стала неактивной
        assert target.evaluate("el => el === document.activeElement")  # фокус остался на ней
        page.keyboard.press("Escape")
        assert menu.count() == 0
        assert button.evaluate("el => el === document.activeElement")
```

Плюс клавиатурный путь хотя бы для одной кнопки: открыть Enter на кнопке фильтра, фокус на «Выбрать все», `Enter`, затем `Escape` — окно закрыто, фокус на кнопке фильтра.

Сейчас тест падает на проверке фокуса (`activeElement` = `BODY`) и на `menu.count() == 0`; после исправления проходит. Важно: не делать `.click()` по уже неактивной кнопке — Playwright будет ждать, пока она станет активной, и упадёт по времени.

Уверенность: высокая. Причина прямо следует из кода (`disabled` на кнопке с фокусом + обработчик на `div`, а не на `document`) и совпадает с наблюдением тестировщика (`activeElement = BODY`, флажок работает, щелчок вне окна работает).
