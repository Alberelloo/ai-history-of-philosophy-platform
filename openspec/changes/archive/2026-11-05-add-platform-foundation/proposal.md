# Proposal

## Why

Все возможности первой версии стоят на общем основании: сервисы запускаются одной командой, вызовы моделей идут через одно место с учётом расходов и дневным лимитом, у каждого действия есть журнал, по которому можно восстановить, что произошло. Без этого нельзя ни уложиться в бюджет 50 долларов в месяц, ни проверять поведение системы тестами по журналам. Это этап 1 [roadmap.md](../../../docs/product/roadmap.md).

## What Changes

- Сервис LLM: единственное место вызовов языковых моделей и моделей эмбеддингов. Роли моделей вместо имён, замена провайдера настройкой, потоковый ответ, таймауты и повторы, кэш одинаковых запросов, журнал вызовов, учёт стоимости по бюджетам, дневной лимит.
- Наблюдаемость: структурированный журнал событий с общим идентификатором запроса через все сервисы, каталог событий как контракт, метрики, проверки состояния, правила о персональных данных.
- Доступ оператора: внутренние страницы и команды закрыты, посетители их не видят.
- Запуск сервисов: одна команда, настройки из окружения, проверка настроек при старте, таймауты между сервисами, понятные ошибки.

## Capabilities

### New Capabilities

- `llm-gateway`: доступ к языковым моделям и моделям эмбеддингов, учёт расходов, лимиты, кэш и журнал вызовов.
- `observability`: журнал событий, сквозной идентификатор запроса, каталог событий, метрики, проверки состояния.
- `operator-access`: защита внутренних страниц и команд оператора.
- `service-runtime`: запуск, настройки, взаимодействие сервисов и поведение при сбоях соседей.

### Modified Capabilities

Нет.
