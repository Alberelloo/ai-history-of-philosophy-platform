## Стенд

`scripts/dev_stack.py` в-process без демо-источников (запасной регион `RU`), плюс свой шлюз с
`PHILOGRAPH_REGION_HEADER=CF-IPCountry` и `PHILOGRAPH_TRUSTED_PROXY=1`. Тестировщик добавил три
источника через настоящий конвейер библиотеки; вид `public-domain-ru` **не выдуман**: он взят из
`sources/licenses.yaml` через `CatalogService.ensure_license_kinds()` (то же делает `sync`).

| Источник | Вид | Регионы | Внешняя обработка |
| --- | --- | --- | --- |
| «Открытый сборник о рассудке» | `qa-open` (QA) | везде | разрешена |
| «Закрытый учебник без внешней обработки» | **`public-domain-ru`** (настоящие данные) | `[RU]` | **запрещена** |
| «Закрытый учебник с внешней обработкой» | `qa-ru-ext` (QA) | `[RU]` | разрешена |

События публикации переданы в очередь **после** старта стека, поэтому индексацию, извлечение знаний
и упоминания делал настоящий worker. В онтологию посеяны два однофамильца «Бэкон» (неоднозначное
упоминание) и однозначный «Кант».

## Что проверено на живом стенде

- **Индексация (TC-56, UC-30, R24).** У абзацев источника без внешней обработки
  `docs.external = false` и `docs.embedded = false` (2 из 2), у открытого — `true/true`; в журнале
  поиска `search.index.external_forbidden`, векторов у источника нет; в журнале LLM два вызова
  индексации (по числу источников с внешней обработкой), для источника без неё вызова нет (EC-48).
- **Поиск (TC-57).** Запрос «Каллистика прекрасном» из РФ отдаёт абзац с `external: false`, из DE и
  без региона — не отдаёт. «Каллистика рассудок» из РФ возвращает и закрытый, и открытые абзацы.
- **Ответ ассистента (TC-58, TC-59, TC-64).** Текст «СИГМА-3» не встречается ни в одном запросе к
  модели за весь прогон (журнал LLM). В потоке `notice found_not_retold` со ссылкой на абзац;
  открытый абзац («ОМЕГА-7») в passages есть, закрытый — нет; в `citations` закрытого абзаца нет.
  При `scope=current` и `source_id` закрытого источника: `passages: 0`, две пометки
  (`found_not_retold`, `no_library_support`), `assistant.answer.completed passages=0`.
  В режиме «только по источникам» все найденные абзацы непересказываемые: пометка `found_not_retold`
  и `no_answer` (EC-47).
- **Упоминания (TC-61, R26).** Неоднозначное «Бэкон» в источнике без внешней обработки:
  `knowledge.mentions.unresolved` (2 кандидата), строк упоминаний с этим именем нет, к модели за
  текстом источника не обращались; однозначный «Кант» поставлен методом `name` — словарный поиск
  работает.
- **Обратная совместимость (TC-63, EC-52).** Источник `[RU]` с `external_processing: true`:
  «ДЕЛЬТА-5» в passages, пометки нет, `knowledge.extraction.skipped` для него нет, поиск отдаёт
  `external: true`.
- **Читатель из DE (UC-28/DE, R5).** Источник закрыт целиком: `restricted: true`, `regions: ["RU"]`,
  без года и лицензии; поиск его не отдаёт; в вопросе из DE текста нет и пометки нет.
- **Вопрос без региона (TC-60).** Тот же вопрос через шлюз без заголовка страны (запасной регион
  пуст): источника `[RU]` нет в passages, пометки нет — регион неизвестен.
- **Данные 8.4 (TC-8.4).** `catalog validate` — exit 0; у вида `public-domain-ru` в
  `licenses.yaml` `regions: [RU]`, `external_processing: false`, `display: true`. На отдельной базе
  воспроизведён `sync`: вид был без регионов и с внешней обработкой, после `ensure_license_kinds`
  действующие регионы `[RU]`, внешняя обработка `false`, записано `source.access_changed` с
  `regions: ["RU"]`.
- **Клиент (TC-62, EC-50, EC-51).** Пометка «Найдено в источниках, не пересказывается.» с
  `role="status"` и ссылкой `/p/<id>`; клик ведёт на
  `/read/<источник>/<глава>#p-<абзац>`. Ошибок консоли и сетевых сбоев нет.

## Найденное расхождение

**F-1 (major).** В сценарии «найдены только непересказываемые абзацы» клиент показывает только
последнюю пометку (`no_library_support`), а `found_not_retold` со ссылками теряется: сервер шлёт обе
пометки (`live-report.json`, проверка `TC-64`), но `AssistantPanel.tsx` перезаписывает `message`
каждым `notice`, а ссылки рисуются только для `found_not_retold`. Читатель, ограничивший поиск
выбранным учебником, видит «Ответ составлен без опоры на библиотеку» и «В этой книге ответа нет»,
но не видит найденные места. Скриншот `TC-64-1-only-hidden-client.png`, журнал
`assistant.log` (`passages: 0`, `assistant.handoff reason=outside_book`).

## Осталось непроверенным

- EC-46 (пустой результат поиска): на демо-стенде невоспроизводимо — подставной провайдер
  эмбеддингов возвращает смысловые попадания на любой вопрос, поэтому «поиск не нашёл абзацев»
  получить нельзя; пометка `found_not_retold` действительно не появляется, когда среди результатов
  нет непересказываемых (`EC-49`/`TC-58`). Поведение «нет результатов → `no_answer`» покрыто
  автотестом `tests/assistant/test_routing_grounding.py::test_sources_only_mode` подставного поиска.
- TC-61/TC-63 в части «разрешитель вызывается»: в рабочем сервисе знаний `Mentions` создаётся без
  `resolver` (`knowledge/main.py`), поэтому модель-разрешитель не вызывается ни для источников с
  внешней обработкой, ни без неё. Для закрытого источника это совпадает со спекой (вызова нет,
  упоминание неоднозначно — проверено), но «ведёт себя как раньше» для `external: true` на живом
  стенде проверить нельзя; автотест проверяет это подставным `resolver`. Требует решения владельца:
  подключить разрешитель к LLM или зафиксировать в спеке, что разбора моделью нет вовсе.
- Настоящий CDN и проверка конфигурации развёртывания — задача 8.6; `tests/e2e` не прогонялись
  (нужен собранный `web/dist` и подъём стека), браузерные сценарии проверены на `web/dist` живого
  стенда.
- EC-51 проверен в браузере только для пометки `found_not_retold` (роль `status`, фокус на ссылке);
  сценарий с двумя пометками описан в F-1.
