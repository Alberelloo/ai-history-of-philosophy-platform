# Design

## Context

Мотивация в [proposal.md](proposal.md), угрозы и эксплуатация — блок 8 [system-design.md](../../../../docs/product/system-design.md), требования в `abuse-protection`, `backup-and-recovery`, `operational-alerts` и `deployment`. Продукт работает на одном сервере в Docker Compose ([add-platform-foundation](../2026-11-05-add-platform-foundation/proposal.md)). Аккаунтов нет, главная угроза — израсходованный бюджет на модели.

## Decisions

### 1. Лимиты — в шлюзе

Шлюз — единственный вход снаружи, поэтому все лимиты стоят в нём (`gateway/limits.py`):

- **Частота.** Корзина токенов на адрес для всех запросов, включая статику: `PHILOGRAPH_RATE_PER_SECOND`, `PHILOGRAPH_RATE_BURST`. Превышение получает 429 с `Retry-After`. Адрес берётся из `X-Forwarded-For`, только если включён `PHILOGRAPH_TRUSTED_PROXY`, то есть шлюз стоит за своим обратным прокси.
- **Токен страницы.** HTML продукта приходит с подписанной cookie `pg_page`: время выдачи и подпись по секрету и признаку браузера, срок 12 часов. Платная операция без действующего токена получает 403 `page_token_required`. Так отсекается прямой вызов скриптом, который не открывал страницу.
- **Платные операции.** Вопрос ассистенту, достройка графа и описание карточки считаются в час и в сутки на посетителя (`PHILOGRAPH_LIMIT_ASK=20/100` и так далее). Посетитель — хеш адреса и признака браузера с суточной солью. Операция без генерации (граф или описание с `generation=false`) бесплатна и не считается.
- **Отказ не ломает бесплатное.** Вопрос сверх лимита получает событие `unavailable` с временем ожидания в том же потоке NDJSON, что и обычный ответ. Граф уходит сервису знаний с `generation=false` и `visitor_limited=true`: строится из сохранённых связей с пояснением. Описание карточки не запрашивается.
- **Журнал.** Каждое срабатывание пишет `gateway.limit.triggered` с видом лимита, операцией и хешем посетителя, без адреса.

Счётчики живут в памяти: шлюз на сервере один. Перезапуск шлюза обнуляет счётчики, это приемлемо при дневном лимите бюджета в сервисе LLM, который остаётся последней защитой.

### 2. Резервные копии — логическая выгрузка средствами приложения

`philograph.ops.backup` выгружает все таблицы всех схем через SQLAlchemy в JSON Lines и складывает их в архив вместе с файловым хранилищем. Перед отправкой архив шифруется ключом `PHILOGRAPH_BACKUP_KEY` (Fernet), ключ хранится только в окружении сервера. Хранилище копий — каталог, смонтированный с внешнего хранилища, или S3-совместимое хранилище. Ротация: ежедневные за неделю, по одной на неделю за месяц, по одной на месяц за год.

Проверка восстановления:

1. разворачивает последнюю копию в отдельной базе;
2. применяет миграции всех схем;
3. загружает данные;
4. сравнивает версии миграций с источником;
5. проверяет, что основные таблицы не пусты.

Логическая выгрузка не зависит от версии `pg_dump`, одинаково работает с PostgreSQL и SQLite и проверяется тестами. При росте базы её стоит заменить на `pg_dump`.

Векторный и полнотекстовый индексы производные: их восстанавливает переиндексация, а поиск по словам работает и без векторов. Кэш LLM не копируется.

### 3. Оповещения — правила над состоянием

`philograph.ops.alerts` раз в минуту вычисляет правила:

- готовность сервисов;
- доля ответов 5xx шлюза;
- расход бюджета относительно лимита;
- возраст самой старой задачи очереди;
- результат последней копии и проверки.

У каждого правила есть состояние: при переходе в «сработало» отправляется одно сообщение, при переходе обратно — одно сообщение о восстановлении. Повторные срабатывания группируются. Канал — журнал или вебхук: Telegram или произвольный URL. Тексты собираются только из чисел и названий сервисов: вопросов и адресов посетителей в них нет.

### 4. Развёртывание

- **Внешний доступ.** `compose.prod.yaml` добавляет Caddy: HTTPS с автоматическим сертификатом и перенаправление с HTTP. Наружу открыты только порты 80 и 443, порт шлюза закрыт.
- **Перезапуск.** У всех сервисов `restart: unless-stopped`. Каждый процесс при старте пишет `service.started` с версией. Если предыдущий запуск не завершился штатно (остался маркер в `PHILOGRAPH_STATE_DIR`), он пишет и `service.restarted`.
- **Обновление** (`scripts/deploy.py update <версия>`): сначала одноразовый запуск миграций новой версией образа. Если миграции упали, обновление останавливается, а прежние контейнеры продолжают работать. Иначе сервисы перезапускаются с новой версией, а прежняя записывается для отката.
- **Откат** (`scripts/deploy.py rollback`) — одна команда, возвращает прежнюю версию. Миграции только добавляют: тест запрещает удаление и переименование столбцов и таблиц, поэтому прежний код работает с новой схемой.

## Risks / Trade-offs

- [Лимиты по адресу задевают читателей за одним NAT] → лимит частоты щедрый, лимиты платных операций считаются по адресу вместе с признаком браузера.
- [Токен страницы может получить и скрипт, если сначала загрузит страницу] → это защита от случайных и простых скриптов. От целенаправленного обхода защищает дневной лимит бюджета.
- [Логическая выгрузка медленнее `pg_dump` на больших базах] → для пилота база маленькая. Решение пересмотрим при росте.
