# Design

## Поток

```
вопрос ──► маршрутизатор (быстрая модель) ──► тип «карта», names
             │
             ▼
   онтологическое извлечение (assist.resolve): сущности вопроса с id и типами
             │
             ▼
   POST /v1/internal/assistant/map-options: кто из них на карте (вид, годы),
   коды фильтров, которые есть на карте, пределы раздела ── нет никого ──► «база знаний»
             │                                                          + пометка
             ▼
   подбор вида (быстрая модель, структурированный вывод) ──► черновик
             │
             ▼
   POST /v1/map/view (сервер знаний) ──► вид, href, dropped
             │
             ├──► поиск абзацев (цепочка «база знаний» по сущностям вида)
             ▼
   ответ (основная модель, 2–4 предложения со ссылками) + suggestion{kind:"map"}
```

Подбор вида идёт до ответа: ответ объясняет уже проверенный вид, а не черновик.

## Черновик вида (схема вывода модели)

Кандидаты передаются модели под ключами `c1`, `c2`… (вид, название, годы), а не под
внутренними идентификаторами: короткие ключи модель не путает, демо-ответ (`config/llm.demo.yaml`)
не зависит от сгенерированных id, а ассистент переводит ключи в id сам. Годы до н. э. — числами
с подписью («-383 (384 до н. э.)»).

```json
{
  "sel": "c1",                  // ключ одного кандидата или null
  "groups": ["c2"],             // ключи кандидатов-групп (направления и школы)
  "from": 1690, "to": 1800,     // годы; null — без ограничения
  "roles": ["philosopher"],     // коды person_role из реестра
  "kinds": ["work", "concept"], // виды трудов и идей карты
  "ekinds": ["political"],      // коды event_kind из реестра
  "verified": false,
  "lens": ["events"],           // свёрнутые страты
  "caption": "Эмпиристы XVIII века и их труды"
}
```

Модели передаются: вопрос, список кандидатов (ключ, вид, имя, годы — сущности вопроса, которые есть на карте), допустимые коды фильтров (коды реестра, встречающиеся на карте), пределы раздела (`range` карты). Сущностей вне списка модель выбрать не может: схема даёт `enum` по ключам кандидатов, для `groups` — только по ключам групп.

Сущности вопроса, которых на карте нет (понятие без датированного труда, место), ассистент сам добавляет в «не вошло» с причиной «нет на карте» — читатель может открыть их карточку.

## Проверка вида: `POST /api/knowledge/v1/map/view`

Вход — черновик (без `caption`) и `textbook`. Сервер берёт ту же карту, что `GET /v1/map` (с кэшем), и:

- `sel` — оставляет, если сущность есть на карте; иначе переносит в `dropped` (`not_on_map`) — ассистент может предложить карточку.
- `groups` — только группы карты (`kind` direction/school);
- `roles`, `ekinds` — только коды из реестра, встречающиеся на карте; `kinds` — из `work|concept|position|argument`;
- `from`/`to` — пересечение с `range` карты, `from < to`; пустое пересечение — оба отбрасываются;
- `lens` — коды страт; все четыре свёрнуть нельзя (как на клиенте);
- проверяет, что после фильтра на карте остаётся хоть одна персона или труд; иначе снимает фильтры по одному в порядке `ekinds → kinds → roles → годы → groups` и пишет снятое в `dropped` (`empty_result`).

Ответ: `{"view": {...}, "href": "/graph/<sel>?groups=…&via=assistant", "dropped": [{"field": "groups", "value": "e_…", "reason": "unknown"}], "shown": {"people": 12, "works": 30}}`. Параметры адреса — те же, что пишет клиент (`web/src/map/types.ts → writeState`); сервер и клиент сверяются общим тестом на набор пар «вид → адрес».

Лимит шлюза `map_view` (как `map`), без токена страницы.

## Клиент

- `AssistantPanel`: событие `suggestion` с `kind: "map"` (`href`, `caption`, `shown`) → кнопка «Открыть на карте» и подпись `caption` под ответом. Переход — `navigate(href)`.
- `MapPage`: параметр `via=assistant` → пометка «Вид подобран ассистентом» в панели карты, под поиском (`map/ViaNotice.tsx`): перечень «выбрано: Кант; направления и школы: …; годы: 1690–1800» строится из `MapState` и данных карты — выбор, группы и коды, которых на карте нет, не называются; текст модели и адреса не показывается. Кнопка «Сбросить вид» снимает фильтры, линзы и `via`, выбор оставляет. Пометка уходит при любой ручной смене фильтров и линз.
- Пометка — в панели, а не полосой над картой: на 1024×576 высота карты уже на пределе раскладки страт (~340 px), полоса дала бы прокрутку страницы; панель сама сворачивает разделы, чтобы поместиться.
- `via` — служебный параметр, как `fixture` и `recipe`: сохраняется при `replaceState` (после параметров вида, до `fixture`), в `writeState` не входит. При `via=assistant` текст поиска `q` из адреса не подставляется: ссылка ассистента его не несёт.
- Демо-стенд: фальшивый провайдер получил правила по шаблону и подстроке вопроса (`fake_rules`): «на карте» → тип «карта», «эмпирист» → вид «Эмпиризм, 1700–1800».

## Журнал

- `assistant.map_view.drafted` — число кандидатов, заполненные поля проверенного вида (без текста), сколько отброшено, `shown`, длительность.
- `assistant.map_view.failed` — причина: `ontology_unavailable`, `knowledge_unavailable`, `no_candidates`, `call_limit`, `draft_failed`, `empty_map`; ответ идёт по цепочке «база знаний» с пометкой `map_no_candidates` или `map_unavailable`.
- `knowledge.map_view.normalized` — `dropped` по причинам, `shown`, снятые при ослаблении поля (`relaxed`).

## Риски

- **Модель выбирает «не те» группы.** Вид — только фильтр поверх реальных данных; пометка на карте показывает применённое, «Сбросить вид» — в один щелчок.
- **Пустая карта после фильтров.** Сервер ослабляет фильтры по порядку и говорит, что снял.
- **Понятия.** Без режима «карта понятия» вид по понятию беден; подпись и ответ честно говорят, что показан автор и время.
