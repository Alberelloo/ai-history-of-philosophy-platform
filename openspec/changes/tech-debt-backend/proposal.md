# Proposal

## Why

Аудит 2026-11-19 (`docs/audit/2026-11-19-system-audit.md`, раздел 1 и таблица «Критично») нашёл долг бэкенда, сборки и CI, который мешает настоящему запуску:

- секрет посетителя молча откатывается на публично известный `"dev-secret"` (1.1, «Критично» 4);
- Python-зависимости и базовые образы не закреплены, прод-образ невоспроизводим (1.2, 1.3, «Критично» 5);
- настройки сервисов читаются из `os.environ` на уровне модулей без проверки; без `PHILOGRAPH_KNOWLEDGE_URL` ассистент молча работает без онтологии (1.5);
- CI дважды гоняет браузерные тесты, `checks` идёт до 18 минут (1.4, 1.15);
- OCR выбран в ADR-0001, но в образе его нет (1.8);
- еженедельной проверки обновлений каталога нет ни в compose, ни в runbook (раздел 2, строка ADR-0003);
- счётчики лимитов шлюза живут в памяти процесса, и это ограничение нигде не записано («Критично» 7);
- сервис знаний не входит в контракт независимости (1.12), сетевые ошибки глушатся без события (1.13), отладочные скрипты попадают в прод-образ (1.14).

## What Changes

- Каждый сервис и каждая команда читают настройки при старте через свой класс настроек (`platform.settings`). Ошибка — `SettingsError` и событие `service.settings.invalid`, сервис не стартует. Если нет необязательной зависимости, пишется событие `service.settings.optional_absent`: какой настройки нет и что без неё не работает.
- Секрет посетителя обязателен у шлюза и ассистента, значения по умолчанию в коде нет.
- Точки входа сервисов — фабрики `create()` (`uvicorn --factory`) вместо сборки приложения при импорте модуля по условию.
- Lock-файл `uv.lock`, установка по нему в Docker и CI; точные теги и digest базовых образов; actions по SHA; Dependabot.
- Образ с целями `runtime` (прод, без отладочных скриптов и демо) и `e2e` (плюс `seed_demo.py`, `crash_service.py`, `demo/`).
- CI: `checks` без e2e, прогон на PostgreSQL без `tests/web`, без мёртвого шага, ниже предел времени.
- Еженедельная проверка обновлений каталога: планировщик сервиса `ops` ставит задачу в очередь, исполнитель выполняет `check-updates` каталога.
- События `knowledge.portraits.download_failed` и `library.catalog.lookup_failed` вместо молчаливых `except`.
- `philograph.knowledge` в контракте независимости import-linter.
- ADR-0004 (лимиты шлюза в памяти одной реплики) и запись в ADR-0001 об OCR вне сервера.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `service-runtime` — проверка настроек при старте всеми сервисами, обязательный секрет посетителя, событие о необязательной зависимости.
- `observability` — сбой внешнего запроса с запасным путём пишет событие.
- `source-catalog` — еженедельная проверка обновлений по расписанию.
- `deployment` — воспроизводимая сборка образа, прод-образ без отладочных частей.

## Impact

- Код: `src/philograph/*/main.py`, `platform/settings.py`, `gateway/app.py`, `assistant/app.py`, `worker.py`, `ops/__main__.py`, CLI каталога и портретов.
- Запуск: команды в `compose.yaml` (`--factory`), `scripts/dev_stack.py`, `Dockerfile`, `compose.e2e.yaml`.
- CI: `.github/workflows/ci.yml`, `.github/dependabot.yml`.
- Документы: `docs/operations/runbook.md`, ADR-0001, ADR-0004.
- Тесты, которые собирают ассистента напрямую, передают секрет явно.
