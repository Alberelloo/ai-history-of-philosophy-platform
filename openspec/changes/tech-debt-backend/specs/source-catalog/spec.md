## ADDED Requirements

### Requirement: Еженедельная проверка обновлений

Проверка обновлений каталога (`check-updates`) SHALL запускаться сама раз в неделю, в ночное окно сервиса эксплуатации, без участия оператора. Планировщик SHALL ставить задачу в очередь, а выполнять её — исполнитель очереди. Перезапуск сервиса эксплуатации MUST NOT приводить к лишней проверке и MUST NOT пропускать плановую. За одну неделю SHALL ставиться не больше одной задачи проверки. Постановка пишет событие `ops.check_updates.scheduled` (`job_key`), выполнение — `library.catalog.check_updates.finished` (`checked` — сколько записей проверено, `outcomes` — сколько каких итогов).

#### Scenario: Прошла неделя

- **GIVEN** последняя проверка ставилась больше семи дней назад
- **WHEN** наступает ночное окно сервиса эксплуатации
- **THEN** в очереди появляется задача `library.catalog.check_updates`, в журнале — `ops.check_updates.scheduled`; исполнитель выполняет её, и в журнале — `library.catalog.check_updates.finished`

#### Scenario: Перезапуск в ту же неделю

- **GIVEN** проверка уже ставилась два дня назад
- **WHEN** сервис эксплуатации перезапускается и проходит ночное окно
- **THEN** новой задачи проверки нет, события `ops.check_updates.scheduled` нет

#### Scenario: Задача поставлена дважды

- **WHEN** постановка задачи проверки за одну неделю повторяется
- **THEN** в очереди одна задача на эту неделю
