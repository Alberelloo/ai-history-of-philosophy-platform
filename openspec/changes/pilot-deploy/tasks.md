# Tasks

Выделено из `pilot-launch` (3.1 ← add-production-readiness 1.8). Для каждой задачи указано, что нужно от владельца. Порядок действий описан в [runbook](../../../docs/operations/runbook.md).

## 1. Инфраструктура и первое развёртывание

- [ ] 1.1 Сервер с Docker и плагином `docker compose`, снаружи открыты только 80 и 443. **От владельца:** сервер (размер — по объёму файлов из `pilot-data` 1.1) и SSH-доступ.
- [ ] 1.2 Домен, DNS-запись на сервер, `PHILOGRAPH_DOMAIN`. **От владельца:** домен и доступ к DNS.
- [ ] 1.3 CDN с заголовком страны (`regional-access`, раздел runbook «Доступ только через CDN»):
  - CDN передаёт страну читателя заголовком (у Cloudflare — `CF-IPCountry`), имя заголовка задаётся в `PHILOGRAPH_REGION_HEADER`;
  - диапазоны IP CDN записаны в `PHILOGRAPH_CDN_IPS`, прямой доступ к серверу закрыт фаерволом;
  - CDN не кэширует `/api/*`.
  
  Проверка: запрос в обход CDN не получает текст закрытого источника, а правило оповещений «Регион читателя» молчит при обычном трафике. **От владельца:** учётная запись CDN и решение, какой CDN.
- [ ] 1.4 Внешнее хранилище копий: `PHILOGRAPH_BACKUP_DIR` (смонтированный rclone или sshfs) или `PHILOGRAPH_BACKUP_TARGET=s3://…`. `PHILOGRAPH_BACKUP_KEY` хранится в менеджере паролей отдельно от сервера. Проверка: ночная копия создана, еженедельная проверка восстановления прошла. **От владельца:** хранилище и место для ключа.
- [ ] 1.5 Канал оповещений: `PHILOGRAPH_ALERT_TELEGRAM_TOKEN` и `PHILOGRAPH_ALERT_TELEGRAM_CHAT` или `PHILOGRAPH_ALERT_WEBHOOK`. Проверка: пробное срабатывание доходит. **От владельца:** бот и чат или адрес webhook.
- [ ] 1.6 Ключи провайдеров моделей и эмбеддингов на сервере, бюджеты в `config/llm.yaml`. **От владельца:** ключи и месячный бюджет.
- [ ] 1.7 Первое развёртывание `python scripts/deploy.py update <версия>` по runbook (add-production-readiness 1.8; pilot-launch 3.1). Проверить HTTPS, готовность всех сервисов и загрузку каталога (`catalog sync`, `pilot-data` 1.1). Расхождения с runbook исправить в нём же. **От владельца:** всё из 1.1–1.6.

## 2. Плановая проверка обновлений

- [ ] 2.1 Завести изменение со спецификацией (дельта `source-catalog`, при необходимости `operational-alerts`): еженедельный `check-updates` из планировщика сервиса `ops` и правило оповещения о сбое (выбор — в `design.md`). Там же решить, кто применяет правило публикации: задача очереди или команда каталога. До его слияния на сервере временно работает cron по `docs/architecture/source-ingestion.md`, раздел «Плановый запуск». **От владельца:** ничего, кроме доступа к серверу для временного cron.
