# Proposal

Выделено из `pilot-launch` (группа 3 «Запуск»), 2026-11-19. Добавлена плановая проверка обновлений источников.

## Why

Развёртывание описано и проверено в CI: `scripts/deploy.py`, `compose.prod.yaml`, Caddy с HTTPS, копии, оповещения, [runbook](../../../docs/operations/runbook.md). Публичного сервера при этом нет.

С 06.11 к запуску добавились два требования:
- **CDN с заголовком страны** (`regional-access`, #39). Шлюз в продакшене доступен только через CDN, иначе ограничение показа источников по региону обходится. `scripts/deploy.py update` откажется выкладывать без `PHILOGRAPH_REGION_HEADER`.
- **Еженедельная проверка обновлений.** ADR-0003 и `docs/architecture/source-ingestion.md` обещают её раз в неделю. В коде есть команда `catalog check-updates` и задача очереди `library.check_updates`, но запускать их по расписанию нечему: ни сервис `ops`, ни `compose.prod.yaml`, ни runbook этого не делают.

## What Changes

- Сервер, домен, CDN с заголовком страны, внешнее хранилище копий, канал оповещений, ключи моделей на сервере.
- Первое развёртывание по runbook и проверка после него.
- Плановый еженедельный `check-updates`. Способ выбран в `design.md`: планировщик сервиса `ops`. Он меняет поведение, поэтому реализуется отдельным изменением со спецификацией.

## Capabilities

### New Capabilities

Нет. Развёртывание, копии, оповещения и регион уже описаны в `deployment`, `backup-and-recovery`, `operational-alerts` и `regional-access`. Плановая проверка обновлений пойдёт отдельным изменением с дельтой `source-catalog` (задача 2.1).

### Modified Capabilities

Нет.

## Impact

- Инфраструктура: сервер, DNS, CDN, хранилище копий, Telegram или webhook.
- Секреты на сервере: `.env` по `.env.example`, ключи моделей.
- Документы: в `docs/operations/runbook.md` попадает то, что выяснится при первом развёртывании.
- Зависит от `pilot-data` 1.1: без загруженных источников сайт откроется пустым.
