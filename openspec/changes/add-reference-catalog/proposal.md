# Proposal

## Why

В онтологии у Lead'а уже 700+ сущностей и 360+ утверждений, но читатель попадает к ним только из упоминаний в тексте главы и с карты раздела. Нет места, где можно спросить «а кто вообще есть в базе», найти философа или понятие по части названия, отобрать «все события Просвещения» или «все понятия, о которых говорит мой учебник». Пункт боковой панели «Справочник» ведёт на заглушку `/soon/reference` (сценарии С2, С6 в `docs/product/vision.md`).

Сейчас у сервиса знаний есть только `GET /v1/entities?name=` — точный поиск по нормализованному названию, без списка, фильтров, пагинации и счётчиков. Это годится для разрешения имени, но не для каталога.

## What Changes

- **Новый эндпоинт** `GET /api/knowledge/v1/catalog`: список сущностей онтологии с поиском по части любого названия (русского, английского, вариантов), фильтрами по типу, эпохе и разделу (учебнику-области), счётчиками по типам и эпохам (фасеты), сортировкой и постраничной выдачей. Без вызова модели, из сохранённых данных.
- **Принадлежность к эпохе** вычисляется в одном месте сервиса знаний (`knowledge/epochs.py`): явное «относится к эпохе» важнее вычисленного по датам; по датам — середина жизни персоны или год труда/события внутри датировки эпохи. Справочник фильтрует по ней; изменения 2.2 и 2.3 берут её же.
- **Общий снимок данных онтологии** (`knowledge/snapshot.py`): чтение действующих сущностей, названий и утверждений и отпечаток базы выносятся из `map.py`, карта и справочник читают одно и то же правило «действующее утверждение». Поведение карты не меняется.
- **Старый контракт** `GET /v1/entities?name=` не меняется.
- **Страница «Справочник»** `/reference` вместо заглушки: строка поиска, переключатели типов со счётчиками, выбор эпохи и раздела, список результатов, «Показать ещё», переход в карточку (правая панель) и на карту. Состояние — в адресе. Старая закладка `/soon/reference` заменяется на `/reference`.
- **Боковая панель:** у «Справочника» нет метки «скоро».
- **Журнал:** события `knowledge.catalog.listed` и `knowledge.snapshot.built`.
- **Демо-данные:** `scripts/seed_demo.py` получает несколько сущностей разных типов с явной принадлежностью к эпохе и с вариантами названий, чтобы справочник был не пустым в демо и e2e.

## Capabilities

### New Capabilities

- `entity-catalog`: справочник сущностей — список, поиск, фильтры, счётчики, пагинация, закрытые источники, страница `/reference`.
- `epochs`: здесь — только требование «Принадлежность к эпохе» (общее правило, на которое опираются справочник, карта и контекст). Остальные требования к эпохам добавляет изменение `add-epochs`.

### Modified Capabilities

- `visual-design`: изменено «Разделы в разработке» — «Справочник» без метки «скоро», ведёт на `/reference`, старая закладка заменяется.
- `abuse-protection`: изменено «Бесплатное без ограничений платных» — справочник не зависит от лимитов платных операций.

## Impact

- Сервис знаний: новые `knowledge/catalog.py`, `knowledge/epochs.py`, `knowledge/snapshot.py`; `knowledge/map.py` переходит на общий снимок (рефакторинг без изменения поведения); маршрут в `knowledge/app.py`; сборка в `knowledge/main.py`.
- Шлюз: правок нет — `/api/knowledge/v1/catalog` проходит общим прокси и общим лимитом частоты; в `PAID` не добавляется (решение в design.md).
- Клиент: новые `web/src/reference/ReferencePage.tsx`, `web/src/reference/api.ts`, `web/src/reference/types.ts`, стили `web/src/styles/reference.css`; `App.tsx` (маршрут `/reference`, замена `/soon/reference`), `Sidebar.tsx` (`LIVE.reference`), `SoonPage.tsx` (без изменений списка), строки `i18n/ru.ts`, `i18n/en.ts`.
- Тесты: `tests/knowledge/test_catalog.py`, `tests/knowledge/test_epochs_membership.py`, `tests/web/test_reference.py`, дополнение `tests/web` для `/soon/reference`; прогон `tests/knowledge/test_map.py` как защита рефакторинга.
- Демо: `scripts/seed_demo.py` (несколько записей, без изменения существующих карточек Канта и Юма).
- `openspec/traceability.yaml`: `entity-catalog` и `epochs` добавляются в `enforce` в конце реализации.
- Файлы Lead'а (`config/llm.yaml`, `scripts/dev_stack.py`, `platform/queue.py`, `knowledge/filling.py`, `prompts/__init__.py`, `sources/catalog.yaml`) не меняются.

## Вне объёма

- Полнотекстовый поиск по описаниям и абзацам (это `paragraph-search`); здесь только названия.
- Морфология и опечатки («Канта» → «Кант», «Юмм»): поиск по подстроке нормализованного названия. Нечёткий поиск — отдельным изменением, если понадобится.
- Правка сущностей из справочника, массовые операции — это страница проверки оператора.
- Фильтр «Эпоха» на карте и страница «Эпохи» — изменение `add-epochs`; исторический контекст — `add-epoch-context`.
- Сущности типа `source` (книги библиотеки) в справочник не попадают: у них своя страница библиотеки.

## Решения, принятые без владельца

Владелец в обсуждении не участвует (ТЗ, «Процесс», п. 1). Решения и альтернативы — в design.md, «Выбор решения»; кратко:

1. **Новый маршрут `/v1/catalog`, а не перегрузка `/v1/entities`.** Один маршрут с двумя формами ответа (список при `name`, страница при её отсутствии) ломает типизацию клиентов и тесты старого контракта. Альтернатива «`/v1/entities` без `name` отдаёт страницу» отвергнута.
2. **Справочник не платная операция.** Модель не вызывается, ответ ограничен (≤ 60 записей на страницу), снимок данных кэшируется; общего лимита частоты шлюза (20 запросов/с, всплеск 60) достаточно. Альтернатива «квота как у карты» отвергнута: она нужна карте, которая отдаёт всю область целиком.
3. **Поиск по подстроке нормализованных названий в снимке в памяти**, а не SQL `LIKE` на каждый запрос и не отдельный поисковый индекс: фильтр по эпохе вычисляется по датам, в SQL его не выразить переносимо между SQLite и PostgreSQL. При 10× сущностей снимок ~70 тыс. записей — десятки мегабайт и десятки миллисекунд на фильтр; путь дальше (PostgreSQL `pg_trgm`) описан в рисках.
4. **Справочнику допустима устарелость снимка до 15 секунд** (настройка), карте — нет (как сейчас). Во время фонового извлечения отпечаток меняется постоянно; без окна каждая страница справочника пересобирала бы снимок.
5. **Закрытые источники:** сущности и их названия остаются видимыми (как в `regional-access`), но фильтр «Раздел» по учебнику, закрытому для региона, ничего не раскрывает: ответ пустой с пометкой `textbook_closed`.
6. **Принадлежность к эпохе определяется здесь, в `add-reference-catalog`,** потому что фильтр по эпохе нужен уже справочнику, а правило должно жить в одном месте; `add-epochs` его переиспользует.
