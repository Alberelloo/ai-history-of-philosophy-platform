# Proposal

## Why

Разбор онтологии стенда Lead'а от 2026-11-25 (задание владельца `PHILO-SPEC-ONTOLOGY.md`, П1–П3):

- **П1.** 1425 из 1935 названий (74%) на латинице: понятия 838/923, позиции 171/295, персоны 52/85, термины 64/83. Промпт `ontology.extract` не задаёт язык названий. Кроме того, `Filling._resolve` записывает любое название с языком `ru`, даже латинское.
- **П2.** В справочнике есть номера разделов (`3.1`, `20.1`, `23.4.3` — 7 штук), фразы и пустая строка. Ни промпт, ни сервер не проверяют, что название — имя или термин.
- **П3.** Датированы 10 сущностей из 1889. Промпт не просит дат, а в схеме вывода нет места для датировки.

## What Changes

- **Названия на языке источника** (новая возможность `entity-naming`):
  - Модель возвращает для каждой упомянутой сущности русское название, английское и оригинальное написание. Делает она это в новом необязательном массиве `entities` схемы вывода.
  - Сервер выбирает основное название: русское, если оно есть и прошло проверку. Остальные написания идут вариантами со своим языком.
  - Язык названия код определяет по письменности (кириллица → `ru`, латиница → `en`, греческий → `el`), а не по тому, что сказала модель.
  - Сущность, у которой есть только английское название, получает русское основное название, а прежнее становится вариантом `en`. Новая сущность при этом не создаётся, ссылки сохраняются.
- **Проверка названий на сервере**, в `Entities.create` и при записи основного названия. Поэтому она действует для любого пути: извлечение, ядро, импорт, ручной ввод.
  - Отклоняются номер, пустое название, предложение, слово из стоп-списка, а для персоны — не имя собственное.
  - Стоп-список и пределы — данные в `knowledge/naming_rules.yaml`, а не код.
  - Каждый отказ пишет событие `knowledge.entity.rejected` (`type`, `label`, `reason`).
- **Датировка при извлечении** (новая возможность `entity-dating`, требование «Извлечение дат»):
  - У элемента `entities` есть поле `dating` с текстом даты, номером абзаца и цитатой.
  - Сервер разбирает дату своим `dates.parse` и сверяет цитату с абзацем. Каждое число года из даты должно встречаться в цитате.
  - Для персоны записывается `lifespan`, для остальных — `dating`. Значение попадает в `primary.dates`.
- **Промпт** `ontology.extract` дополняется правилами языка, валидности и дат. Добавляется поле данных `language` — язык фрагмента по полю `lang` его абзацев. Правка промпта и точки вызова в `filling.py` минимальные, логика — в новых модулях (решение ведущего О3).
- **Изменённые требования `ontology-extraction`:** «Структурированный вывод по реестру» (массив `entities`, поле `dating`) и «Нормализация сущностей» (привязка по всем написаниям, русское основное название).
- **Журнал:**
  - `knowledge.entity.rejected` — новое;
  - `knowledge.entity.renamed` — новое: основное название сменилось;
  - отказ датировки — существующее `knowledge.extraction.dropped` с причиной `dating:<код>`.

## Out of scope

- Существующие данные. Их перевод, чистку и замер А1–А8 делает изменение `migrate-ontology-quality`. Это изменение действует только на новые записи.
- Даты из Wikidata — изменение `add-wikidata-life-dates`.
- Критерии персоны сверх правила 4 и слияние вариантов — изменение `improve-person-quality`. Здесь только привязка одного элемента `entities` к одной существующей сущности.
- `config/llm.yaml`, `dev_stack.py`, `queue.py`, `sources/catalog.yaml` не меняются.
- Клиент не меняется: справочник и карточки уже показывают основное русское название (`snapshot.labels`).

## Вопросы владельцу (решены разработчиком, записаны в progress.md)

1. **Английские источники** (34 из 441). Владелец пишет «на языке источника, для русских учебников — по-русски». Решение: основное название всегда русское, если модель дала принятое русское написание и оно прошло проверку. Иначе основное — название на языке источника. Причина: интерфейс русский, А1 считается по всем сущностям.
2. **Пятая причина отказа `empty`** (пустое название или только пробелы и знаки). В перечне владельца её нет. Пустая строка из П2 под «номер» не подходит.
3. **Пределы предложения** (6 слов, 80 знаков) для произведений и событий слишком тесны: «Выход первого тома «Энциклопедии»», полные заглавия трудов. Решение: пределы задаются по типам в данных. По умолчанию 6/80, для `work`, `event`, `idea_event`, `phenomenon` — 12/160. Источники библиотеки (`source`) не проверяются: их названия — данные каталога.
4. **Порядок причин**: `empty` → `number` → `sentence` → `not_a_name` (только персоны) → `stopword`. При таком порядке «blind mathematician» даёт `not_a_name`, как в сценарии владельца, хотя это слово есть и в стоп-списке.
5. **Даты в астрономическом счёте.** Владелец записал `{from: 1724, to: 1804, precision: "year"}`. В системе `primary.dates` хранит четыре границы, а «от» и «до» получаются через `dates.span`. В сценариях наблюдаемое значение: `span(primary.dates)` и `precision`.
