## MODIFIED Requirements

### Requirement: Даты эпох из Wikidata

Даты эпох SHALL дополняться из Wikidata командой оператора `apply` с внедряемой функцией загрузки. Для эпохи SHALL использоваться только подтверждённый человеком идентификатор Wikidata: внешний идентификатор сущности или поле `wikidata` манифеста эпох; режим `--linked` дополнительно обходит все эпохи базы с внешним идентификатором Wikidata. Датировка SHALL строиться из «времени начала» (P580) и «времени окончания» (P582), а если их нет — из «даты основания» (P571) и «даты прекращения» (P576), по правилу требования «Доступ к Wikidata». Записанное SHALL получать статус «по источникам», атрибуцию «Wikidata» со ссылкой на запись, происхождение «импорт» с идентификатором записи и свойствами, а сущность — внешний идентификатор Wikidata, если его не было. Если у эпохи уже есть действующая датировка, команда MUST NOT записывать новую. Режим проверки (`--dry-run`) MUST NOT менять базу. Связи влияния из Wikidata MUST NOT импортироваться. Повторный запуск с тем же манифестом и теми же ответами MUST NOT создавать новых утверждений и сущностей.

Каждая эпоха SHALL записываться событием `knowledge.epoch_dates.checked` с полями `epoch_id` (может быть `null`, если эпоха не найдена), `qid` (может быть `null`), `result`:

| `result` | Когда | Запись |
|---|---|---|
| `added` | датировки не было, Wikidata дала начало и конец | `dating` (+ внешний идентификатор) |
| `created` | эпохи не было — заведена из манифеста и получила датировку | сущность, названия, внешний идентификатор, `dating` |
| `unchanged` | действующая датировка совпадает по четырём границам | нет |
| `conflict` | действующая датировка отличается | нет; обе — в отчёте |
| `no_dates` | нет начала или конца (в т. ч. неразбираемые значения) | нет (эпоха из манифеста не заводится) |
| `no_qid` | у эпохи нет подтверждённого идентификатора | нет, загрузка не вызывается |
| `fetch_failed` | загрузка сообщила сбой | нет |
| `ambiguous` | в онтологии несколько эпох с этим названием | нет |
| `duplicate_qid` | идентификатор уже у другой сущности или у эпохи уже другой идентификатор Wikidata | нет |
| `invalid_name` | эпохи не было, а её название из манифеста не прошло правило названий (`entity-naming`); событие `knowledge.entity.rejected` | нет (эпоха не заводится) |

Запуск SHALL записываться событием `knowledge.epoch_dates.run` с полями `mode` (`apply` | `dry_run`), `checked` (число эпох), `added`, `created`, `conflicts`, `skipped` (число эпох с любым другим `result`); `checked = added + created + conflicts + skipped`. В режиме проверки `result` — тот, что был бы записан.

#### Scenario: Дата из Wikidata

- **GIVEN** эпоха «Просвещение» без датировки с внешним идентификатором `wikidata=Q12539`; запись (фикстура) содержит P580 `+1685-00-00T00:00:00Z` и P582 `+1815-00-00T00:00:00Z`, оба с точностью 9
- **WHEN** оператор запускает `apply --linked`
- **THEN** у «Просвещения» одно утверждение `dating` 1685–1815 со статусом «по источникам», атрибуцией `wikidata:Q12539` со ссылкой `https://www.wikidata.org/wiki/Q12539`; в журнале `knowledge.epoch_dates.checked` с `result=added` и `knowledge.epoch_dates.run` с `mode=apply`, `checked=1`, `added=1`, `skipped=0`

#### Scenario: Запасные свойства

- **GIVEN** у записи нет P580/P582, есть P571 `+1543` и P576 `+1687` (точность 9)
- **WHEN** оператор запускает `apply`
- **THEN** датировка 1543–1687, в происхождении свойства `["P571","P576"]`

#### Scenario: Датировка уже есть

- **GIVEN** у «Научной революции» датировка 1543–1687 из текста, а Wikidata даёт 1550–1700
- **WHEN** оператор запускает `apply`
- **THEN** у эпохи по-прежнему одно утверждение `dating` (1543–1687); `result=conflict`; в отчёте обе датировки; `run.conflicts=1`

#### Scenario: Повторный запуск

- **WHEN** после «Дата из Wikidata» оператор запускает `apply --linked` второй раз
- **THEN** число утверждений и сущностей не изменилось, `result=unchanged`, `run.skipped=1`

#### Scenario: Проверка без записи

- **WHEN** оператор запускает `apply --linked --dry-run` на данных «Дата из Wikidata»
- **THEN** число строк во всех таблицах онтологии не изменилось; отчёт показывает `added`; в журнале `knowledge.epoch_dates.run` с `mode=dry_run`, `added=1` и ни одного `knowledge.statement.created`

#### Scenario: Без QID

- **GIVEN** у эпохи «Барокко» нет внешнего идентификатора и в манифесте `wikidata: null`
- **WHEN** оператор запускает `apply`
- **THEN** функция загрузки вызвана 0 раз; `result=no_qid`

#### Scenario: Сбой загрузки и одинаковый QID

- **GIVEN** в манифесте три эпохи: загрузка первой сообщает сбой; QID второй уже записан у персоны; третья в порядке
- **WHEN** оператор запускает `apply`
- **THEN** `result` соответственно `fetch_failed`, `duplicate_qid`, `added`; `run.checked=3`, `added=1`, `skipped=2`

#### Scenario: Название эпохи не прошло проверку

- **GIVEN** в манифесте эпоха «20.1» с подтверждённым QID, такой эпохи в онтологии нет
- **WHEN** оператор запускает `apply`
- **THEN** `result=invalid_name`, эпоха не заведена, запуск продолжается со следующей записью; эпоха входит в `skipped`
- **AND** в журнале `knowledge.entity.rejected` с `type="epoch"`, `reason="number"` и `knowledge.epoch_dates.checked` с `result="invalid_name"`
