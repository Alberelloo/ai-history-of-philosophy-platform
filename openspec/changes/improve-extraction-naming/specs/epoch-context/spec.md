## MODIFIED Requirements

### Requirement: Контекстные события из Wikidata

Контекстные события эпохи SHALL подбираться из Wikidata командой оператора через общий модуль доступа к Wikidata (требование «Доступ к Wikidata»): для эпохи с подтверждённым идентификатором берутся её «значимые события» (P793); у каждого — дата (момент P585, иначе начало и конец P580/P582), вид события по таблице соответствия классов (P31) из данных модуля (класс не из таблицы — вид не записывается) и первое место (P276). Команда `harvest` SHALL записывать кандидатов в манифест контекста с решением `pending`; кандидат без даты MUST NOT предлагаться; повторный `harvest` MUST NOT менять решения и поля, заполненные человеком. Команда `apply` SHALL записывать в базу только кандидатов с решением `accepted`: событие с внешним идентификатором Wikidata (новое или найденное по идентификатору), датировку, вид события (если есть), принадлежность к эпохе (уточнитель «основание принадлежности» — `historians`) и место (найденное по идентификатору или новое). Все записанные утверждения SHALL получать статус «по источникам», атрибуцию «Wikidata» со ссылкой на запись и происхождение «импорт». Связи «стимулировало», механизм и связи влияния из Wikidata MUST NOT записываться. Режим проверки (`--dry-run`) MUST NOT менять базу. Повторный `apply` MUST NOT создавать новых сущностей и утверждений.

События журнала: `knowledge.context_import.harvested` (`epochs`, `candidates`); `knowledge.context_import.checked` (`qid`, `result`) на каждый кандидат `apply`; `knowledge.context_import.run` (`mode` — `apply` | `dry_run`, `created`, `statements`, `places_created`, `skipped`).

| `result` | Когда |
|---|---|
| `created` | принятый кандидат записан (событие новое или найдено, утверждения добавлены) |
| `exists` | принятый кандидат уже записан полностью — новых строк нет |
| `pending` | решение `pending` — пропущен |
| `rejected` | решение `rejected` — пропущен |
| `no_date` | у принятого кандидата дата не разбирается при повторной загрузке — пропущен |
| `fetch_failed` | загрузка сообщила сбой — пропущен |
| `duplicate_qid` | идентификатор события или места уже принадлежит сущности другого типа — ничего не записано, пропущен |
| `invalid_name` | название нового события или нового места не прошло правило названий (`entity-naming`) — ничего не записано, пропущен; событие `knowledge.entity.rejected` |

#### Scenario: Кандидаты в манифест

- **GIVEN** у «Просвещения» подтверждённый QID; запись (фикстура) содержит P793 с тремя событиями: революция с P585 1789, классом из таблицы («революция» → `political`) и P276 «Париж»; событие с P585 1755 и классом не из таблицы; событие без даты
- **WHEN** оператор запускает `harvest`
- **THEN** в манифесте у «Просвещения» два кандидата с `decision: pending`: революция (`kind: political`, место «Париж») и событие 1755 (`kind: null`); события без даты нет; число строк в таблицах онтологии не изменилось; в журнале `knowledge.context_import.harvested` с `epochs=1`, `candidates=2`

#### Scenario: Принятый кандидат

- **GIVEN** кандидат «Французская революция» (1789, `political`, место «Париж» — новое) с `decision: accepted`
- **WHEN** оператор запускает `apply`
- **THEN** заведены событие «Французская революция» и место «Париж» с внешними идентификаторами; у события четыре утверждения — `dating` (1789), `event_kind=political`, `belongs_to_epoch` → «Просвещение» (`membership_basis=historians`), `happened_in` → «Париж» — все со статусом «по источникам» и атрибуцией Wikidata; утверждений `stimulated` 0; в журнале `knowledge.context_import.checked` с `result="created"` и `knowledge.context_import.run` с `mode="apply"`, `created=1`, `statements=4`, `places_created=1`, `skipped=0`

#### Scenario: Ожидающий и отклонённый

- **GIVEN** кандидаты с `decision: pending` и `decision: rejected`
- **WHEN** оператор запускает `apply`
- **THEN** ни один не записан; в журнале `result="pending"` и `result="rejected"`, `run.skipped=2`

#### Scenario: Повторный запуск и проверка

- **WHEN** после «Принятого кандидата» оператор запускает `apply` второй раз, затем `apply --dry-run` с новым принятым кандидатом
- **THEN** при втором запуске новых строк нет, `result="exists"`, `run.created=0`, `statements=0`; при `--dry-run` число строк во всех таблицах онтологии не изменилось, `run.mode="dry_run"`, `created=1`

#### Scenario: Повторный подбор не сбрасывает решения

- **GIVEN** у кандидата революции `decision: accepted`
- **WHEN** оператор снова запускает `harvest`
- **THEN** у кандидата по-прежнему `decision: accepted`, кандидаты не задвоены

#### Scenario: Название события не прошло проверку

- **GIVEN** принятый кандидат «Французская революция», у которого в манифесте подпись `ru` исправлена на «your Lordship»; события и места «Париж» в онтологии нет
- **WHEN** оператор запускает `apply`
- **THEN** у кандидата `result=invalid_name`; не созданы ни событие, ни место, ни утверждения; прочие кандидаты обработаны
- **AND** в журнале `knowledge.entity.rejected` с `type="event"`, `reason="stopword"` и `knowledge.context_import.checked` с `result="invalid_name"`
