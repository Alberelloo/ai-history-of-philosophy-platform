# Кейсы: portrait-sourcing

Каталог изменения: `openspec/changes/portrait-sourcing/`. Покрывает новую возможность
`entity-portraits` и изменённое требование `entity-cards` «Портреты в карточке».

Требования — `specs/entity-portraits/spec.md`, `specs/entity-cards/spec.md`; решения — `design.md`,
`proposal.md` («Решения владельца», 2026-11-13).

## Требования

| REQ | Источник | Формулировка (SHALL) |
| --- | --- | --- |
| R1 | entity-portraits / «Отбор портретов персоны» | Портреты собираются только для персон с идентификатором Wikidata; источник — Wikidata `P18` и Commons; до 7 разных, первое главное; дубли (разрешения, кадрирования, гравюра с той же композиции) считаются одним |
| R2 | entity-portraits / «Лицензии и атрибуция» | Сохраняются только PD, CC0, CC BY, CC BY-SA; хранятся автор, год (если есть), код лицензии, её адрес и ссылка на страницу источника; без распознанной лицензии или ссылки изображение не сохраняется; NC и ND не принимаются |
| R3 | entity-portraits / «Хранение и раздача изображений» | Файлы — в `FileStore`, сведения и порядок — в базе знаний; раздаёт сайт (`/api/knowledge/v1/portraits/{id}`), без горячих ссылок; скрытое и черновики не отдаются ни в карточке, ни по адресу (404) |
| R4 | entity-portraits / «Проверка оператором» | Собранное попадает черновиками; читателю отдаются только подтверждённые; оператор подтверждает, скрывает, назначает главным; действия в журнале; «главное» меняет порядок без потери остальных |
| R5 | entity-portraits / «Ответ карточки с портретами» | `portraits` — до 7 подтверждённых и видимых, главное первым, поля `url`, `width`, `height`, `author`, `year`, `license`, `license_url`, `source_url`; без подтверждённых — пустой список; регион и внешняя обработка не применяются |
| R6 | entity-cards / «Портреты в карточке» | Полная карточка — до 7 разных портретов галереей со счётчиком, точками, листанием и подписью автора, года, лицензии и ссылки на источник; окно у упоминания — одно главное изображение без счётчика; без изображений — монограмма и «Изображений нет» |

## Как проверять

- Сервер: `.venv/Scripts/python.exe -m pytest -q tests/knowledge -p no:cacheprovider`,
  затем всё вместе `-m "not e2e"`.
- Шлюз: `tests/gateway/test_region_scope.py` и новая проверка раздачи через шлюз.
- Клиент: сборка `cd web; npm run build` и `pytest -q tests/web/test_reader_cards.py`
  (на этой машине `TMP`/`TEMP` внутри репозитория, иначе Chromium падает с `EPERM mkdtemp`).
- Данные: `python -m philograph.knowledge.portraits_source validate` (без сети), затем `harvest`
  и `sync` на стенде; очередь проверки — в операторском интерфейсе.
- Визуальные: снимки S1 (окно у упоминания) и S4 (полная карточка) в обеих темах.
