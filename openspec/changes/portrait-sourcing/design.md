# Design

## Context

Карточка персоны уже умеет показывать портреты: клиент `PortraitGallery` листает до семи изображений, `Portrait` рисует медальон, сервер отдаёт `portraits: []`. Задача — наполнить это поле и научить медальон показывать изображение, не меняя поведение без портретов.

Что известно из кода и документов:
- у сущностей есть `external_ids` с системой `wikidata` (`knowledge/entities.py`), у персон онтологии он заполняется при наполнении;
- в каталоге источников уже есть `Fetcher` с кешем и `Wikidata`-адаптер — берём их как образец загрузки и кеширования;
- `FileStore` платформы (`platform/files.py`) хранит файлы по sha256; `Pillow` уже в зависимостях (нужен OCR);
- в сервисе знаний есть проверка оператором (`_review_routes`, `require(auth, ...)`, `ActionLog`) — новый модуль проверки повторяет этот порядок;
- дуотон медальона уже сделан CSS-ом (`web/src/styles/components.css`, `mix-blend-mode: lighten`), галерея показывает исходные цвета;
- шлюз проксирует `/api/knowledge/*` в сервис знаний, отдельный маршрут для изображений не нужен.

## Decisions

### 1. Отбор изображений

Автоматический сбор для персон с `external_ids.wikidata`:

1. Wikidata `Special:EntityData/{qid}.json` → свойство `P18` (основное изображение).
2. Если набрано меньше семи, Wikimedia Commons: файлы из `P18` и из категории Commons, привязанной к персоне (`P373`), — до лимита.
3. Для каждого файла — `imageinfo` с `iiurlwidth=480`: эскиз (`thumburl`), ширина/высота, MIME, `extmetadata` (`Artist`, `DateTimeOriginal`, `LicenseShortName`, `LicenseUrl`, `DescriptionUrl`). Скачивается **эскиз**, а не оригинал (у Юма и Витгенштейна оригиналы 9–22 МБ); жёсткий предел — 8 МБ на файл, больше — отказ с причиной `too-large`. MIME определяется по сигнатуре скачанных байтов, а не по расширению (у Локка PNG).
4. Дубли: перцептивный хеш (dHash 64 бита по уменьшенной до 9×8 серой картинке) — расстояние Хэмминга ≤ 6 считается тем же изображением. Сравнение идёт по всем кандидатам персоны и по уже сохранённым файлам.
5. Порядок: `P18` первым (главное), дальше — по убыванию размера; дополнительные файлы вне `P18` (`--extra "QID=File:..."`) нужны, когда основное изображение Wikidata мало или плохого качества. Категория Commons по умолчанию **не** подмешивается: в ней бывают посторонние фотографии (у Канта — отпечаток ладони и здание); добор из категории включается только явным `--category-limit`. Изображение мельче 400 px по длинной стороне отклоняется (`too-small`): в галерее оно было бы мыльным.

Сеть ходит только скрипт отбора (как каталог источников): сервис во время работы читателя ничего не качает.

### 2. Лицензии и атрибуция

Допустимые коды: `pd`, `cc0`, `cc-by-*`, `cc-by-sa-*`. Всё остальное (`nc`, `nd`, нераспознанное, пусто) отбрасывается на этапе отбора. Атрибуция:
- `author` — из `Artist`, очищенный от HTML и лишних пробелов;
- `year` — свободная строка «как её даёт источник» (`1790`, `after 330 BC`, `2009 (фото)`); не приводим к числу и не интерпретируем, это подпись, а не дата жизни;
- `license` — нормализованный код, `license_url` — со страницы файла, если Commons его отдаёт (у общественного достояния часто нет — тогда `null`, а в подписи лицензия без ссылки);
- `source_url` — `DescriptionUrl` (страница файла на Commons);
- `origin` — `wikidata:{qid}` или `commons:{File:...}` для трассировки;
- `mime` — по сигнатуре байтов; `width`/`height` — размер сохранённого файла (эскиз до 480 px по длинной стороне; медальон 56–112 px, галерея 400 px).

Без лицензии из списка или без `DescriptionUrl` кандидат не сохраняется. Решение фиксируется в манифесте (см. п. 3), чтобы отказ был виден и повторяем.

### 3. Хранение и данные

- БД знаний, миграция 7: таблица `portraits` — `id`, `entity_id`, `file_id` (sha256 в `FileStore`), `width`, `height`, `mime`, `author`, `year`, `license`, `license_url`, `source_url`, `origin`, `phash`, `position` (0 — главное), `status` (`draft` | `approved`), `hidden` (bool), `created_at`. Уникальность: `(entity_id, phash)`.
- Файлы — в `FileStore` (`PHILOGRAPH_FILES_ROOT`, тот же корень, что у библиотеки).
- Манифест — `sources/portraits.yaml`: персоны (`name`, `wikidata`, `entity_id` не хранится — связь по внешнему ключу), кандидаты с атрибуцией и решением (`accepted` / `rejected` + причина). Манифест коммитится, файлы — нет: их приносит `sync`.
- CLI `python -m philograph.knowledge.portraits_source`:
  - `harvest --persons Q1,Q2 [--extra "QID=File:..."]` — собрать кандидатов в манифест (сеть);
  - `sync --root <каталог FileStore>` — скачать принятые файлы в `FileStore` и завести строки `portraits` черновиками (идемпотентно); персона без сущности в онтологии пропускается с предупреждением;
  - `validate` — проверить манифест без сети: лицензии, обязательные поля, дубли, до семи на персону;
  - `list` — что собрано и сколько ждёт проверки.

Пилот: 13 персон (15 из исследования минус Рассел и Гуссерль — провенанс под сомнением, см. `qa/pilot-portraits.md`), затем расширение. Размер файлов ограничиваем эскизом и лимитом 8 МБ; в репозиторий изображения не попадают.

### 4. Раздача изображений

`GET /api/knowledge/v1/portraits/{id}` в сервисе знаний: отдаёт байты из `FileStore` с `Content-Type` по расширению, `ETag` = `file_id`, `Cache-Control: public, max-age=31536000, immutable`. Скрытые и черновики — 404. Так как шлюз уже проксирует `/api/knowledge/*`, отдельного маршрута в шлюзе не нужно; `url` в карточке — этот адрес.

### 5. Проверка оператором

- `status` и `hidden` — две независимые вещи: черновик не виден, подтверждённое можно скрыть.
- Маршруты под существующей проверкой оператора, право `review_portraits`:
  - `GET /v1/review/portraits?status=draft` — очередь с подписью, лицензией и ссылкой;
  - `POST /v1/review/portraits/{id}` — `approve`, `hide`, `show`, `main`;
  - каждое действие — `ActionLog` и событие `knowledge.portrait.*`.
- «Сделать главным» — перестановка `position`: выбранному 0, остальным — прежний порядок со сдвигом; без потери изображений.

### 6. Ответ карточки

`Cards._row`/`card`: `portraits` — только `status = approved` и `hidden = false`, `order by position`, максимум 7, каждое: `url`, `width`, `height`, `author`, `year`, `license`, `license_url`, `source_url`. Регион и внешняя обработка к портретам не применяются: это факты о персоне, а не текст источника. Если изображений нет — пустой список (текущее поведение).

### 7. Клиент

- `Portrait` принимает необязательный `portrait` и рисует `<img>` в круге (дуотон — существующим CSS), иначе монограмму; `alt` — имя персоны.
- `CardPopup` передаёт главный портрет из ответа карточки; `FullCard` уже передаёт список в `PortraitGallery`.
- Подпись галереи: `автор, год` + лицензия ссылкой на `license_url` + ссылка «Источник» на `source_url`; новые строки — в `i18n` (ru/en).
- T11 и T16 дополняются: медальон с изображением, подпись с лицензией и ссылкой, отсутствие изображений.

### 8. Риски и как их закрываем

| Риск | Что делаем |
|---|---|
| Неверная персона на портрете | обязательное подтверждение оператором до показа; скрытие в любой момент |
| Несвободная лицензия попала в набор | `validate` + отказ на этапе отбора; тест на NC/ND и на отсутствие лицензии |
| Дубли (одна картина в разных файлах) | dHash и уникальность `(entity_id, phash)`; тест с разными разрешениями одной картинки |
| Вес репозитория | изображения не коммитятся; ресайз до 480 px; манифест — текст |
| Битый файл или не тот MIME | проверка типа и размеров при `sync`; непрошедшее — в отказ с причиной |
| Этикет Commons API | один `User-Agent` с названием проекта, не больше одного запроса за раз, кеш ответов |
| Миграция и откат | только добавление таблицы; старый код её не читает |
| Атрибуция неточная | автор и лицензия — из метаданных Commons как есть; пустое поле не выдумываем, в подписи показываем то, что есть |

## Migration Plan

1. Выкатить миграцию 7 и код, который отдаёт пустой список, как сейчас (поведение не меняется).
2. Собрать манифест для пилота, прогнать `validate`, `sync` на стенде, подтвердить часть изображений оператором.
3. Проверить карточку, медальон и галерею в браузере (T11, T16, снимки S1 и S4).
4. Расширить на остальных персон с Wikidata тем же путём.
5. Откат: скрыть изображения оператором (мгновенно) или выкатить прежнюю версию — поле `portraits` игнорируется клиентом, монограмма возвращается.
