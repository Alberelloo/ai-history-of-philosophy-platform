# Proposal

## Why

Ассистент отвечает по источникам, только если умеет находить нужные абзацы: по смыслу, по словам с учётом склонений и в пределах выбранного учебника или всей библиотеки. Индексация и поиск — первая половина этапа 3 [roadmap.md](../../../docs/product/roadmap.md) и база для сравнения с онтологией: качество поиска без онтологии измеряется до того, как она появится.

## What Changes

- Индексация опубликованных абзацев по событиям конвейера источника: эмбеддинги и полнотекстовый индекс, только для изменённых абзацев, с соблюдением разрешений лицензии.
- Нормализация текста для полнотекстового поиска: морфология, «ё», дореформенная орфография, разные языки.
- Гибридный поиск: по смыслу и по словам, объединение результатов, фильтры по источнику, языку, видимости и виду раздела.
- Точка расширения запроса, через которую позже подключится онтология.
- Переиндексация при смене модели эмбеддингов без простоя.
- Деградация: без векторной базы или провайдера эмбеддингов поиск работает по словам.

## Capabilities

### New Capabilities

- `paragraph-indexing`: как абзацы попадают в индексы, обновляются и удаляются из них.
- `paragraph-search`: как ищутся абзацы и что возвращает поиск.

### Modified Capabilities

Нет.

## Impact

- Новый сервис поиска и офлайн-задача индексации, векторная база.
- Зависит от событий [add-source-pipeline](../add-source-pipeline/proposal.md) и от сервиса LLM ([add-platform-foundation](../add-platform-foundation/proposal.md)) для эмбеддингов.
- Нужен выбор провайдера эмбеддингов (открытый вопрос system design).
