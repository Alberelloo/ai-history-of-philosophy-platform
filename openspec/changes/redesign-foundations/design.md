# Design

## Context

Мотивация в [proposal.md](proposal.md), решения дизайна в [design-system.md](../../../docs/design/design-system.md), правила в [brandbook.md](../../../docs/design/system/brandbook.md), [layout.md](../../../docs/design/system/layout.md) и [content.md](../../../docs/design/system/content.md). Это первый шаг переделки интерфейса: основа (токены, шрифты, компоненты, тема, язык, верхняя панель, визуальная проверка). Экран чтения, граф и остальные экраны переделываются следующими изменениями.

## Decisions

### 1. Токены генерируются, а не копируются

`scripts/design_tokens.py` пишет `web/src/styles/tokens.css` из `docs/design/tokens.json`:

- цвета и тени по темам: светлые в `:root, [data-theme="light"]`, тёмные в `[data-theme="dark"]` и в `@media (prefers-color-scheme: dark)` для режима «как в системе»;
- остальные семейства — `--<имя>` в `:root`;
- шрифты — `--font-ui`, `--font-read`, стили текста — `--type-<имя>` (запись `font`).

Файл коммитится, тест сверяет его с генератором. В `styles.css` и `components.css` литеральных цветов нет, это тоже проверяется тестом.

### 2. Шрифты из пакетов

`@fontsource/onest` (400–700) и `@fontsource-variable/literata` (оптический размер, прямой и курсив) импортируются в `main.tsx`; файлы отдаёт сам сайт. Вариативный пакет объявляет семейство «Literata Variable», поэтому генератор ставит его в `--font-read` перед «Literata» из токенов.

### 3. Компоненты — классы дизайн-системы

`web/src/styles/components.css` — копия `docs/design/system/components.css` без подключения Google Fonts и раскладки превью. Обёртки на React — `web/src/ui.tsx` (значки, `Switch`, `Seg`, `StatusMark`, `Generated`, `Portrait` с монограммой). Флажки фильтров библиотеки и выбор источников в настройках остаются настоящими `input`, оформленными по токенам: так сохраняются подписи и проверка флажков в тестах.

### 4. Тема без мигания

Тема и язык хранятся в общем хранилище `philograph:v2` (`theme`, `lang`). Скрипт в `<head>` `index.html` до загрузки приложения ставит `data-theme` (для «как в системе» атрибута нет) и `lang`; приложение потом меняет их при выборе.

### 5. Каталог строк

`web/src/i18n/ru.ts` — источник ключей, `en.ts` типизирован как `typeof ru`: недостающий или лишний ключ ломает `tsc`. Язык по умолчанию — язык браузера. Сервер отвечает кодами (`kind`, `reason`, `extension`), клиент показывает текст из каталога, текст сервера — запасной вариант. В истории диалога, которая уходит модели, пометка сгенерированного остаётся русской, как в подсказках сервера.

### 6. Верхняя панель и навигация

`TopBar` закреплена, высота `--topbar`. Ссылки «Библиотека», текущий источник и «Настройки» — настоящие ссылки; повторявшие их кнопки внутри экранов убраны. Название источника берётся из списка библиотеки и кэшируется. Из-за закреплённой панели у страницы `scroll-padding-top`, а место чтения считается от него.

### 7. Визуальная проверка

`tests/e2e/visual.py`: проверки по DOM (цвета равны токенам, шрифты загружены, нет горизонтальной прокрутки, области не пересекаются, текст не обрезан, контраст не ниже 4.5:1, кольцо фокуса) и `snap()` — сравнение снимка с эталоном через Pillow. Порог — 0.5% пикселей с разницей канала больше 40 (сглаживание не считается). Эталоны свои для каждой платформы (`baselines/<sys.platform>/`); без эталонов платформы сравнение пропускается, проверки по DOM работают всегда. Обновление — только `PHILOGRAPH_UPDATE_SNAPSHOTS=1` или `python scripts/visual_check.py --update`. Визуальные тесты поднимают свой стенд, чтобы снимки не зависели от других сценариев.

## Risks / Trade-offs

- [Шрифты добавляют ~10 запросов на первую загрузку] → общий лимит частоты шлюза (запас 60) читателю не мешает, но тесты открывают сотни страниц без кэша; на стендах тестов запас поднят (`PHILOGRAPH_RATE_BURST`).
- [Эталоны только для Windows] → в CI на Linux снимки не сравниваются, остаются проверки по DOM. Эталоны Linux можно добавить командой обновления в контейнере CI.
- [Упоминания без типа сущности] → сервер пока не отдаёт тип в `/mentions`, поэтому подчёркивание нейтральное, а не цвета семьи. Добавим вместе с экраном чтения.
- [Карточка и ассистент поверх текста] → панель, сдвигающая колонку, и окно на поле — следующий шаг (экран чтения).
