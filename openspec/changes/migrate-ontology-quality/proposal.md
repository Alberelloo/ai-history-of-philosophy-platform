# Proposal

## Why

Первые три изменения (`improve-extraction-naming`, `improve-person-quality`, `add-wikidata-life-dates`) исправляют **новые** записи. Существующая онтология стенда (1889 сущностей, 1935 названий) остаётся такой, как в П1–П4 задания владельца:
- 74% названий на латинице;
- 7 номеров разделов;
- около 21 мусорной персоны;
- около 15 дублей;
- 10 датированных сущностей.

Приёмка А1–А8 считается на стенде **после** переработки. Значит, нужны две вещи: приведение данных и воспроизводимый замер. Решения ведущего: О4 — замер скриптом только на чтение, стенд и прогон у Lead'а; О5 — выбор варианта миграции с расчётом А1; О7 — инварианты.

## What Changes

- **Гибридная миграция** — команда оператора `python -m philograph.knowledge.ontology_migrate`, `plan | run | rollback`. Шаги по порядку, каждый записан в `run_actions` запуска:
  1. **Язык названий по письменности.** Латинское название с языком `ru` получает язык `en`.
  2. **Снятие мусора.** Сущность, у которой основное название не проходит правило названий (`naming.check_name`), снимается. Её утверждения остаются в базе, но не показываются. Сущность не удаляется.
  3. **Русские названия из Wikidata** для сущностей с QID: подпись `ru` записи становится основной (`set_primary_name`), если проходит проверку.
  4. **Перевод остальных латинских названий моделью.** Пакетами по 50 через шлюз (`ontology.translate_names`), только по флагу `--translate model`. Сервер проверяет каждое предложение: русская письменность, правило названий, id из пакета. Отклонённое остаётся английским.
  5. **Слияние дублей персон** — `Dedupe` из `improve-person-quality`. Сомнительные пары и совпавшие названия не-персон идут в очередь проверки.
  6. **Проверка сохранности.** Ни одно действующее утверждение и ни одна атрибуция не потеряны, кроме утверждений снятого мусора. Если что-то потеряно, запуск сам откатывается, команда выходит с кодом 1.
- **Сухой прогон** (`plan`) считает тот же отчёт по проекции без записи и без вызова модели. Вместо переводов он показывает число названий к переводу и пакетов.
- **Оценка стоимости** перевода (`plan --estimate`) — одна оплачиваемая проба на одном пакете, по образцу `Filling.estimate`. Запускает только Lead (О5).
- **Откат** `rollback <run_id>` возвращает базу к состоянию до запуска: обратные действия по `run_actions` в обратном порядке и отмена слияний запуска.
- **Отчёт** — JSON с числами по шагам, сохранностью, А1 до и после.
- **Замер А1–А8** — `python -m philograph.knowledge.quality_report [--save F] [--baseline F] [--json]`. Работает только на чтение и печатает таблицу «критерий | значение | порог | итог». Формулы — в спецификации.
- **Снятие сущности** — новые столбцы `entities.retired_run` и `entities.retired_reason` (схема `knowledge:9`). Снятая сущность не видна в снимке, поиске, справочнике, на карте, в упоминаниях и карточках. Её утверждения в базе сохраняются.
- **Новая возможность `ontology-migration`:**
  - «Миграция существующей онтологии»;
  - «Снятие мусорных сущностей»;
  - «Перевод названий»;
  - «Откат миграции»;
  - «Замер качества онтологии».
- **Журнал:**
  - `knowledge.migration.step`;
  - `knowledge.migration.run`;
  - `knowledge.migration.aborted`;
  - `knowledge.migration.rolled_back`;
  - `knowledge.entity.retired`;
  - `knowledge.entity.restored`;
  - `knowledge.quality.measured`.

## Out of scope

- Переизвлечение всех источников (вариант А) — отвергнут в design.md. Повторное извлечение отдельных источников новым промптом остаётся обычной командой оператора.
- Перевод не-латинских названий (греческих) и транслитерации («Омир» → «Гомер»). Это очередь проверки.
- Автослияние не-персон: только очередь проверки.
- Данные `.stack` в git не попадают. Стенд Lead'а (1889 сущностей) на этой машине отсутствует (О4). Тесты идут на синтетической онтологии с симптомами П1–П4.

## Деньги и внешние сервисы (за Lead'ом, О5)

- **Перевод моделью** — около 1400 названий, 28–29 пакетов роли `main` (deepseek-flash). Оценка по ценам `config/llm.yaml`:
  - вход ~1,5 тыс. токенов на пакет;
  - выход ~1,2 тыс.;
  - итого ≈ 29 × (1,5k × $0,30 + 1,2k × $1,20) / 1M ≈ **$0,06** (ночью вдвое дешевле).

  Точную цифру даёт `plan --estimate` на стенде.
- **Wikidata** — бесплатно, сеть только в команде оператора, в тестах фикстуры.
