# Design

## Контекст

**Данные стенда** (задание владельца, разбор 2026-11-25):

| | Всего | Латиница |
|---|---|---|
| Сущностей | 1889 | — |
| Названий | 1935 | 1425 (74%) |
| Понятия | 923 | 838 |
| Позиции | 295 | 171 |
| Персоны | 85 | 52 |
| Термины | 83 | 64 |
| Прочие (произведения, события, группы, места, источники, эпохи) | 549 названий (≈ 503 сущности: 1889 − 1386) | 300 |

Мусор: 7 номеров, ~21 персона, единичные термины и пустая строка. Дубли персон: ~15 лишних записей. Датировано 10 сущностей. Сейчас доля русских — около 25% (≈ 472 сущности). Владелец дал доли по названиям (1425 из 1935). Число латинских *сущностей* ≈ 1889 × 0,75 ≈ 1417 оценено по его «сейчас 25%», отсюда расхождение 1417/1425.

**Факт кода, на который опирается план:**

- `naming.check_name`, `naming.is_russian`, `naming.lang_for`, `Entities.set_primary_name`, `tests/knowledge/dump.py`, `scripts/mutation_check.py` — из `improve-extraction-naming`.
- `dedupe.same_person`, `dedupe.plan` (компоненты), `Dedupe.run`, `Statements.merge_entities` и `Statements.undo_merge` со свёрткой и архивом — из `improve-person-quality`.
- `run_actions` (`knowledge:8`) и кэш записей Wikidata через `fetch` — из `add-wikidata-life-dates`.
- Реестр онтологии (`registry_data.py`) содержит типы, связи и уточнители. **Таблицы названий в нём нет**: соответствий «Locke → Локк» в реестре ноль. Это важно для варианта Б.
- `Statements.rollback_run(run_id)` удаляет непроверенные утверждения запуска вместе с их атрибуциями и подтверждениями.
- `Filling.estimate` — образец пробы стоимости: короткий запуск, затем `spend` по `run_id`.
- Снимок (`snapshot.load`), `mentions.py`, `Entities.find` и `duplicate_candidates` отбирают действующие сущности условием `redirect_to IS NULL`. Это четыре места.

## Выбор решения: вариант миграции (О5)

Расчёт А1. Знаменатель — действующие сущности, кроме источников библиотеки (`source`).

**Что останется после чистки и слияния:**
- снято мусора ≈ 30;
- слито дублей ≈ 11: Berkeley×3 → 1, Сократ×3 → 1, Теэтет×3 → 1, по одному лишнему у Hegel, Hume, Newton, Reid, Descartes. Однословные дубли сливаются `merge:name` (О13); шаг `translate` идёт до `dedupe`, поэтому «Hume» после перевода в «Юм» сливается с «Юм» по общему основному;
- Гомер/Омир и Горгий/Горгиас без общего написания правило имён не видит. Их путь (О10): `suggest` ставит пару в очередь `duplicate` (`review:qid_candidate`), человек подтверждает QID в манифесте, шаг `manifest_qids` сливает по `merge:qid_confirmed`. До решения пара открыта в очереди и А4 её считает.

**Знаменатель и пороги:**
- знаменатель ≈ 1889 − 30 − 11 − S ≈ **1838 при S ≈ 10**. Здесь S — число сущностей-источников, по одной на каждый обработанный источник (`source_entity`). На стенде S не проверено; при S = 100 знаменатель ≈ 1748, допуск ≈ 175, нужная доля принятых переводов ≈ 87,3%. Вывод от S не меняется;
- латинских среди оставшихся ≈ 1417 − 30 − 8 ≈ **1379**;
- порог А1 ≥ 90% допускает не больше **183** нерусских основных названий.

| Вариант | Что даёт для А1 | Оптимальность (деньги, время) | Архитектура | Поддержка и масштаб |
|---|---|---|---|---|
| **А. Переизвлечение** всех источников новым промптом, старые запуски откатываются | Зависит от модели и состава источников: 407 из 441 источника русские, ожидаемо 85–95%. Не гарантировано, и новый набор сущностей нельзя сравнить со старым | Дорого. Роль `strong`, ≈ 5,5 тыс. токенов входа и 1,5 тыс. выхода на фрагмент ≈ **$0,0115 за фрагмент**. При 10 тыс. фрагментов ≈ $115, месячный бюджет `filling` — $200. Часы работы очереди | `rollback_run` удаляет непроверенные утверждения старых запусков. Всё, что новая модель не повторит, теряется, а это **нарушает «не потерять утверждения» и А8** | Повторяемость низкая: другой ответ модели — другая онтология. Проверки человека по старым id пропадают |
| **Б. Скрипт по таблице соответствий** + удаление мусора + слияние | В реестре таблицы нет (0 записей). Таблицу пришлось бы писать вручную. Даже для всех персон и терминов (≈ 116) А1 ≈ (472 + 116) / 1838 ≈ **32%**. Верхняя граница без перевода понятий и позиций — (1838 − 838 − 171) / 1838 ≈ **45%** | Дёшево: без модели, секунды | Детерминированно, но таблица на 1400 строк — те же данные, что дала бы модель, только вручную | Таблица растёт с каждым источником; порог **недостижим** |
| **Гибрид** (выбран): детерминированная чистка + русские названия из Wikidata для сущностей с QID + перевод остальных латинских названий моделью пакетами с проверкой сервером + слияние дублей | Чтобы получить ≥ 90%, сервер должен принять ≥ (1379 − 183) / 1379 ≈ **86,7%** переводов. Для словаря философии у flash-модели ожидается ≥ 95% → А1 ≈ (1838 − 0,05 × 1379) / 1838 ≈ **96%**. Без шага перевода (`--translate off`) — ≈ 32–35%, порог не выполнен | ≈ 29 пакетов роли `main` (flash) ≈ **$0,06**. Минуты. Wikidata бесплатно | Модель предлагает только название. Код проверяет письменность, правило названий и id пакета. Утверждения, атрибуции и id сущностей не трогаются, переименование не меняет ссылок. Каждое действие записано и откатывается | Шаги — данные (`STEPS`). При 10× сущностей — 10× пакетов, линейно. Перевод — тот же механизм для новых английских источников |

**Выбран гибрид.**

Платим так:
- переводы модели не проверены человеком. Все они перечислены в отчёте (`renamed.model`), а английское написание остаётся вариантом, поэтому поиск по нему работает. Выборочную проверку делает Lead;
- А1 ≥ 90% достигается **только** с оплачиваемым шагом `--translate model`. Его запускает Lead после `plan --estimate` (О5).

Костыли, которых избегаем:
- удаление сущностей и утверждений;
- переименование через новую сущность;
- ручная таблица в коде;
- перевод без проверки;
- особые случаи под цифры приёмки.

## Выбор решения: как снять мусор

| Вариант | Оптимальность | Архитектура | Поддержка и масштаб |
|---|---|---|---|
| А. Удалить сущность и её утверждения | Просто | Необратимо. API удаления нет. Нарушает «не потерять», откат невозможен | — |
| Б. Отклонить утверждения мусора (`rejected`) | Без схемы | Сущность остаётся в справочнике, и А7 не выполнится. Статус «отклонено» означает решение о факте, а не о названии | Смешение смыслов |
| В. Флаг снятия у сущности `retired_run`/`retired_reason` (выбрано) | Один столбец, одно условие | Условие «действующая» — одна функция `schema.active(t.entities)` вместо четырёх копий `redirect_to IS NULL`. Утверждения в базе целы и вернутся при откате | Снятие и возврат — по запуску. Новый потребитель берёт общее условие |

## Выбор решения: сухой прогон

| Вариант | Оптимальность | Архитектура | Поддержка и масштаб |
|---|---|---|---|
| А. Запуск + откат в том же процессе | Ноль нового кода | Читатели живого сервиса видят промежуточное состояние | Опасно на стенде |
| Б. Копия базы | Полный реализм | Операции с Postgres (шаблонная база, отключение соединений) | Зависит от СУБД |
| В. Проекция: шаги — чистые функции `plan(view) → actions`, сухой прогон применяет действия к проекции в памяти (выбрано) | Только чтение базы | Те же планировщики, что у настоящего запуска; `dedupe.clusters` уже чистая | Инвариант «отчёт `plan` = отчёт `run --translate off`» проверяется тестом |

## Контракты

### `knowledge/ontology_migrate.py` (новый)

```
python -m philograph.knowledge.ontology_migrate plan     [--from-file WD] [--estimate] [--limit N]
python -m philograph.knowledge.ontology_migrate run      [--translate off|model] [--from-file WD] [--batch 50]
python -m philograph.knowledge.ontology_migrate rollback <run_id>
```

```python
@dataclass(frozen=True)
class Action:  step: str; kind: str; payload: dict          # пишется в run_actions
class View:    # проекция: entities, names, externals, retired — из snapshot-подобной выборки
    def apply(self, action: Action) -> None
STEPS = ("manifest_qids", "lang_fix", "retire", "wikidata_labels", "translate", "dedupe", "verify")
class Migration:
    def __init__(self, statements, review, fetch: Fetch | None, llm: ServiceClient | None)
    def plan(self, *, estimate=False) -> Report          # без записи; translate — подсчёт
    def run(self, *, translate="off", batch=50) -> Report
    def rollback(self, run_id) -> dict
```

**Шаги.** У каждого есть `plan(view) → [Action]`, `apply(action)` и `undo(action)`.

| Шаг | Действие | `payload` для отката |
|---|---|---|
| `manifest_qids` | при `--manifest`: `LifeDates.apply` по манифесту в рамках запуска (`run_id` общий); пары `qid_taken` с `accepted` идут в шаг `dedupe` как `confirmed`, без решения — в очередь | `{kind: external}` из `run_actions`, слияния — `{merge_id}` |
| `lang_fix` | название с `lang ≠ script_lang(text)` (и `script_lang` не `None`) → язык по письменности | `{name_id, old_lang}` |
| `retire` | действующая сущность (не `source`), у которой `check_name(type, label)` даёт причину → `retired_run = run_id`, `retired_reason = причина`; событие `knowledge.entity.retired` | `{entity_id}` |
| `wikidata_labels` | сущность с QID и с нерусским основным названием: подпись `ru` записи проходит `is_russian` и `check_name` → `set_primary_name(e, "ru", …)` | `{entity_id, names_before}` |
| `translate` | оставшиеся с нерусским основным названием, пакетами `batch`, шаблон `ontology.translate_names`, роль `main`, бюджет `filling`, `run_id` в контексте | как у `wikidata_labels` |
| `dedupe` | `Dedupe(...).run(run_id=…)` по персонам. Не-персоны одного типа с общим основным названием → очередь `duplicate` с `reason="review:same_name"` (своя причина: в А4 не входит, там только персоны) | `{merge_id}` |
| `verify` | `integrity.compare(baseline, engine)`. Потери > 0 → автоматический `rollback`, `knowledge.migration.aborted`, код выхода 1 | — |

**Проверка перевода сервером.** Для пакета из `k` элементов `{n, type, label}` модель возвращает `{"translations": [{"n": int, "ru": str}]}`. Принимается предложение, у которого:
- `1 ≤ n ≤ k` и `n` встречается один раз;
- `is_russian(ru)`;
- `check_name(type, ru)` не дал причины.

Порядок причин и правило повтора номера (отклоняются все предложения с этим номером) — в спецификации «Перевод названий». Элемент без предложения — `missing`. Идентификаторы сущностей модели не передаются, только номер в пакете. Сбой шлюза — пакет пропускается, запуск идёт дальше (`failed_batches`).

**`--limit N`** — предел числа названий к переводу (шаг `translate`), в `plan` и `run`.

**`--estimate`.** `plan` отправляет модели один пакет (оплачиваемый вызов), а ответ не записывает. Цена берётся из `spend` по `run_id`, как в `Filling.estimate`:

`estimate_usd = probe_cost × ceil(к_переводу / batch)`

**Отчёт** (`Report.to_json()`):

```json
{"run_id": "...", "dry_run": false, "translate": "model",
 "lang_fixed": 0, "retired": {"number": 7, "not_a_name": 19, "stopword": 3, "empty": 1, "sentence": 2},
 "retired_list": [{"id": "e_…", "type": "position", "label": "…", "reason": "sentence"}],
 "renamed": {"wikidata": 0, "model": 0}, "renamed_list": [{"id": "e_…", "from": "causality", "to": "Причинность", "by": "model"}], "untranslated": {"not_russian": 0, "invalid:stopword": 0, "missing": 0},
 "to_translate": 0, "batches": 0, "failed_batches": 0,
 "merged": 0, "folded": 0, "review": 0,
 "statements": {"before": 0, "after": 0, "folded": 0, "dropped_garbage": 0, "lost": 0},
 "attributions": {"before": 0, "lost": 0},
 "a1": {"before": 0.25, "after": 0.96}, "estimate_usd": null}
```

### `rollback(run_id)`

Действия `run_actions` запуска выполняются в обратном порядке `seq`:
- `dedupe` → `Statements.undo_merge(merge_id)`;
- `manifest_qids` (О12): `{kind: external, entity, qid}` → удаление внешнего идентификатора; утверждения шага (годы жизни, датировки, роли P106) → `Statements.rollback_run(run_id)`, тот же механизм, что `LifeDates.rollback`. Слияния по `qid_confirmed` уже отменены вместе с `dedupe`. Проверенные человеком утверждения не трогаются;
- переименования → восстановление `names_before` (тексты, виды, языки);
- `retire` → `retired_run = NULL`, событие `knowledge.entity.restored`;
- `lang_fix` → прежний язык.

Пункты очереди проверки, созданные запуском, закрываются со статусом `rolled_back`. Пересчёт `primary` у затронутых сущностей. Событие `knowledge.migration.rolled_back`.

### Схема `knowledge:9`

- `entities.retired_run String(64) NULL`, `entities.retired_reason String(20) NULL`;
- функция `schema.active(entities)` — `redirect_to IS NULL AND retired_run IS NULL`.

Её используют `snapshot.load`, `mentions.py`, `Entities.find`, `Entities.duplicate_candidates`, `Entities.externals`, индекс `dedupe`.

**Утверждения снятых** (ревью, блок. 3; О9). `snapshot.load`:
- берёт только утверждения, оба конца которых действующие (без этого `context.py` падает с `KeyError` на `snapshot.entities[target]`, а `catalog.py` считает вес по мусорным концам);
- скрывает атрибуции с `who_kind="entity"` и снятым `who`;
- не показывает утверждение, у которого все атрибуции скрыты (как правило «только снятый источник»);
- берёт только упоминания действующих сущностей.

Все потребители — справочник, карта, карточки, граф, контекст ассистента — читают снимок, поэтому правило одно. `Statements.about` (карточка, `/entities/{id}/statements`) фильтрует так же через `schema.active`. Карточка снятой сущности (`/entities/{id}/card`) отвечает 404, как для неизвестной. `Entities.get` отдаёт снятую с полем `retired`: внутренние вызовы по концам утверждений не ломаются.

### `knowledge/integrity.py` (новый)

Общий для `verify` и для замера А8.

```python
@dataclass(frozen=True)
class Baseline: statements: dict[str, Content]; attributions: dict[str, Counter[tuple]]
def baseline(engine) -> Baseline        # действующие: status != rejected, rank != deprecated, любой scope
def compare(b: Baseline, engine) -> {"lost": [...], "lost_attributions": [...], "folded": n, "dropped_garbage": n}
def save(b, path) / load(path)          # JSON
```

Сопоставление: id утверждения из `Baseline` → (перенаправление свёртки, `merges.moved.folded[].into`) → действующее утверждение `s'`.
- **Потеряно**, если `s'` нет или оно не действующее, и при этом ни один конец (с учётом перенаправлений сущностей) не снят.
- **Мусор**, если конец снят: тогда это `dropped_garbage`.

Атрибуция исходного утверждения `(who_kind, resolve(who), stance)` должна быть у `s'`, иначе `lost_attributions`. Точный повтор на одном утверждении после свёртки не считается потерей.

### `knowledge/quality_report.py` (новый) — замер А1–А8 (О4)

```
python -m philograph.knowledge.quality_report [--save before.json] [--baseline before.json] [--json]
```

- **Только чтение:**
  - SQLite открывается с `mode=ro` (URI);
  - Postgres — с `default_transaction_read_only=on`;
  - миграции схемы не выполняются;
  - на схеме без `knowledge:9` снятых сущностей нет.
- **Вывод.** Таблица `критерий | значение | порог | итог` и итоговая строка. `--json` даёт тот же результат в JSON.
- **Код выхода:** 0 — все пороги выполнены, 1 — нет, 2 — ошибка базы или аргументов.
- **Журнал:** событие `knowledge.quality.measured` с числами.
- **Определения** заданы данными `CRITERIA` (имя, функция, порог, сравнение) и повторены в спецификации.

Обозначения:
- `E` — действующие сущности (`schema.active`);
- `label(e)` — правило `snapshot.labels`: основное `ru`, иначе первое основное, иначе первое любое;
- `P` — действующие персоны.

| # | Формула | Порог |
|---|---|---|
| А1 | `|{e ∈ E, type ≠ source : is_russian(label(e))}| / |{e ∈ E, type ≠ source}|`. `is_russian`: ≥ 1 кириллическая буква, нет латинских букв, кроме слов из римских цифр `[IVXLCDM]+` | ≥ 0,90 |
| А2 | `|{e ∈ E, type ≠ source : check_name(type, label) ∈ {number}}|` | = 0 |
| А3 | `|{p ∈ P : check_name("person", label(p)) ≠ None}|` (стоп-список, роли, описания, склейки) | = 0 |
| А4 | `len(names ∪ queue − distinct)` по неупорядоченным парам `frozenset({a, b}) ⊂ P` (О12): `names` — пары, где `normalize(основное(a))` ∈ нормализованные названия `b` (основные и варианты) или наоборот; `queue` — пары открытых пунктов `duplicate` любой причины (`review:dates`, `review:variant`, `review:single_name`, `review:qid_cluster`, `review:decided_conflict`, `review:qid_candidate`, `review:qid_taken`; пункты не-персон `review:same_name` в `P` не входят); `distinct` — пары закрытых пунктов `duplicate` с `resolution.merge = false`. Объединение, а не сумма: пара по названию и её пункт `review:variant` — одна пара. `dedupe` и `suggest` не ставят в очередь пару из `distinct` повторно. Общий QID невозможен (PK `external_ids`), поэтому в формуле его нет (О9). Тёзки «Фрэнсис Бэкон»/«Роджер Бэкон» с вариантом «Бэкон» не совпадают: сравнивается основное одной со всеми названиями другой | = 0 |
| А5 | `|{p ∈ P : primary.dates ≠ None}|` | ≥ 20 |
| А6 | число записей `people` ответа `GET /api/knowledge/v1/map` без учебника с `"philosopher" ∈ roles`. Команда считает его тем же объектом `SectionMap.result(textbook=None)`, что отвечает на этот адрес. Тест сверяет с ответом API | ≥ 10 |
| А7 | число элементов ответа `GET /api/knowledge/v1/catalog` (все страницы, `lang=ru`, без фильтров), у которых `check_name(type, label) ≠ None`. Считается тем же `Catalog.list`. Тест сверяет с API | = 0 |
| А8 | `lost + lost_attributions` по `integrity.compare(baseline)`; без `--baseline` — «не измерено», итог не «выполнен» | = 0 |

Справочно, без порога:

- пары в очереди проверки;
- `dropped_garbage`;
- А1 по типам.

## Стратегии для property-тестов (О7, О9)

- `ontologies()` — синтетическая онтология 10–80 сущностей с симптомами П1–П4:
  - латинские понятия с языком `ru`;
  - номера `\d+(\.\d+)+`, пустые, стоп-слова;
  - персоны-роли и склейки;
  - кластеры дублей (Berkeley×3, «Hume»(QID)/«Юм» без QID, «Гомер»/«Омир»);
  - 0–150 утверждений с атрибуциями `source`/`entity` (в том числе на дубль и на мусор)/`common`;
  - подтверждения, упоминания, портреты, утверждения `verified`.
- `wd_label_records()` — записи с `ru`-подписью, без неё, с мусорной подписью.
- `translation_replies()` — ответы фейковой модели:
  - верные;
  - латиница;
  - стоп-слово;
  - чужой `n`;
  - повтор `n`;
  - пропуски;
  - сбой шлюза.

Все стратегии возвращают пару «вход + ожидание»: ожидаемые снятия с причинами, переименования, разбиение, А1–А8. Ожидание строится из того, как собран вход, без импорта `naming`, `dedupe`, `integrity`, `quality_report`. Профиль `heavy` (25 примеров) для `run`/`rollback`, `ci` для перевода и снятия.

**Независимые оракулы сухого прогона** (Б9):
1. `dump` до и после `plan` равны;
2. список действий `plan` (вид, сущность, значения) равен списку `run_actions`, которые записал `run --translate off` на копии той же онтологии, кроме служебных полей отката (`names_before`);
3. разность дампов до и после `run` совпадает с тем, что предсказывают действия `plan`: снятые, переименованные, перенаправленные.

Сравнение отчётов — дополнительная, а не единственная проверка.

**Названия в журнале:** в названиях онтологии стоит маркер «Zq7Marker». Сериализованный журнал всех событий запуска ищется по маркеру.

**Инварианты:**
- **Сохранность.** `compare(baseline).lost == lost_attributions == []` после `run`.
- **Откат.** После `rollback` `dump` таблиц данных равен дампу до `run`. Журнальные таблицы (`run_actions`, `merges`, `review_items`) проверяются отдельно: пункты запуска закрыты как `rolled_back`.
- **Сухой прогон.** Оракулы 1–3.
- **Перевод.** Записаны ровно ожидаемые названия, причины равны ожидаемым.
- **Снятие.** После `run` ни одна действующая сущность не даёт причины, то есть А2 = А3 = А7 = 0. Ни одно утверждение со снятым концом не показано ни в одном ответе API.

## Риски

- Качество перевода не проверено человеком. Меры: английское название остаётся вариантом, отчёт перечисляет переименования, откат по запуску полный. Выборка на проверку — за Lead'ом.
- Перевод может создать совпадения названий у не-персон («Причинность»/«causality» → два «Причинность»). Они уходят в очередь проверки, автослияния не-персон нет. В отчёте поле `review`.
- `retire` по правилу названий снимает и законные сущности с длинным названием, если пределы типа малы. Сухой прогон показывает `retired` по причинам до записи. Пределы — данные.
- Гомер/Омир, Горгий/Горгиас видны А4 только через очередь: если `suggest` не нашёл общего кандидата QID (у обеих нет QID или поиск не дал держателя), пара не попадёт ни в очередь, ни в А4. А4 = 0 не значит, что таких пар нет; на стенде их проверяет ручной список П4 в отчёте.
- А5/А6 зависят от подтверждения QID (`add-wikidata-life-dates` 5.2) и ролей P106. Без них миграция А5/А6 не поднимет. Это записано в замере.
