## Why

Аудит `docs/audit/2026-11-19-system-audit.md` нашёл технический долг клиента (`web/`):

- **1.6.** Крупные компоненты: `AssistantPanel.tsx` 1469 строк, `MapPanel.tsx` 910, `ReaderPage.tsx` 770, `ui.tsx` 721. Запросы идут мимо `api.ts`: база `/api/knowledge/v1` объявлена в пяти местах, 14 прямых `fetch`, а `ReviewPage.tsx:89` не проверяет `ok`.
- **1.7.** ESLint не подключён, но восемь комментариев отключают его правило `react-hooks/exhaustive-deps`.
- **1.15**, клиентская часть. Нет `engines` и `.nvmrc`. Нет юнит-тестов клиента: `model.ts`, `storage.ts` и `layout.ts` проверяются только через Playwright.
- **1.16.** В хранилище браузера лежат переносы старых форматов (`storage.ts:353-385`).

Каждое новое поведение клиента сейчас ложится в и без того крупные файлы. Нарушения правил хуков никто не ловит, а ошибки сети обрабатываются в каждом месте по-своему.

## What Changes

- Все запросы клиента идут через `web/src/api.ts`. Базы сервисов объявлены в одном месте, ошибки приходят как `ApiError`, потоки NDJSON читает один общий помощник.
- ESLint (flat config) с `typescript-eslint` и `eslint-plugin-react-hooks` запускается в `npm run build`, а значит и в CI. Подавления `exhaustive-deps` устранены по существу.
- В `package.json` появляется `engines` (node ≥ 20), рядом `.nvmrc` (24).
- `AssistantPanel`, `ReaderPage`, `MapPanel` и `ui.tsx` разделены на хуки и подкомпоненты по смыслу. Разметка и классы не меняются.
- Переносы старых форматов хранилища остаются: на них опираются браузерные тесты требования «Единое хранилище в браузере». Перенос вынесен в отдельный модуль чистых функций.
- Юнит-тесты (vitest) чистых функций `map/model.ts`, хранилища и `map/layout.ts` запускаются в `npm run build`.

Поведение для пользователя не меняется, поэтому дельт спецификаций нет (`skip_specs: true`).

## Impact

Только `web/`: исходники клиента, `package.json`, `package-lock.json`, `eslint.config.js`, `vitest`-тесты в `web/src/**/*.test.ts`, `.nvmrc`. Сервер, тесты `tests/web` и `tests/e2e` и CI (`.github/workflows`) не меняются. CI запускает `npm ci && npm run build` в `web/`, поэтому линтер и юнит-тесты попадают в проверку `checks` без правки `ci.yml`.
