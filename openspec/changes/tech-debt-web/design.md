## Context

Клиент — React 18 + TypeScript + Vite (ADR-0001). Сборка в CI: `cd web && npm ci && npm run build`, а `ci.yml` этим изменением не меняется. Браузерные тесты `tests/web` (один процесс) и `tests/e2e` (весь продукт) — доказательство того, что поведение не изменилось. Они должны пройти без правок. Тесты опираются на классы, роли, подписи и ключи хранилища (`philograph:v4`, `philograph:v3`, `philograph:v2`, `philograph:v1`), поэтому разметка и формат хранилища не меняются.

## Goals / Non-Goals

**Goals:** один вход для запросов и ошибок; линтер хуков в CI; файлы компонентов, которые можно прочитать целиком; юнит-тесты чистой логики клиента.

**Non-Goals:** менять поведение, разметку, классы, тексты или формат хранилища; править CI; переводить клиент на библиотеку запросов или на React Compiler.

## Выбор решения

### 1. Запросы

| Вариант | Оптимальность | Архитектура | Поддержка и масштаб |
|---|---|---|---|
| А. Оставить `fetch` по месту, вынести только константы баз | Минимум правок | Проверка `ok` и разбор ошибки остаются в 14 местах, `ReviewPage` по-прежнему не проверяет `ok` | Каждый новый запрос пишет свою обработку ошибок |
| Б. `api.ts`: базы сервисов, `request()` бросает `ApiError` (`kind`, `status`, тело ответа), `stream()` читает NDJSON; методы по сервисам (`api`, `knowledgeApi`, `assistantApi`) | Без новых зависимостей, около 150 строк | Правило «ответ не `ok` — это `ApiError`» живёт в одном месте; компоненты не знают адресов | Новый запрос — один метод; поток — один помощник с общим тестом |
| В. Библиотека запросов (TanStack Query, axios) | Новая зависимость и кэш, который здесь не нужен | Второй способ хранить серверное состояние рядом с `storage.ts` | Перестройка всех компонентов |

Выбрано: **Б**. Сетевой сбой и отмена (`AbortError`) не заворачиваются в `ApiError`: компоненты уже различают отмену по `signal.aborted`, и обёртка сломала бы это различие. Чем платим: вызывающий код ловит два вида ошибок, `ApiError` и сетевую; везде, где это важно, они обрабатываются одинаково, как и раньше. Костыли, которых избегаем: копии разбора тела ошибки и NDJSON-парсера в трёх местах (`map/stream.ts`, `CardPopup.tsx`, `AssistantPanel.tsx`).

Поведение на ошибках, которые раньше не обрабатывались:
- `ReviewPage.openStatement` при ответе не `ok` не открывает пустую карточку утверждения, а показывает ошибку тем же блоком `pg-notice--danger`, что и вход.
- `ReviewPage.load` при ответе не `ok`, кроме 404, показывает ту же ошибку вместо падения на `.map` у тела ошибки.

Для читателя это не новое поведение, а исправление падения на странице оператора.

### 2. Линтер

| Вариант | Оптимальность | Архитектура | Поддержка и масштаб |
|---|---|---|---|
| А. Без ESLint, убрать комментарии `eslint-disable` | Ноль зависимостей | Правила хуков никто не проверяет: аудит 1.7 остаётся открытым | Нарушения копятся молча |
| Б. ESLint 9 flat: `typescript-eslint` `recommended` (без типов) и `eslint-plugin-react-hooks` 5 (`rules-of-hooks`, `exhaustive-deps` как ошибки); запуск в `npm run build` | Пять dev-зависимостей, линт около 5 с | Одна точка входа в CI без правки `ci.yml` | Конфиг на 30 строк; правила расширяются по месту |
| В. `recommendedTypeChecked` и react-hooks 7 с правилами React Compiler | Медленнее, требует `parserOptions.project` | Правила компилятора (`refs`, `set-state-in-effect`, `purity`) спорят с принятыми в коде приёмами: измерение DOM в `useLayoutEffect`, ref последнего значения | Отдельная большая переделка, к долгу аудита не относится |

Выбрано: **Б**. Подавления `exhaustive-deps` устранены по существу:

- **Обработчик, который эффект вызывает, но от которого не должен перезапускаться** (выделение, поручение перехода, смена книги в панели): `useEvent` (`hooks/useEvent.ts`) — стабильная функция, которая вызывает последнюю версию обработчика. Это тот же приём, что `useEffectEvent` в React 19.
- **Значение, читаемое при измерении** (`Facet`): функциональное обновление состояния вместо чтения замыкания.
- **Перерасчёт раскладки карты после загрузки шрифтов**: новый измеритель (`setMeasure(canvasMeasure())`) вместо счётчика-«ключа» в зависимостях `useMemo`.
- **Подписка `useSources`**: зависимость по ключу, а внутри эффекта используется сам ключ.
- **Перетаскивание обзорной шкалы**: последняя версия `commit` через `useEvent`, а зависимости — числа шкалы.

Чем платим: react-hooks 7 и правила компилятора отложены (вариант В). Если клиент перейдёт на React 19 или Compiler, это отдельное изменение.

`engines.node` равен `>=20`: на машине разработки Node 20, а в CI и `Dockerfile` — 24. `.nvmrc` = `24`, как в CI.

### 3. Деление крупных компонентов

| Вариант | Оптимальность | Архитектура | Поддержка и масштаб |
|---|---|---|---|
| А. Разрезать по числу строк | Быстро | Логика одного смысла оказывается в разных файлах | Править так же трудно, как раньше |
| Б. Делить по смыслу: состояние и потоки — в модули и хуки, части разметки — в подкомпоненты; прежние пути импорта сохраняются (`AssistantPanel.tsx`, `ui.tsx` реэкспортируют) | Только перенос кода | Стрим ответа, хранение сессий, переходы по ссылкам — каждое в своём модуле | Файл читается целиком; модуль потоков тестируется без React |

Выбрано: **Б**.

- **Ассистент** (`web/src/assistant/`):
  - `stream.ts` — потоки ответов, стадии, отправка вопроса;
  - `handoff.ts` — поручение перехода в раздел;
  - `drafts.ts` — черновики и фрагмент на поле главы;
  - `navigation.ts` — переходы по ссылкам и возврат к месту;
  - `messages.tsx` — тексты пометок и подписи;
  - `SessionList.tsx`, `TurnView.tsx`, `Composer.tsx`, `stages.tsx` — части панели.
- **Чтение** (`web/src/reader/`):
  - `text.tsx` — текст абзаца с упоминаниями и сносками;
  - `useChapter.ts` — оглавление, глава и ближайшее место;
  - `useMentions.ts`;
  - `useTextSelection.ts`;
  - `useReaderLayout.ts`.
- **Панель карты** (`web/src/map/panel/`):
  - `fold.tsx` — подгонка разделов по высоте;
  - `SearchBox.tsx`, `Selected.tsx`, `Filters.tsx`, `Legend.tsx`.
- **`ui.tsx`** разделён на `Icon.tsx`, `Portrait.tsx`, `Lifeline.tsx`, `FilterMenu.tsx`. Сам `ui.tsx` оставляет мелкие обёртки и реэкспортирует остальное.

Чем платим: больше файлов и реэкспорты. Зато ни один импорт за пределами разрезанных файлов не меняется.

### 4. Переносы старых форматов хранилища

| Вариант | Оптимальность | Архитектура | Поддержка и масштаб |
|---|---|---|---|
| А. Удалить переносы v1–v3, неизвестное — сбросить | Минус 60 строк | Противоречит требованию «Единое хранилище в браузере» (`reader-settings`): его сценарии переноса проверяют `tests/web/test_assistant_dialogs.py::test_t40_v3_to_v4_migration`, `tests/e2e/test_settings.py::test_format_2_migrated_to_open_books`, `test_old_format_migrated`, а `tests/e2e/test_reader_snapshots.py` засевает формат 3 | Удаление поведения требует изменения спецификации, а это не рефакторинг |
| Б. Оставить переносы и вынести нормализацию и переносы в модуль чистых функций `storage/format.ts` | Только перенос кода | Формат и его переносы — отдельно от работы с `localStorage` | Переносы покрыты юнит-тестами; удалить их — одно изменение спецификации и один модуль |

Выбрано: **Б**. Тесты проверяют перенос, а удаление было бы изменением поведения по спецификации, а не долгом. Задача «после запуска зафиксировать один формат» (аудит 1.16) остаётся за изменением спецификации `reader-settings`.

### 5. Юнит-тесты клиента

| Вариант | Оптимальность | Архитектура | Поддержка и масштаб |
|---|---|---|---|
| А. Без юнит-тестов, только Playwright | Ноль зависимостей | Чистые функции проверяются через браузер, а поломку раскладки ищут по снимкам | Медленно, около 10 мин на `tests/web` |
| Б. `node:test` и `tsx` | Две зависимости | — | Свой запуск TS и ESM, без совместимости с конфигом Vite |
| В. `vitest` (окружение node, без jsdom) | Одна зависимость, переиспользует конфиг Vite | Тесты лежат рядом с модулями (`*.test.ts`) | Около 1 с на прогон, запуск в `npm run build` |

Выбрано: **В**. `npm run build` = `tsc --noEmit && eslint . && vitest run && vite build`. Тестируются только чистые функции:
- `map/model.ts` — видимость, связанные, поиск, счётчики;
- `storage/format.ts` — нормализация, переносы, вытеснение диалогов;
- `map/layout.ts` — раскладка на плотном наборе.

Компоненты по-прежнему проверяют `tests/web`. Чем платим: одна dev-зависимость и около секунды сборки.

## Risks / Trade-offs

- **[Регрессия при переносе кода]** → полный прогон `tests/web` и затронутых `tests/e2e` с собранным клиентом. Снимки DOM и экрана ключевых страниц до и после переноса сравниваются построчно.
- **[Изменился порядок эффектов из-за `useEvent`]** → обработчик обновляется в `useLayoutEffect`, а эффекты, которые его вызывают, — пассивные. Значит, они видят значения того же рендера, как прежнее замыкание.
