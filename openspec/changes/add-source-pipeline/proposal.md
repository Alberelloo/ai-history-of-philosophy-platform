# Proposal

## Why

Библиотека и чтение ([add-library-and-reading](../add-library-and-reading/proposal.md)) показывают только то, что уже лежит в системе в виде глав, абзацев, страниц и сносок. Кто-то должен превратить файл учебника в такую структуру, проверить лицензию и качество текста и не сломать ссылки на абзацы, когда источник обрабатывается заново. На эту структуру опираются поиск, ассистент и онтология, поэтому конвейер источника — первое, что нужно сделать на этапе 2 [roadmap.md](../../../docs/product/roadmap.md). Позже на этот же конвейер ляжет загрузка своих материалов пользователями (system design, блок 5).

## What Changes

- Регистрация источника: описание, лицензия с основанием и разрешениями, вид, область видимости, проверка на дубликаты.
- Версии источника: каждая обработка создаёт новую версию, читатели видят опубликованную, пока новая не будет готова целиком.
- Конвейер обработки по шагам с состояниями: получение файлов, извлечение текста, проверка качества, разбор структуры, автоматические проверки, публикация. Продолжение с места сбоя, повторный запуск без побочных эффектов, журнал и стоимость каждого запуска.
- Проверка качества текста: автоматические метрики для распознанных сканов и для готового текстового слоя, просмотр выборки страниц человеком, решение принять или отложить, эталонные страницы для оценки распознавания.
- Единая структура документа для всех форматов: разделы с видами (основной текст, предисловие, библиография, указатель и т. д.), абзацы с языком и видом, сноски, страницы печатного издания.
- Устойчивые идентификаторы абзацев: сопоставление со старой версией при повторной обработке, перенаправление при разбиении и слиянии, записи об удалённых абзацах.
- Ручные правки структуры и текста, которые не теряются при повторной обработке.
- Снятие с публикации и удаление источника.
- События для следующих конвейеров (индексация, наполнение онтологии) со списком добавленных, изменённых и удалённых абзацев.

Не входит: индексация и наполнение онтологии (отдельные изменения этапов 3 и 4), загрузка материалов пользователями через интерфейс (после первой версии), поиск источников в интернете.

## Capabilities

### New Capabilities

- `source-registry`: учёт источников: описание, лицензия и разрешения, вид, область видимости, версии, публикация, снятие с публикации и удаление.
- `source-processing`: конвейер обработки версии источника: шаги, состояния, перезапуск, параллельность, журнал, стоимость, события для следующих конвейеров.
- `text-quality-check`: проверка качества извлечённого текста: метрики, выборка страниц для человека, решение, эталонные страницы.
- `document-structure`: структура документа, в которую приводится любой источник, правила разбора, устойчивые идентификаторы абзацев и ручные правки.

### Modified Capabilities

Нет: в `openspec/specs/` пока нет спецификаций. Требования к устойчивым ссылкам в `chapter-reading` из [add-library-and-reading](../add-library-and-reading/specs/chapter-reading/spec.md) этим изменением выполняются, а не меняются.

## Impact

- Новая офлайн-задача «обновление источников» и рабочее место оператора: команды конвейера и внутренняя страница проверки качества, закрытая паролем, как страница проверки онтологии.
- Сервис библиотеки: хранит источники, версии, структуру, правки и записи об удалённых абзацах; отдаёт только опубликованные версии.
- Хранилище файлов для исходных файлов и изображений страниц.
- Очередь задач: события о публикации, обновлении и снятии источника.
- Сервис LLM, если шаг разбора использует модель: через него идут все вызовы, расход учитывается в бюджете наполнения.
- Позже от событий зависят индексация и онтология: подтверждения утверждений, указывающие на удалённые абзацы, они обрабатывают у себя.
- [system-design.md](../../../docs/product/system-design.md), блок 5: список состояний источника уточняется под версии.
