# Прослеживаемость до сценариев и журнала, снимки в CI

## Зачем

Аудит 2026-11-19 (раздел 4.1, пункты 4.a, 4.c, 4.d, 4.e, 4.g, 1.9) показал, что зелёный CI говорит меньше, чем кажется:
- `check_traceability.py` сверяет только пару «возможность, требование»: сценарии не разбирает, тело теста не смотрит, нерешённые маркеры молча пропускает, засчитывает вложенные функции, не знает, выполнился ли тест;
- журнал проверяют тесты только у 45% требований, и это никто не считает;
- снимки экрана в CI не сравниваются: эталоны есть только для Windows;
- `openspec validate` в CI не запускается;
- фикстура стенда `site` скопирована в четыре e2e-модуля и меняет `os.environ` на весь прогон.

## Что меняется

- **Прослеживаемость до сценариев.** Маркер `req` принимает `scenario=`, `invariant=`, `nolog=`. Скрипт разбирает `#### Scenario:` под каждым требованием и печатает четыре строки итога: требования с тестами, сценарии с тестами, требования с проверкой журнала, нормативные тесты.
- **Новые режимы в `openspec/traceability.yaml`:**
  - `enforce_scenarios` — возможности, где непокрытый сценарий проваливает проверку;
  - `enforce_log` — возможности, где у каждого требования есть тест с проверкой журнала или с `nolog`.
  
  Пока списки пустые (режим отчёта). Включает ведущий, когда тестировщики расставят маркеры.
- **Строгость разбора.** Считаются только тесты, которые соберёт pytest. Нерешённый маркер, маркер не на тесте, неизвестный параметр, опечатка в `scenario=` — ошибки.
- **`--report`** печатает непокрытое по возможностям и события каталога, которые не проверяет ни один тест. **`--junit`** сверяет, что помеченные тесты выполнились и не пропущены.
- **Снимки в CI.** Эталоны для Linux; с `PHILOGRAPH_REQUIRE_SNAPSHOTS=1` отсутствие эталона проваливает тест. Ручной запуск в GitHub пересобирает эталоны Linux в образе CI.
- **`openspec validate --all`** — шаг CI.
- **Одна фикстура стенда** `site` на прогон в `tests/e2e/conftest.py`. Окружение меняется только на время запуска процессов стенда.

## Возможности

- `service-runtime` — изменено требование «Прослеживаемость требований тестами».
- `visual-design` — изменено требование «Визуальная проверка»: без эталона в CI тест падает.

## Влияние

- Код продукта не меняется. Меняются `scripts/check_traceability.py`, `openspec/traceability.yaml`, `tests/e2e/conftest.py`, `tests/e2e/visual.py`, эталоны `tests/e2e/visual/baselines/linux/`, новые шаги `.github/workflows/ci.yml`, новый `.github/workflows/snapshots.yml`.
- Тестировщики получают `--report` со списками непокрытых сценариев и требований без проверки журнала.
