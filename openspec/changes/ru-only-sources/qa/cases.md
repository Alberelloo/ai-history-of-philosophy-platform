# Кейсы: ru-only-sources

Каталог изменения: `openspec/changes/ru-only-sources/`. Покрыты группы 1–2 `tasks.md` (учёт
регионов, библиотека). Группы 3–8 (шлюз, поиск, ассистент, знания, внешняя обработка, оценка,
развёртывание) добавят свои UC/TC/EC по мере работы — здесь для них оставлены места.

Требования — `specs/source-registry/spec.md`, `specs/source-library/spec.md`,
`specs/chapter-reading/spec.md`, `specs/regional-access/spec.md`; решения — `design.md`.

## Требования

| REQ | Источник | Формулировка (SHALL) |
| --- | --- | --- |
| R1 | source-registry / «Виды лицензий как данные» | Вид лицензии хранит регионы показа; пусто или нет значения — «везде» |
| R2 | source-registry / «Виды лицензий как данные» | Регионы источника сужают регионы вида, но не расширяют; действующие регионы — пересечение |
| R3 | source-registry / «Виды лицензий как данные» | Пустое пересечение регионов равносильно запрету показа |
| R4 | regional-access / «Неизвестный регион закрывает ограниченные источники» | Сервис без региона обрабатывает запрос как из неизвестного региона; неизвестный регион закрывает источники с ограничением |
| R5 | regional-access / «Библиотека закрывает текст ограниченных источников» | Закрытый источник есть в списке строкой: название, авторы, пометка «доступен в РФ», `restricted: true`, `regions`; без года, описания и лицензии; открыть нельзя; не учебник по умолчанию, не текущий, не запомненный; поиск и фильтры работают |
| R6 | regional-access / «Ссылка на абзац закрытого источника» | Ссылка отвечает «источник недоступен» с причиной «регион», может называть название и авторов, не раскрывает текст, главу и раздел |
| R7 | regional-access / «Внутренние интерфейсы не фильтруют по региону» | Внутренний интерфейс версий и `published()` не теряют закрытые источники; `GET /internal/access?region=XX` отдаёт закрытые для региона идентификаторы |
| R8 | regional-access / «Смена регионов у опубликованного источника» | Смена регионов рассылается событием `source.access_changed` (при `change_license` и при синхронизации вида лицензии); повторная публикация не нужна |
| R9 | regional-access / «Внешняя обработка закрытых источников» | Внутренний ответ версии несёт `external_processing` (поле нужно группе 7; здесь только отдаётся) |

## Краевые случаи (EC)

| ID | Категория | Ситуация | Ожидаемое поведение | Приоритет |
| --- | --- | --- | --- | --- |
| EC-1 | Пустое значение | у вида и у источника регионов нет (`None`) | «везде»: `regions()` → `None`, источник открыт любому региону и без региона | высокий |
| EC-2 | Пустое значение | у вида `[]` (пустой список) | то же, что `None`: «везде» | высокий |
| EC-3 | Границы | источник `[RU]`, читатель без региона (`None`) | закрыт: `None` не совпадает ни с одним кодом | высокий |
| EC-4 | Границы | пустое пересечение: вид сузили до `[RU]`, а у источника было `[BY]` | нигде: `display: false`, скрыт из чтения, в списке строкой «доступен в РФ» | высокий |
| EC-5 | Формат | код региона в нижнем регистре (`"ru"`) | приводится к `"RU"`; сравнение регистронезависимо | средний |
| EC-6 | Ошибки | код не из двух латинских букв (`"RU1"`, `"РФ"`, `""`) | `RegistryError`, поле `regions` | средний |
| EC-7 | Права | источник не опубликован или `scope` не публичный | в списке нет вовсе (не строка `restricted`) | высокий |
| EC-8 | Права | лицензия запрещает показ (`display: false`, `blocked`) | в списке нет вовсе | высокий |
| EC-9 | Повтор | повторный `sync` без изменений регионов | событий `source.access_changed` нет | средний |
| EC-10 | Совместимость | миграция на базе версии 4 со старыми данными | столбцы добавлены, старые источники читаются как «везде» | высокий |
| EC-11 | Совместимость | старый код на новой базе (откат) | не падает: регионы в отдельных столбцах, не в JSON `license` | высокий |
| EC-12 | Служебное | `Reader.ALL_REGIONS` (индексация) | видит ограниченные источники; клиенту такое значение не приходит | высокий |
| EC-13 | Локаль | название и авторы в строке `restricted` не локализуются, пометка — из `i18n` | пометка на языке интерфейса, данные — как в источнике | низкий |
| EC-14 | Доступность | строка `restricted` без кнопки «Читать» | фокус не уходит в несуществующую кнопку; `aria`-описание пометки | средний |
| EC-15 | Повтор/конкурентность | два `change_license` подряд меняют регионы | последнее состояние в БД и в outbox; порядок событий сохраняется | средний |

## Как проверять

- Юнит-тесты: `.venv/Scripts/python -m pytest -q tests/library tests/library/catalog -m "not e2e"`.
- HTTP-слой: тесты `tests/library/test_regions_api.py` на `TestClient` с заголовком региона.
- Клиент: сборка `web` (`npm run build`) и `tests/web/test_region_restricted.py` (браузер).
- Не проверено здесь: настоящий CDN и шлюз (группа 3), поиск (группа 4), ассистент и знания
  (группы 5–6), внешняя обработка (группа 7) — их кейсы появятся в следующих раундах.

## Статус покрытия (группы 1–2)

Закрыто автотестами: TC-1…TC-16, EC-1, EC-2, EC-3, EC-4, EC-5, EC-6, EC-7, EC-8, EC-9, EC-10,
EC-12; клиент — TC-17.

Не автоматизировано (проверять на раунде тестировщика или вручную):

  откатом образа на стенде — группа 8.
- EC-13 (локаль пометки): пометка берётся из `i18n`, данные источника не переводятся.
- EC-14 (доступность): у пометки есть `title`, кнопки «Читать» в строке нет — проверить фокус
  и чтение скринридером в раунде тестировщика.
- EC-15 (два `change_license` подряд): порядок событий в outbox — по коду транзакции; отдельного
  теста нет.
