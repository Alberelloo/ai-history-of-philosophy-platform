# Proposal

## Why

П4 задания владельца (`PHILO-SPEC-ONTOLOGY.md`): на стенде 85 «персон».

- **Мусор, около 21:** `your Lordship`, `children`, `some`, `поэт`, `мальчик`, `blind mathematician`, `author of…`.
- **Дубли, около 15:**
  - `Berkeley`×3, `Сократ`×3, `Теэтет`×3;
  - `Hegel`×2, `Hume`×2, `Newton`×2, `Reid`×2, `Descartes`×2;
  - `Гомер`/`Омир`, `Горгий`/`Горгиас`.
- **Склейка, 1:** `Kepler and Des Cartes`.

Промпт не говорит, кто считается персоной. Слияние (`Entities.merge`) есть, но оно неполное:
- атрибуции с автором-сущностью (`who_kind="entity"`, `who=<удалённая>`) не переносятся;
- ключи перенесённых утверждений не пересчитываются, поэтому повторы после слияния не объединяются. Требование «повторные утверждения объединяться» в `ontology-entities` не выполнено;
- основные названия двух сущностей остаются основными: у одной сущности оказывается два основных `ru`;
- `primary.dates` не пересчитывается;
- портреты удалённой не переносятся.

## What Changes

- **Новая возможность `person-quality`.**
  - **«Качество персон».**
    - Персона создаётся только для названного лица. Сервер отклоняет местоимения, роли, описания, обращения, группы и склейки: правило `not_a_name` и стоп-список из `improve-extraction-naming`.
    - Промпт `ontology.extract` получает определение персоны с отрицательными примерами.
  - **«Слияние вариантов персоны».**
    - Элемент `entities` может назвать одно лицо несколькими написаниями, а они найдут две разные персоны («Locke» и «Локк»). Тогда сервер сливает их по проверяемому правилу `same_person`:
      - внешние QID не противоречат;
      - даты не противоречат;
      - есть доказательство тождества.
    - Остаётся та, у которой есть QID, иначе та, у которой больше утверждений. Основное русское название — «Локк», «Locke» — вариант.
    - Сомнительные пары идут в очередь проверки (`duplicate`), а не сливаются.
- **Изменённые требования `ontology-entities`.**
  - **«Слияние с перенаправлением»** переносит:
    - названия: основные удалённой становятся вариантами, если у оставшейся уже есть основное на этом языке;
    - утверждения: ключи пересчитываются, повторы сворачиваются в одно, атрибуции и подтверждения переносятся, согласие пересчитывается;
    - атрибуции с автором-сущностью;
    - внешние id;
    - упоминания;
    - портреты.

    Кроме того, оно пересчитывает `primary`. Отмена восстанавливает всё перечисленное.
  - **«Поиск дублей»** находит кандидатов ещё и по совпадению основных названий на любом языке и по одному QID.
- **Общее правило тождества** `knowledge/dedupe.py`: одно правило для извлечения и для миграции (`migrate-ontology-quality`).
- **Журнал:**
  - у `knowledge.entity.merged` новые поля: `statements`, `attributions`, `folded`, `reason`;
  - `knowledge.entity.merge_proposed` (новое): `kept`, `removed`, `reason` — пара в очереди проверки.

## Out of scope

- Чистка и слияние уже существующих персон стенда — `migrate-ontology-quality`. Здесь правило и механизм слияния, которые она переиспользует.
- Транслитерации без общего написания («Гомер»/«Омир», «Горгий»/«Горгиас»). Правило их автоматически не сливает. Их сливает подтверждение QID человеком в манифесте (`qid_confirmed`, `add-wikidata-life-dates`) или решение человека: общий QID у двух сущностей невозможен.
- Слияние не-персон. Механизм `merge` общий, а автоматическое правило в этом изменении — только для `person`.
- Удаление сущностей. Его в API нет и здесь не появляется.

## Вопросы владельцу (решены, см. progress.md)

1. Автослияние только при выполнении всех трёх условий правила `same_person`. Иначе — очередь проверки. Ложное слияние хуже дубля.
2. Кэш достройки графа (`graph_extensions`) удалённой сущности при слиянии удаляется: это кэш, он перестраивается по запросу. Отмена его не восстанавливает.
