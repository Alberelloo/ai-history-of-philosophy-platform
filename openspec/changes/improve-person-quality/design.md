# Design

## Контекст (факт кода)

- `Entities.merge(kept, removed)` переносит такие данные:
  - `names`;
  - `statements.subject` и `statements.object`;
  - `external_ids`;
  - `mentions`.

  Затем ставит `redirect_to` и пишет `merges.moved` (id перенесённого) для `undo_merge`. Чего она не делает:
  - **не трогает** `attributions.who` (`who_kind="entity"`), то есть атрибуции «так считает Кант»;
  - **не пересчитывает** `statements.key`. Ключ включает id концов (`Statements._key`), поэтому повтор после слияния не объединяется, а новое утверждение с оставшейся сущностью не найдёт старое;
  - **оставляет** два основных названия на одном языке;
  - **не пересчитывает** `primary` (`Statements._update_primary` живёт в `Statements`);
  - **не переносит** портреты (`portraits.entity_id`, `UniqueConstraint(entity_id, phash)`).
- `Entities.duplicate_candidates` — пары одного типа, у которых совпадает последнее слово нормализованного названия и равны `primary.dates`. Сравнение всех со всеми: O(n²), при 1889 сущностях около 1,8 млн пар.
- `ReviewQueue.resolve_duplicate` вызывает `entities.merge`.
- Из `improve-extraction-naming` берутся:
  - `naming.check_name` (`not_a_name`, стоп-список), действует при создании;
  - `EntityItems.resolve`, где кандидаты ищутся по всем написаниям элемента.

## Контракты

### `knowledge/dedupe.py` (новый)

```python
@dataclass(frozen=True)
class Verdict:  kind: Literal["merge", "review", "apart"]; reason: str
def same_person(a: Entity, b: Entity, *, paired_by_model: bool = False) -> Verdict
def choose_kept(a: Entity, b: Entity, counts: Mapping[str, int]) -> tuple[str, str]   # (kept, removed)
def clusters(entities: Iterable[Entity]) -> list[list[str]]   # для миграции: связные компоненты по правилу
```

`Entity` — `{id, type, names, primary, externals}`. Правило `same_person` проверяет по порядку:

1. **Разный тип** или **тип не `person`** → `apart:type`. Правило из этого изменения работает только для персон.
2. **Разные QID** (у обеих есть `wikidata`, значения различны) → `apart:qid`.
3. **Один QID** → `merge:qid`.
4. **Даты противоречат:** обе `primary.dates` есть, и интервалы начала `[earliest_start − 2, latest_start + 2]` не пересекаются, или так же не пересекаются интервалы конца → `review:dates`. Неопределённость учитывается: «V в. до н. э.» не противоречит «ок. 470 до н. э.».
5. **Доказательство тождества** → `merge:name` или `merge:model_pair`:
   - совпадает хотя бы одно *основное* нормализованное название (на любом языке);
   - или `paired_by_model`: один элемент `entities` дал оба написания, и каждое нашло ровно одну из двух сущностей.
6. **Совпадает только вариант** → `review:variant`. Пример: «Бэкон» у Фрэнсиса и Роджера.
7. Иначе → `apart:none`.

`choose_kept` выбирает оставшуюся по порядку:
- сущность с QID;
- иначе ту, у которой больше ссылок (утверждения как субъект и объект плюс атрибуции `who`);
- иначе меньший id.

`clusters` строит компоненты по `merge` для миграции. Индекс — по нормализованному основному названию и по QID, а не все пары: O(n · названий).

`Dedupe(statements, review).run(*, dry_run=False, run_id=None) -> {merged, proposed, apart}` — «запуск слияния вариантов» из сценариев. Он обходит персон по индексу и сливает пары с вердиктом `merge` через `merge_entities`, а пары `review` ставит в очередь. Сухой прогон только считает. Своего CLI у него нет: оператор запускает его шагом миграции (`migrate-ontology-quality`) или из юнит-кода. Слияния запуска записываются в `merges` с `run_id` в `moved.run_id`, чтобы миграция могла откатить их по запуску.

### `Statements.merge_entities(kept, removed, reason) -> merge_id` (новый, `statements.py`)

`Entities.merge` остаётся низкоуровневым переносом строк. Он дополняется переносом `attributions.who`, `portraits` и правилом основного названия. Свёртка и пересчёт живут в `Statements`, потому что ключ, согласие и `primary` принадлежат ему.

1. `Entities.merge` переносит:
   - названия: основное удалённой на языке, где у оставшейся уже есть основное, становится `variant`; прежний вид пишется в `moved.kinds`. Точные повторы названий `(lang, normalized)` не дублируются: строка удалённой переносится, но получает вид `variant`;
   - `statements.subject` и `statements.object`;
   - `external_ids`;
   - `mentions`;
   - `attributions.who`, где `who_kind="entity"` и `who=removed` (`moved.attributions_who`);
   - `portraits`. При конфликте уникальности (одинаковый `phash`) портрет удалённой остаётся за ней, это записывается в `moved.portraits_kept`.

   Кэш `graph_extensions` удалённой удаляется.
2. Для каждого перенесённого утверждения ключ пересчитывается (`_key`). Старый ключ пишется в `moved.keys`.
3. Если новый ключ совпал с ключом другого действующего утверждения (`survivor`), выполняется **свёртка**:
   - атрибуции и подтверждения повтора переносятся на `survivor`; точные повторы атрибуции `(who_kind, who, stance)` не дублируются, а помечаются в `moved.folded[].skipped`;
   - полная строка повтора сохраняется в `moved.folded[].row`, сама строка удаляется;
   - согласие `survivor` пересчитывается, в журнал утверждения (`journal`) пишется запись «свёрнуто при слиянии».
4. `_update_primary(kept, "lifespan" | "dating" | "description")`.
5. Событие `knowledge.entity.merged` с полями `kept`, `removed`, `reason`, `statements`, `attributions`, `folded`.

`Statements.undo_merge(merge_id)` выполняет шаги в обратном порядке:
- восстанавливает строки свёрнутых утверждений;
- возвращает атрибуции и подтверждения на них;
- возвращает ключи, виды названий, `attributions.who`, портреты;
- вызывает `Entities.undo_merge`;
- пересчитывает `primary` обеих сущностей.

`ReviewQueue.resolve_duplicate` вызывает `Statements.merge_entities` вместо `entities.merge`. Отдельной копии правила нет.

### Точка в извлечении

В `EntityItems.resolve` (из `improve-extraction-naming`) разбирается случай, когда написания элемента нашли больше одного кандидата-персоны:
- для каждой пары вызывается `same_person(..., paired_by_model=True)`, но только для пар, где разные написания элемента нашли разные сущности;
- все пары дали `merge` → `merge_entities` по `choose_kept`, привязка — к оставшейся;
- есть `review` → пункт очереди `duplicate` (`payload.pair`, `payload.reason`), событие `knowledge.entity.merge_proposed`, утверждение уходит по прежней логике неоднозначности;
- `apart` → прежняя логика неоднозначности.

`filling.py` для этого не меняется: точка вызова уже в `EntityItems`.

### Промпт (файл Lead'а, О3)

`ontology.extract` получает абзац: «Персона (`person`) — только названное по имени лицо. Не персона: местоимения, обращения (your Lordship), роли и описания (поэт, blind mathematician, the author of …), группы (children, logicians), неодушевлённое. Два лица — два элемента, не одно». Правку промпта согласует Lead (5.1).

## События журнала

| Событие | Уровень | Поля | Когда |
|---|---|---|---|
| `knowledge.entity.merged` (есть, поля расширены) | info | `kept`, `removed`; новые — `reason` (`qid`, `name`, `model_pair`, `review`, `migration`), `statements` (перенесено), `attributions` (перенесено `who` + атрибуций свёрнутых), `folded` (свёрнуто утверждений) | слияние |
| `knowledge.entity.merge_undone` (есть) | info | `kept`, `removed`; новые — `restored` (восстановлено свёрнутых) | отмена |
| `knowledge.entity.merge_proposed` (новое) | info | `kept`, `removed`, `reason` (`dates`, `variant`) | пара в очередь проверки |
| `knowledge.entity.rejected` (из `improve-extraction-naming`) | warning | `type`, `label`, `reason` | мусорная персона |

Новые поля `knowledge.entity.merged` добавляются в `optional`, `required` прежний: старые вызовы `Entities.merge` событие не ломают.

## Выбор решения

### Слияние вариантов

| Вариант | Оптимальность | Архитектура | Поддержка и масштаб |
|---|---|---|---|
| А. Только очередь проверки: каждая пара — человеку | Ноль автоматики, человек на ~15 пар | Правильно, но А4 = 0 зависит от ручной работы | При 10× источников — сотни пар вручную |
| Б. Слияние по совпадению последнего слова (как `duplicate_candidates`) | Просто | Ложные слияния: Бэконы, Миллы | Ошибки тихие, откат ручной |
| В. Правило `same_person` (QID, основные названия, пара от модели, даты) + очередь для сомнительного (выбрано) | Индекс по названиям и QID, O(n) | Одно правило в `dedupe.py` для извлечения и миграции; модель предлагает пару, код проверяет QID и даты | Порог дат и виды доказательств — константы правила; любое слияние откатывается |

**Выбрано В.** Платим тем, что «Гомер»/«Омир» без общего QID остаются в очереди. Костыли, которых избегаем: слияние по подстроке, второе правило тождества в миграции, тихое слияние без события.

### Где свёртка утверждений

| Вариант | Оптимальность | Архитектура | Поддержка и масштаб |
|---|---|---|---|
| А. Не сворачивать, скрывать повторы в снимке по содержимому | Без записи в базу | Правило объединения повторов размазано по снимку, карточкам и графу | Каждый новый потребитель должен помнить про повторы |
| Б. Свёртка в `Statements.merge_entities` с архивом строки в `merges.moved` (выбрано) | Одна транзакция на слияние | Ключ, согласие и `primary` у их владельца (`Statements`); `Entities.merge` остаётся переносом строк | Отмена полная по архиву; формат `moved` расширяется ключами, старые записи отменяются как прежде (`get` с умолчаниями) |

## Генераторы для property-тестов (О7)

Генераторы лежат в `tests/knowledge/strategies.py` (общий файл с `improve-extraction-naming`).

- `persons_with_variants()` — кластеры 1–4 сущностей одного лица:
  - написания ru/en/транслит, регистр;
  - QID: общий, разные или нет;
  - даты: равные, в пределах 2 лет, противоречащие или нет.
- `ontology_with_duplicates()` — 5–30 сущностей и 0–60 утверждений между ними:
  - атрибуции `source`, `entity` (в том числе на дубль), `common`;
  - подтверждения;
  - повторы утверждений, которые совпадут после слияния;
  - упоминания;
  - портреты с одинаковым `phash`.
- `not_persons()` — роли, обращения, группы, местоимения, склейки `A and B`/`А и Б` (переиспользует `not_names`).

## Инварианты, которые доказывают тесты

- **Сохранение при слиянии.** Для любой онтологии и любой пары множество троек `(resolve(subject), type, resolve(object), value, qualifiers)` до и после слияния одинаково. Мультимножество атрибуций `(тройка, who_kind, resolve(who), stance)` не теряет элементов, кроме точных повторов на одном утверждении. Подтверждения сохраняются полностью.
- **Отмена.** После `undo_merge` дамп таблиц `names`, `statements`, `attributions`, `evidence`, `external_ids`, `mentions`, `portraits`, `entities` равен дампу до слияния. Исключение — порядок строк и кэш `graph_extensions`.
- **Одно основное.** После слияния у сущности не больше одного основного названия на язык.
- **QID.** Сущности с разными QID никогда не сливаются автоматически; общий QID после слияния один и принадлежит оставшейся.

## Риски

- Свёртка удаляет строку утверждения, и ссылки на её id снаружи (`statement_views`, `review_samples`, `journal`) повиснут. Поэтому при свёртке выполняется перенаправление: в `merges.moved.folded[].into` хранится `survivor`, а `Statements.get` по свёрнутому id отдаёт `survivor`. Так же устроены перенаправления сущностей: старая ссылка работает.
- Допуск дат 2 года на краях интервалов неопределённости — константа правила. Слишком строгий допуск отправит в очередь персону с годами «1632–1704» и «1632–1705» из разных учебников. Поэтому допуск ненулевой.
