# Spec Delta

## Purpose

Описывает схему онтологии как данные: какие бывают сущности, связи, уточнители и рецепты обхода. Новый тип добавляется записью в реестр, а не изменением кода.

## ADDED Requirements

### Requirement: Типы сущностей в реестре

Реестр SHALL содержать типы сущностей с названием, описанием, родительским типом и набором допустимых значений-свойств. Начальный набор: термин, понятие, концепция, учение, проблема, позиция, аргумент, персона, группа, произведение, событие, идейное событие, явление, эпоха, место. Идейное событие SHALL быть подтипом события.

#### Scenario: Подтип

- **WHEN** запрашиваются все события
- **THEN** в ответе есть и идейные события

### Requirement: Типы связей в реестре

У типа связи в реестре SHALL быть: название и обратное название, допустимые типы субъекта и объекта, родительский тип, симметричность, транзитивность, семейства (генезис, последствия, полемика, структура, контекст, лексика, биография), допустимые уточнители, описание и правила для LLM, способ показа, признак «входит в v0».

#### Scenario: Обратное название

- **GIVEN** тип «испытал влияние» с обратным названием «повлиял на»
- **WHEN** карточка Юма показывает утверждение «Кант испытал влияние Юма»
- **THEN** в карточке Юма оно читается как «повлиял на Канта»

### Requirement: Иерархия связей

Запрос по типу связи SHALL включать утверждения всех его подтипов. Начальная иерархия влияния: «испытал влияние» с подтипами «учился у», «заимствует у», «развивает», «переосмысляет», «критикует», «защищает», «синтезирует», «написано в ответ на».

#### Scenario: Общий запрос

- **GIVEN** утверждения «Кант критикует Юма» и «Кант развивает Лейбница»
- **WHEN** запрашиваются все утверждения «Кант испытал влияние»
- **THEN** возвращаются оба

### Requirement: Уточнители в реестре

Реестр SHALL описывать уточнители: название, вид значения (нечёткий интервал, сущность заданных типов, место в произведении, значение из списка), список допустимых значений. Начальный набор: время действия, произведение и место, аспект, полярность, путь, механизм, тип ответа, основание принадлежности, роль, подлинность, сила.

#### Scenario: Значение из списка

- **WHEN** у утверждения указан механизм «экономический»
- **THEN** значение принимается, потому что оно есть в списке механизма

### Requirement: Рецепты обхода в реестре

Реестр SHALL содержать рецепты обхода: допустимые типы стартовой сущности, семейства связей, направление, глубина, порядок результатов. Начальный набор: генезис, последствия, полемика, контекст, ответы на проблему, сравнение концепций, путь между двумя.

#### Scenario: Рецепт генезиса

- **WHEN** запрашивается рецепт «генезис»
- **THEN** он описывает преемственность назад, идейные события и лексику с глубиной 2–3 по времени

### Requirement: Добавление типа без изменения кода

Новый тип сущности, связи, уточнителя или рецепта SHALL добавляться записью в реестр и сразу использоваться проверками, запросами, извлечением и показом. Изменения реестра SHALL выполняться через проверку человеком: тип, предложенный моделью, MUST NOT применяться автоматически.

#### Scenario: Новая связь

- **WHEN** оператор добавляет тип связи «покровительствовал» с допустимыми концами
- **THEN** утверждения этого типа проходят проверку концов без изменения кода

#### Scenario: Предложение модели

- **WHEN** при извлечении модель предлагает новый тип связи
- **THEN** предложение попадает в очередь проверки, а утверждение записывается с ближайшим общим типом

### Requirement: Версии реестра

Каждое изменение реестра SHALL создавать новую версию. Удалить тип, которым пользуются утверждения, MUST NOT быть возможно: его можно только пометить устаревшим с указанием замены.

#### Scenario: Устаревший тип

- **WHEN** оператор помечает тип связи устаревшим с заменой на другой
- **THEN** новые утверждения этого типа не принимаются, а существующие остаются и показываются по замене

### Requirement: Схема вывода для LLM из реестра

Из реестра SHALL собираться инструкция и схема структурированного вывода для извлечения и достройки: какие типы допустимы, их описания, примеры и правила. Изменение реестра SHALL менять схему без правки шаблонов запросов.

#### Scenario: Схема для рецепта

- **WHEN** достройка запускается для рецепта «полемика»
- **THEN** схема вывода допускает только типы связей семейства «полемика»
