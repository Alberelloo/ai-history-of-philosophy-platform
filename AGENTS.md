# AGENTS.md

Инструкции для любого агента, который работает в этом репозитории. Подробный процесс — в [docs/process/working-principles.md](docs/process/working-principles.md); особенности Claude Code — в [CLAUDE.md](CLAUDE.md).

## Проект

**PhiloGraph** — интерактивный AI-учебник по истории философии, пилотный раздел «Теория познания».

Читатель:
- выбирает учебник и читает главу;
- открывает карточки философов, понятий и событий;
- смотрит синхронологическую карту раздела;
- спрашивает ассистента о выделенном месте.

Как устроено знание:
- **Онтология** (сущности и утверждения) хранит знание.
- **Поиск по абзацам** (RAG) находит тексты; онтология расширяет поиск.
- **Ассистент** отвечает только со ссылками на источники.
- Связи, которые достроила модель и не проверил человек, помечены в интерфейсе.

Продукт и план — в [docs/product/](docs/product/vision.md), поведение — в [openspec/specs/](openspec/specs/).

## Стек

Выбран в [ADR-0001](docs/architecture/adr/0001-stack.md).

- **Python 3.13:** FastAPI, SQLAlchemy 2, structlog.
- **Хранилища:** PostgreSQL 16 (в тестах — SQLite), Qdrant для векторов, очередь на PostgreSQL.
- **Модели:** через свой шлюз LLM на httpx.
- **Клиент:** React + TypeScript + Vite.
- **Запуск:** Docker Compose + Caddy.

Сервисы не импортируют внутренности друг друга, общее — только `platform`. Границы проверяет `lint-imports`.

## Команды

```bash
pip install -e ".[dev]"                     # зависимости и инструменты
python -m playwright install chromium       # браузер для tests/web и tests/e2e
cd web && npm ci && npm run build           # клиент (tsc + vite); нужен браузерным тестам

ruff check . && ruff format --check .       # стиль Python
lint-imports                                # границы сервисов
python scripts/check_traceability.py        # у каждого требования есть тест
pytest -q tests/<пакет>                     # тесты пакета
pytest -q                                   # всё (~25 мин; e2e поднимают продукт сами)
pytest -q -m "not e2e"                      # без сквозных

python scripts/dev_stack.py --demo          # весь продукт без Docker, демо-тексты; журналы в .stack/logs
python scripts/visual_check.py              # визуальная проверка по DOM и снимкам
```

E2E против системы в Docker: `docker compose -f compose.yaml -f compose.e2e.yaml up -d --build --wait`, затем `PHILOGRAPH_E2E_URL=http://127.0.0.1:8080 pytest -q tests/e2e`.

## Правила

- **OpenSpec.** Поведение меняется только через изменение в `openspec/changes/<имя>/`: сначала спецификация, потом код. Спецификация и код одного изменения — в одном PR. Подробно: [openspec-workflow.md](docs/process/openspec-workflow.md).
- **Роли.** Разработчик, тестировщик, ревьювер, судья. Цикл и что каждой роли нельзя — в [working-principles.md](docs/process/working-principles.md). Роль, которую ты выполняешь, указана в задаче. Если не указана, ты разработчик.
- **Выбор решения.** До кода в `design.md` записывается раздел «Выбор решения»: варианты по трём критериям — оптимальность, архитектурная правильность, поддерживаемость и масштабируемость. Костыли из списка в working-principles.md — повод вернуться к выбору.
- **Тесты.** У каждого требования есть сценарные тесты (`scenario=`) и, где есть правило, нормативные (`invariant=`), с маркером `@pytest.mark.req(возможность, требование, …)`. Каждый тест проверяет вывод и событие журнала. Ожидания не подгоняются под фактический вывод: расхождение — дефект кода или спецификации.
- **Подтверждение.** Тестировщик ведёт `verification.md` с сырыми результатами. Судья независимо прогоняет и сверяет. Без вердикта судьи PR остаётся в draft.
- **Журнал.** Новое поведение пишет событие из каталога событий (`platform`), без личных данных и без текста вопросов.
- **Модель предлагает, код проверяет.** Ответ модели не применяется без проверки сервером: схема вывода, допустимые значения, построение адресов и ссылок кодом.
- **Git.** Ветки `claude/<кратко>` (или `<агент>/<кратко>`), в `main` не пушить, заголовок PR `<тип>: <что сделано>`, описание по шаблону: что изменилось, зачем, как проверить. Спорное — draft-PR. Готовый PR сливается сам (squash), когда проходят `checks` и `pr-format`. Подробно: [git-workflow.md](docs/process/git-workflow.md).
- **Контрольные точки.** После каждого пункта `tasks.md`: отметка, запись в `progress.md`, коммит `wip(<имя>): …`, push. Прерванная работа продолжается с первого незакрытого пункта.
- **Язык.** Документы, спецификации, тексты интерфейса и сообщения коммитов — на русском. Код, идентификаторы и служебные слова OpenSpec — на английском.
- **Документы — источник правды.** Если план или решение поменялись, правится `docs/` в том же PR.

## Известные ловушки окружения

- **CLI `openspec`** ставится отдельно (npm, Node ≥ 22.12). Где его нет, перенос дельт и архив делаются вручную по скиллам `openspec-sync-specs` и `openspec-archive-change`.
- **Эталоны снимков экрана** есть только для Windows (`tests/e2e/visual/baselines/win32`). На Linux сравнение снимков пропускается, остаются проверки по DOM. Эталоны обновляет владелец: `python scripts/visual_check.py --update`.
- **`tests/ops/test_deploy.py`** требует плагин `docker compose`. Без него эти тесты падают на подготовке, к изменению это обычно не относится.
- **Полный `pytest` идёт около 25 минут.** Задание `checks` в CI — до 25 минут, поэтому во время работы гоняйте тесты затронутых пакетов.
