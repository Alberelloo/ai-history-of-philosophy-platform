# CLAUDE.md

Контекст проекта для Claude Code (в VS Code и в облачных сессиях). Подробности в [docs/](docs/README.md).

## О проекте

Интерактивный AI-учебник по истории философии. Учения изучаются через исторический, социальный и интеллектуальный контекст и связи между собой (влияние, критика, преемственность). Встроенный LLM-ассистент отвечает на вопросы студента с опорой на материалы учебника (RAG) и на граф связей «философ — школа — концепция».

Проблема: студент знает содержание отдельных учений, но плохо понимает, почему идея возникла, на что отвечала и как повлияла на дальнейшую мысль.

Рабочее название: PhiloGraph. Пилотный раздел пока условно «античная философия».

## Две цели, один код

1. **ВКР (трек Education, ИТМО)**: прототип плюс учебные материалы пилотного раздела, апробация на целевой аудитории, сравнение с традиционным форматом и аналитический отчёт. См. [docs/thesis/](docs/thesis/).
2. **Финальный проект курса по LLM-приложениям** (командный): оценивают дизайн решения, архитектуру кода, сквозной user path, измеренное качество на валидационном наборе, тесты, логирование и рабочий интерфейс. См. [docs/course/](docs/course/).

## Договорённости

- Источник правды по плану и требованиям лежит в `docs/`. Если план меняется, обновляем документы там же, чтобы локальная работа и облачные сессии видели одну версию.
- Изменения идут через ветки и PR в `main`, процесс описан в [docs/process/git-workflow.md](docs/process/git-workflow.md). Готовый PR сливается сам (squash), когда проходят проверки `checks` и `pr-format`.
- Claude не пушит в `main` напрямую. Ветки называет `claude/<кратко>`. Заголовок PR пишет по формату `<тип>: <что сделано>`, описание заполняет по шаблону (что изменилось, зачем, как проверить). Если изменение спорное и требует решения человека, PR открывается как draft.
- Код вычитываем: за явно сгенерированный «нейрослоп» на курсе снижают оценку.
