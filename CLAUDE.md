# CLAUDE.md

Контекст проекта для Claude Code (в VS Code и в облачных сессиях). Подробности в [docs/](docs/README.md).

## О проекте

Интерактивный AI-учебник по истории философии. Пользователь выбирает учебник, читает главу, открывает карточки понятий, философов и событий, строит граф связей по запросу и спрашивает LLM-ассистента о выделенном месте текста. Знания хранит онтология (сущности и связи), тексты ищет RAG, онтология расширяет поиск. Связи, достроенные LLM и не проверенные человеком, в интерфейсе помечены. Ассистент отвечает со ссылками на источники.

Проблема: учебник задаёт одну авторскую парадигму, материал разрознен, а связи между учениями и контекст эпохи читателю приходится восстанавливать самому.

Рабочее название: PhiloGraph. Пилотный раздел: теория познания. Стек не выбран, его определим после спецификаций. Что в первой версии и что отложено (например, пометки об однобокости подачи) в [docs/product/vision.md](docs/product/vision.md), устройство в [docs/product/system-design.md](docs/product/system-design.md), этапы в [docs/product/roadmap.md](docs/product/roadmap.md).

## Договорённости

- Источник правды по продукту и плану лежит в `docs/`. Если план меняется, обновляем документы там же, чтобы локальная работа и облачные сессии видели одну версию.
- Фичи ведём по spec-driven подходу OpenSpec: сначала спецификация в `openspec/`, потом реализация. Правила в [docs/process/openspec-workflow.md](docs/process/openspec-workflow.md). Спецификации описывают поведение, продуктовое обоснование остаётся в `docs/product/`.
- Изменения идут через ветки и PR в `main`, процесс описан в [docs/process/git-workflow.md](docs/process/git-workflow.md). Готовый PR сливается сам (squash), когда проходят проверки `checks` и `pr-format`.
- Claude не пушит в `main` напрямую. Ветки называет `claude/<кратко>`. Заголовок PR пишет по формату `<тип>: <что сделано>`, описание заполняет по шаблону (что изменилось, зачем, как проверить). Если изменение спорное и требует решения человека, PR открывается как draft.
- Код вычитываем: сгенерированное без проверки в `main` не попадает.
