# Работа с Git и PR

## Поток

1. Ветка от свежего `main`: `<автор>/<кратко-о-задаче>`, например `daniil/rag-chunking`. Ветки Claude начинаются с `claude/`.
2. Коммиты в ветке как удобно, в `main` они схлопнутся в один.
3. PR в `main` по шаблону. Сразу после открытия включается автослияние.
4. CI проверяет PR. Когда проверки зелёные, GitHub сам делает squash-слияние и удаляет ветку.
5. Если проверка упала, чиним в той же ветке, PR сольётся после следующего зелёного прогона.

Чтобы PR не слился сам (нужно обсуждение или ревью), открывайте его как draft. Автослияние включится, когда PR переведут в «Ready for review». Уже включённое автослияние отключается кнопкой в PR или командой `gh pr merge --disable-auto <номер>`.

## Заголовок и описание PR

Заголовок и описание становятся сообщением коммита в `main`, поэтому история читается по ним.

Заголовок: `<тип>: <что сделано>`, по-русски, без точки в конце. Можно указать область в скобках: `feat(rag): поиск по главам`.

| Тип | Когда |
|---|---|
| `feat` | новая возможность |
| `fix` | исправление ошибки |
| `docs` | документы, README |
| `refactor` | переделка без изменения поведения |
| `test` | тесты |
| `ci` | CI, автоматизация репозитория |
| `chore` | зависимости, конфиги, мелочи |
| `data` | корпус текстов, разметка графа |
| `eval` | валидационный набор, метрики |

Описание по шаблону, коротко:

- **Что изменилось**: список изменений по сути, не пересказ диффа.
- **Зачем**: какую задачу или пункт плана закрывает.
- **Как проверить**: команда, сценарий в интерфейсе или «только документы».

## Что проверяет CI

| Проверка | Что делает |
|---|---|
| `checks` | ищет секреты в истории (gitleaks), битые ссылки в Markdown; при наличии `pyproject.toml` запускает `ruff check`, `ruff format --check` и `pytest` |
| `pr-format` | формат заголовка PR и непустое описание |

Обе проверки обязательны для слияния. Ревью не обязательно. Если команда захочет обязательное ревью, поднимите `required_approving_review_count` в [scripts/setup-github.sh](../../scripts/setup-github.sh) и перезапустите скрипт.

## Первичная настройка репозитория

Один раз, человеком с правами администратора:

```bash
gh auth login
bash scripts/setup-github.sh
```

Скрипт разрешает автослияние, оставляет только squash с сообщением из PR и защищает `main`: прямой push запрещён, слияние только после зелёных проверок. Администраторы могут обойти защиту в аварийном случае.
