# Задача: переизвлечение онтологии связей — извлекает сам Claude на умной модели

Статус: **в очереди** — после `polities` и аудита (сервер 1 CPU, не параллелить тяжёлое).
Исполнитель — Claude (прораб — умная модель; субагенты по ролям).

## 1. Контекст (диагноз на 26.11.2026)

Данных достаточно: **209 источников, 63 558 абзацев**. Проблема — извлечение связей:

- Создано 1099 утверждений, отброшено **20 557** (~95%).
- Из 817 запусков извлечения **639 — «running»** (брошены), 30 источников не извлекались.
- Книги о Ницше: 6 источников, **created=0, dropped=1647** (у «Заратустры» одной 1218 отброшено).
- Персон всего 62 (из «удачных» источников), Ницше нет.

Вероятные причины (проверить): отбраковка по цитате (модель пересказывает), ссылка на абзац вне фрагмента, несоответствие типов концов, слишком крупные/мелкие фрагменты.

## 2. Что должен сделать Claude

### 2.1. Разобраться сам (собрать контекст, найти точки улучшения)

1. Перезапустить извлечение на 2–3 проблемных источниках (**«Так говорил Заратустра»**, **«Философия Ницше. Критический очерк»**) с **полным логированием причин отбраковки** (`knowledge.extraction.dropped` с `reason`) и посмотреть, что именно падает.
2. Прочитать валидацию в `src/philograph/knowledge/filling.py` (`_fit`, проверка цитаты, диапазон абзаца, концы типов), промпт `ontology.extract`, схему вывода.
3. Найти **потенциальные точки улучшения** (не ограничиваясь списком): размер фрагмента, проверка цитаты (пересказ vs дословно), резолвинг типов, именование сущностей, дедуп, обработка литературных текстов.
4. Зафиксировать выводы в `docs/audit/extraction-diagnosis.md`.

### 2.2. Составить полную спеку

OpenSpec-change «переизвлечение и качество извлечения»: требования, сценарии, инварианты, план переизвлечения, метрики. Планирование — до кода.

### 2.3. Пайплайн

Прораб (умная модель) + субагенты (coder, tester, reviewer, judge). На **каждое** требование — исполняемая проверка-инвариант; матрица «требование → тест» в `verification.md`.

### 2.4. Извлечение связей — САМ CLAUDE на умной модели

Извлечение утверждений (связей) выполняет **сам Claude на умной модели** (Opus), **не** LLM-шлюз с deepseek. Переизвлечение — **на ВСЕХ 208 источниках заново** (полный перебор всех данных с нуля), а не только на проблемных книгах о Ницше: проблемные источники из п. 2.1 — лишь для диагностики причин отбраковки.

- Claude читает фрагменты источника и формирует утверждения по схеме реестра (subject/type/object/paragraph/quote) — своим рассуждением.
- Код проверяет и записывает (та же валидация, что у filling), но **источник вывода — Claude**.
- Для объёма — субагенты Claude (по подмножествам источников), прораб сводит.
- Разрешено использовать существующий код извлечения/валидации как библиотеку, но генерация утверждений — Claude.

### 2.5. Явное сохранение «чем извлекал» и метрик

В каждом запуске извлечения SHALL явно сохраняться:

- **модель-извлекатель**: `filling_runs.model` = явный идентификатор (например `claude-opus`), а не `deepseek-v4-pro`;
- **метрики**: длительность (сек/мин на источник и всего), число фрагментов, токены (in/out), **стоимость** (по тарифу модели), число created/dropped и **причины** отбраковки;
- сводный отчёт — в `docs/audit/extraction-run-YYYY-MM-DD.md` (таблица по источникам: модель, время, токены, стоимость, created/dropped).
