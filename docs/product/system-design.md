# System design

Рабочий документ. Обновлён 01.11.2026 по итогам обсуждения. Исходит из [видения](vision.md). Стек не выбран: сначала архитектура, технологии выбираем из неё. Пилотный раздел: теория познания.

## 1. Принятые решения

| # | Решение | Почему |
|---|---|---|
| D1 | Пилотный раздел: теория познания | лучший баланс доступных источников и ясной логики связей (рационализм, эмпиризм, Кант) |
| D2 | Разметку каждого абзаца не делаем | избыточна по стоимости и проверке |
| D3 | Знания о предметной области хранит **онтология** (сущности и связи), тексты ищем через **RAG**; онтология участвует в каждом запросе и улучшает поиск | поиск по смыслу сам не знает, что «опыт» и «чувственное восприятие» связаны; онтология знает |
| D4 | Граф строится по запросу обходом связей онтологии | граф зависит от сущности и направления, готовым в карточке его не хранить |
| D5 | Если связи нет в онтологии, LLM достраивает её по собственным знаниям, и такие связи в интерфейсе помечены как сгенерированные и непроверенные | полнота важнее, но обман о надёжности недопустим |
| D6 | Пометки «автор подаёт однобоко, есть распространённая альтернатива» в базовую версию не входят | оценочное суждение, трудно сделать надёжно; вернёмся, когда будет работающий прототип |
| D7 | Содержимое онтологии (типы сущностей и связей) и способ её наполнения обсуждаем отдельно | |

## 2. Путь пользователя (базовая версия)

1. Выбирает учебник из библиотеки.
2. Читает главу как обычный текст.
3. Термины, личности и события кликабельны. Нажатие открывает карточку: у понятия происхождение слова, кто к нему обращался, с чем связано; у философа биография, связи, основные работы.
4. Из карточки или по запросу («понятие причинности») просит построить граф: откуда идея, кто её использовал, в какую сторону. Узлы и связи из онтологии показаны как проверенные, достроенные LLM выделены.
5. Выделяет непонятное место и задаёт вопрос ассистенту. Ответ со ссылками на абзацы источников. По явной просьбе ассистент рассказывает, как об этом пишут другие авторы библиотеки.

## 3. Две части знаний

```
Онтология                         Тексты (RAG)
сущности и связи между ними   ←→   учебники → главы → абзацы
(философы, понятия, ...)          поиск по смыслу и по словам
```

Они не размечены друг с другом абзац за абзацем. Связь идёт через запрос: из запроса находим сущности онтологии, берём их окружение и используем при поиске по текстам. Для кликабельных терминов в тексте нужен список названий каждой сущности (включая варианты написания и переводы), по нему термины находятся автоматически, без LLM и без ручной разметки.

## 4. Компоненты

```
            offline                             online
 источники ──▶ Ingestion ──▶ Индекс текстов ◀── Assistant service ◀─┐
                              (абзацы, поиск)      │  ▲               │
 наполнение ──▶ Онтология ◀──────────────────────────┘  │              │
 онтологии     (сущности,  ◀── Entity/Graph service ◀───┘  Веб-клиент ◀──▶ API
               связи)
```

| Компонент | Ответственность |
|---|---|
| **Ingestion** | прочитать источник, очистить, разбить на главы и абзацы, сохранить метаданные и лицензию |
| **Индекс текстов** | хранение абзацев и поиск по ним (по смыслу и по ключевым словам) |
| **Онтология** | сущности, их названия на разных языках, связи с типом и источником (проверена человеком или сгенерирована LLM) |
| **Entity/Graph service** | карточка сущности, обход связей в заданном направлении и на заданную глубину, достройка недостающих связей LLM |
| **Assistant service** | ответ на вопрос по выделенному месту (раздел 5) |
| **API** | граница между клиентом и сервисами, валидация, обработка ошибок |
| **Веб-клиент** | выбор источника, чтение, кликабельные термины, карточки, граф, панель ассистента |
| **Eval harness** | прогон валидационного набора по тем же сервисам, что использует API |

## 5. Поток запроса ассистенту

1. Вход: вопрос, выделенный фрагмент, источник и абзац.
2. Находим в фрагменте и вопросе сущности онтологии.
3. Берём окружение сущностей: синонимы, переводы, родственные и противопоставленные понятия, связанных философов.
4. Ищем по текстам с расширенным запросом. По умолчанию в основном источнике, в режиме «как пишут другие» во всей библиотеке.
5. LLM отвечает только по найденным абзацам и указывает ссылки на них.
6. Код проверяет, что ссылки указывают на реальные найденные абзацы. Если подходящих абзацев нет, ассистент так и говорит, а не отвечает из общих знаний модели.

## 6. Поток запроса графа

1. Распознаём сущность и направление в запросе («как появилась причинность», «кто критиковал Юма»).
2. Находим сущность в онтологии. Если её нет, она создаётся как сгенерированная LLM.
3. Обходим связи нужных типов в нужную сторону на заданную глубину.
4. Если связей мало или их нет, LLM достраивает недостающие. Эти связи помечены в интерфейсе как сгенерированные.
5. Для каждой связи, где возможно, достаём подтверждающие абзацы из текстов и показываем рядом.
6. Клиент рисует граф. Проверенные и сгенерированные связи визуально различаются.

## 7. Оценка качества

| Что | Метрика |
|---|---|
| Поиск с онтологией и без неё | recall@k на вопросах с размеченными релевантными абзацами. Прямое сравнение показывает, что онтология даёт |
| Ответ ассистента | faithfulness, корректность ссылок, доля корректных отказов |
| Связи, достроенные LLM | доля подтверждённых при ручной проверке выборки |
| Система целиком | задержка и стоимость одного ответа |

## 8. Сквозные требования

- Логирование каждого вызова LLM: промпт, ответ, переданные абзацы, модель, задержка, токены.
- Недоступность LLM не должна ломать чтение и карточки сущностей.
- Источник и лицензия видны всегда, показываем только разрешённое лицензией.
- Запуск целиком одной командой.

## 9. Открытые вопросы

1. **Онтология: что в ней хранится** (типы сущностей и связей) и **как наполняется** (вручную, LLM с проверкой, из открытых баз вроде Wikidata). Следующая тема обсуждения.
2. Откуда карточка берёт биографию, этимологию и события эпохи: из онтологии, из открытых баз или генерируется.
3. Для связей, достроенных LLM: опирается ли LLM только на собственные знания или получает ещё найденные абзацы для сверки.
4. Включать ли в онтологию связи, которые LLM достроил по запросу пользователя, чтобы в следующий раз не генерировать заново, и как пометить, что они не проверены.
5. Технологический стек: после того, как договоримся об онтологии.
6. Возврат к пометкам об однобокости после прототипа (D6).
