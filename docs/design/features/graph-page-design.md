# ТЗ дизайна страницы «Граф» — «Атлас на столе философа»

Версия: **Ф0.2 / 1.0**, 2026-11-14.
Статус: **арт-дирекция одобрена концептуально; численные параметры и макет — на проверку**.
Область: следующий HTML-макет и визуальный контракт будущей страницы. Это не разрешение
реализовывать продуктовую фичу до одобрения макета и OpenSpec-дельты.

## 0. Как исполнять ТЗ

- «MUST / MUST NOT» — обязательное условие; «SHOULD» — допускает отклонение только с
  письменным обоснованием и согласованием. Числа в таблицах — целевые значения, не идеи.
- Все размеры ниже — CSS px при базовом 16px, масштаб графа z=1. В реализации переводить
  размеры интерфейса в rem; не отключать масштаб браузера. Геометрия SVG может быть в px.
- При конфликте: правдивость данных и доступность → спецификация поведения → это ТЗ для
  локальной композиции графа → общая дизайн-система → референсы. ТЗ НЕ отменяет спецификацию.
- Менять палитру, семантику знака, метафору или состав первого экрана без обновления этого
  документа MUST NOT. «Сделать красивее на своё усмотрение» — не допустимая причина.
- Геометрию предметных знаков, цвета и статусы MUST задавать централизованно, не внутри
  отдельных демонстрационных узлов. Тема переключает токены, а не подменяет второй макет.
- Неоднозначность фиксировать как вопрос; не закрывать её декоративным изобретением.

### Инструкция модели-исполнителю

1. Полностью прочитать это ТЗ и cases.md, не ограничиваться общим описанием метафоры.
2. Перед HTML/CSS подготовить четыре фиксированных набора F1–F4 и список используемых
   локальных материалов/лицензий. Не подменять сложные наборы шестью одинаковыми кружками.
3. Собрать геометрию в grayscale без фактуры; проверить GD-02 и TC-01–05. Только после
   этого применять палитру, портреты и материал. Декор не исправляет плохую композицию.
4. Создать таблицу соответствия «GD → компонент/токен/состояние preview → TC» в отчёте.
   Любой нереализованный MUST — открытый пункт, не творческое отклонение.
5. Выполнить предусмотренные действия и снимки; просмотреть каждую тему и состояние.
   Недоступную проверку отметить not-tested с причиной. Не менять кейсы ради pass.
6. Передать макет независимому тестировщику/верификатору; исправлять по finding ID.
7. Сдать владельцу сравнение Ф0/Ф0.2, ключевые кадры и список отклонений. Продуктовый код
   и общую дизайн-систему не менять в рамках задания на макет.

## 1. Замысел и ограничения

**GD-01. Образ.** MUST восприниматься как единый раскладной лист научного атласа на столе,
а не дашборд с бумажным фоном. Главный объект — сеть знаний, не имитация мебели.

Три плана, в порядке от заднего к переднему:

| Объект | Обязательная реализация образа | Чего нет |
|---|---|---|
| Desk / основание | Матовая однотонная периферия, мягкий свет сверху слева | Фото дерева, предметы натюрморта, параллакс |
| Folio / лист | Одна непрерывная поверхность, два нижних края, направленная тень | Рамка вокруг графа, корешок через сеть, свиток |
| Print / печать | Текст, знаки, связи, шкала и маргиналии прямо на листе | Стеклянные карточки, глянец, свечение |

MUST NOT: жёлтый состаренный пергамент, рваные/обгорелые края, барочный орнамент,
перо/свеча/череп, 3D-поворот листа, неон, постоянные частицы. Допустима одна короткая
типографическая линейка; отдельные украшения в углах листа не добавлять.

## 2. Геометрия и композиция

**GD-02. Раскладка.** Пусть W — ширина viewport, S — фактическая занятая ширина навигации
(56 или 280 по [Sidebar](../system/components/Sidebar.md)), A=W−S. Breakpoint выбирается
**по A**, чтобы закрепление навигации не ломало лист.

| Параметр | A ≥ 1200 | 1040 ≤ A < 1200 | A < 1040 |
|---|---:|---:|---:|
| Видимое основание вокруг листа | 28 | 20 | 8 |
| Внутренние поля листа, горизонталь | 40 | 28 | 20 |
| Внутренние поля листа, вертикаль | 32 | 28 | 24 |
| Поле маргиналий | 256 справа | 224 справа | Под графом, вся ширина |
| Между сетью и маргиналиями | 32 | 24 | 24 по вертикали |
| Минимальная высота сети | 480 | 460 | 420 |
| Декоративные нижние слои | 2 | 2 | 0 |

Высота листа определяется содержимым, не фиксированными 100vh. При низком окне — прокрутка
страницы, не обрезка управления. Максимальную ширину листа не ограничивать искусственно:
на широком экране пространство получает граф. Минимальная ширина сети 600; если поле
комментариев её нарушает, MUST переместить комментарии вниз независимо от breakpoint.

Структура, не набор вложенных карточек:

```text
  обычная навигация │ спокойное основание
                   │  ╭─ единый лист ─────────────────────────────────╮
                   │  │ АТЛАС ИДЕЙ                     контекст источника
                   │  │ Иммануил Кант
                   │  │ Генезис · глубина …     поиск / фильтры
                   │  │
                   │  │           СЕТЬ                     01 / Заметка
                   │  │                                    текст, цитата
                   │  │                                    ссылка в источник
                   │  │
                   │  │ шкала времени            −  100%  +  Вписать
                   │  ╰────────────────────────────────────────────────
```

На первом экране без открытого меню MUST быть один большой материальный объект — лист.
Граф, легенда и подробности MUST NOT получать собственные фон, сплошной периметр и тень.
Выпадающие меню, поля ввода, кнопки и предупреждения — допустимые исключения, не фоновые панели.
Зона сети занимает ≥70% ширины строки «сеть + маргиналии» в двухколоночной раскладке.

**GD-03. Состав.** На листе сверху вниз:
1. Рубрика «АТЛАС ИДЕЙ» и честная строка области поиска (источник / вся библиотека).
2. Заголовок = имя стартовой сущности. Контекстная строка = тип и рецепт.
3. Управление: рецепт, глубина, область, достройка; поиск и фильтры компактной второй
   группой. Перенос групп разрешён, превращение в многоэтажную шапку выше 176px при W=1440 — нет.
4. Сеть + маргиналии. По умолчанию: «Как читать карту», три кратких правила и ключ статусов.
5. Нижняя строка: шкала времени, когда рецепт временной; масштаб и «Вписать» всегда.

Фильтры по умолчанию свёрнуты в подписанную кнопку. Состояние фильтра видно счётчиком;
«Показана часть» — отдельное видимое сообщение, не только тултип. Не показывать пустую
«мини-карту для красоты»: она появляется, если границы графа выходят за видимое поле.

## 3. Материал, палитра и контраст

**GD-04. Локальные токены.** Все новые токены ограничены корнем страницы графа; глобальные
paper/surface/семейства приложения MUST NOT переопределяться. Значения — sRGB HEX.

| Токен `graph-*` | Светлая | Тёмная | Назначение |
|---|---|---|---|
| desk | #302E2A | #101318 | Основание, только декор |
| sheet | #F6F3EA | #20242B | Единая поверхность листа |
| sheet-edge | #E9E4D8 | #191D23 | Нижние слои, без текста |
| ink | #1A222F | #E7E6DF | Основной текст, имена |
| ink-secondary | #48505D | #BFBEB5 | Подписи и пояснения |
| ink-muted | #646D78 | #9A9990 | Годы/метаданные, не мельче 12px |
| rule | #C9C2B5 | #505966 | Только декоративные линейки |
| selected | #923F32 | #E9A18D | Выбор объекта, не ошибка |
| focus | #385B8F | #A4BEEF | Фокус и действия, alias accent |
| generated | #8D5D1C | #E9C67D | Значок/текст происхождения |
| generated-tint | #FBEFD6 | #382C15 | Фон маленького маркера статуса |

Цвета семейств сущностей MUST наследоваться из токенов people / ideas / teachings / texts /
history. Цвет семьи — на знаке/контуре, не на всём имени и не большой пастельной карточке.

**GD-05. Цвет семейств связей.** Это отдельная палитра, не цвет субъектов/объектов.

| Семейство | Светлая | Тёмная |
|---|---|---|
| genesis | #435882 | #A8BCE4 |
| consequences | #456C62 | #A0C8B7 |
| polemic | #8D4550 | #DFA5AF |
| context | #7A633A | #CFB887 |
| structure | #6A547B | #C6B1DF |
| biography | #516570 | #A8BFCA |

Связь может принадлежать нескольким семействам. Выбирать первое из пересечения семейств
отношения с семействами текущего рецепта, в порядке списка рецепта; если пересечение пусто —
нейтральный ink-secondary и текст «Семейство не определено». Нельзя назначать семейство по
исторической догадке. Подпись точного типа и легенда обязательны: шесть цветов не обязаны
различаться всеми пользователями.

Расчёт WCAG для непрозрачного текста на sheet выполнен 2026-11-14: ink 14.41/12.44,
secondary 7.33/8.34, muted 4.73/5.44 (light/dark); цвета связей 5.15–6.40 / 7.52–8.48.
Это проверка HEX-пар, **не** сертификация отрендеренного макета. Итоговые текст/фон MUST
иметь ≥4.5:1, основной текст ≥7:1; существенные нетекстовые знаки/фокус ≥3:1. Прозрачность,
фактура и фотография требуют повторной проверки фактического фона.

**GD-06. Материал.** Радиус листа 3px; никаких скруглений 16–24px на материальных поверхностях.
Два нижних слоя смещены на (2,3) и (4,6) px, не интерактивны. Светлая тень листа:
0 16px 40px rgba(0,0,0,.18), тёмная — rgba(0,0,0,.32). У графа и заметок тени нет.
Фактура — необязательная, неподвижная; opacity ≤0.025 в light, ≤0.015 в dark. Убрать её
под подписями и линиями (маска), либо отказаться от неё целиком. Контент от этого не меняется.
Сгиб — полоса ≤12px у левого поля, вне интерактивной сети; не линия посередине графа.
Декоративные слои MUST иметь pointer-events:none и не попадать в accessibility tree.

## 4. Типографика и ритм

**GD-07.** Только локальные Literata и Onest из дизайн-системы. Нет Google Fonts или новой
гарнитуры для этой страницы. Базовые интервалы: 4, 8, 12, 16, 24, 32, 40px.

| Элемент | Гарнитура | Размер / интерлиньяж | Начертание |
|---|---|---|---|
| Рубрика | Onest | 11 / 16 | 600, tracking .12em, uppercase, secondary |
| Заголовок | Literata | 34 / 42; при A<1040 — 28 / 36 | 500 |
| Управление | Onest | 14 / 20 | 400, активное 600 |
| Имя узла | Literata | 15 / 20 | 500; выбранное 600 |
| Годы узла | Onest | 12 / 16 | 400, tabular-nums |
| Тип выбранной связи | Onest | 12 / 16 | 500 |
| Заголовок заметки | Literata | 20 / 28 | 500 |
| Текст заметки | Onest | 14 / 22 | 400 |
| Цитата | Literata | 16 / 25 | 400, курсив необязателен |
| Номер заметки / шкала | Onest | 12 / 16 | 400 |

MUST NOT уменьшать шрифт для вмещения длинных имён: использовать переносы и увеличение
геометрического зазора. Отступ от знака узла до подписи 8px, до следующей строки 4px.
При z=1 подпись: максимум 176px шириной; до трёх строк. Длинное слово разрешено переносить
по символам (overflow-wrap:anywhere). Если три строки не вмещают имя, в сети допускается
многоточие в любом режиме, включая selected/focus: размер подписи не растёт бесконечно.
Полное имя MUST быть в accessible name и в маргиналии при focus/selection; в списке полное
имя переносится без обрезки. Заголовок страницы и выбранная сущность в подробностях
не обрезаются многоточием. Это правило GD-07 устраняет неопределённость DOC-02.

## 5. Объекты графа

**GD-08. Общая грамматика.** Сохраняем соответствие форм существующим семействам, а не
переставляем квадрат и ромб из раннего концепта. Источник соответствий —
[familyOf](../../../web/src/ui.tsx#L320-L342). Внутренний знак рисуется единым набором штрихов
1.25px с round join/cap, не смесью emoji, объёмных иконок и контуров разных библиотек.

| Объект | Форма и размер z=1 | Содержимое / подпись |
|---|---|---|
| person / people | Медальон 48×60, овальный | Реальный портрет в дуотоне; имя под ним |
| group / people | Круг 40×40 | Два схематичных силуэта, не портрет случайного человека |
| ideas | Квадрат 30×30, угол 2px | Малый наборный знак из двух расходящихся штрихов |
| teachings | Ромб 36×36 | Одна внутренняя ось, без иллюстрации «печати» |
| texts | Прямоугольник 28×36, угол 1px | Контур листа с загибом 5px; название курсивом |
| history | Окружность 32×32, внутреннее кольцо 24×24 | Дата снаружи, не миниатюрный текст внутри |
| Неизвестный тип | Нейтральный шестиугольник 32×32 | «Тип не определён» в подробностях |

Овальная форма и размер person — **локальное исключение для проверки в Ф0.2** относительно
круглого Portrait 40px; не изменение общего компонента. Все остальные страницы без изменений.
Цвет семейства — обводка 1.25px; заливка — sheet. Декоративная штриховка только в заглушке
портрета. Нельзя определять тип только портретом, цветом или формой: есть текст в подробностях.

Портреты MUST иметь источник и разрешённую лицензию. Без изображения/при ошибке загрузки —
монограмма на people-tint, без скачка размеров. В Ф0.2 допускаются локальные ранее подобранные
изображения с указанием происхождения, не генерация «правдоподобного Канта». Если доступных
изображений нет, показывать настоящую заглушку и не объявлять проверенным портретный вариант.

**GD-09. Состояния объекта (накладываются, не подменяют друг друга).**

| Состояние | Визуальная реакция |
|---|---|
| Стартовый узел | Маленький подписанный маркер «Начало» над знаком, ink-secondary; остаётся при выборе другого |
| Hover | Подсветка соседства; имя 600, не увеличение самого знака |
| Selected | Кольцо/контур selected 2px с отступом 4px; имя ink 600; маргиналия открыта |
| Keyboard focus | Независимый внешний контур focus 2px, отступ 8px; не исчезает на selected |
| Hidden by filter | Не рисуется в сети; состояние отражено в счётчике и доступном списке |
| Generated description | Маркер статуса относится к описанию и расположен у него, не делает все связи узла сгенерированными |

Размер в Ф0.2 фиксирован по семейству, без кодирования «важности». Вариант размера по степени
связности отложен: он требует отдельной шкалы и кейсов, иначе портреты создадут ложную иерархию.

## 6. Связи и направление

**GD-10. Геометрия.** Спокойные кривые Безье, без случайного декоративного завитка. Вход и
выход в 4px от контура знака; зазор до bbox подписи любого узла ≥8px. Подписи — часть
collision box. Параллельные линии разводить на 16px в средней точке, не объединять статусы.
Петля — отдельная дуга с подписью, не точка внутри узла. Не рисовать ложные развилки «дерева».

Базовый штрих 1.25px, hover/selected 2px. Толщина НЕ означает число источников, силу влияния
или уверенность. В реестре есть необязательный qualifier strength: при наличии его можно
показать текстом в подробностях, но не автоматически превращать в толщину всех линий.

Стрелка — открытый наконечник 6×5px того же цвета, что линия. Направление всегда
**subject → object** из утверждения, не автоматически слева направо. Пример:
«Кант → испытал влияние → Юм» направлен влево на временной оси. Обратное название допустимо
в пояснении как «Юм повлиял на Канта», но не меняет семантику хранимого утверждения.
Для симметричного отношения стрелок нет. Семантический тест важнее красивого изгиба.

**GD-11. Статусы.** Семейство = цвет линии; статус = стиль и независимый знак.

| Статус | Линия | Маркер и текст |
|---|---|---|
| verified | Сплошная | Галочка ok, «Проверено» |
| sourced | Сплошная | Книга ink-secondary, «По источникам» |
| generated | Пунктир 5px / 4px | Ромб generated на generated-tint, «Сгенерировано» |

Маркер 14×14 с подложкой sheet, размещён на линии без пересечения со стрелкой/подписью;
для generated внутренняя подложка generated-tint. У каждой видимой связи статус MUST
различаться и в обзоре: generated — ромб, verified — галочка, sourced — книга; экранный
размер маркера 14×14 сохраняется при масштабе. Если маркеры пересекаются — разнести их
вдоль линий либо свернуть часть графа в явно помеченный кластер, но не стирать различия.
Полный текст статуса дополнительно доступен в списке и при фокусе/выборе. Это сохраняет
«Показ графа» и устраняет DOC-01; таблица происхождения не заменяется цветом семейства.
Выделенная линия НЕ перекрашивается в selected: семейство сохраняется; выделение толщиной,
подписью и независимым знаком выбора. Не путать selected, polemic и danger.
Состояния «Спорно»/«Противоречит» — отдельные знаки consensus по StatusMark, не замена
происхождения. Если API не отдаёт состояние, макет не изображает его как реальный факт.

Текст точного отношения показывать при hover/focus/selection. Под текстом — вырез линии
с фоном sheet и отступом 4px, не прямоугольная карточка. Кликабельная область линии ≥12px
независимо от толщины штриха. Табличный список отношений — альтернативный путь выбора,
без необходимости Tab по сотням почти невидимых путей.

## 7. Раскладка, масштаб и группы

**GD-12.** Временной рецепт: x отражает год из данных, более поздний узел правее; одинаковые
годы разводятся по y. Шкала имеет равные интервалы лет; нельзя рисовать количественную шкалу
поверх произвольных равных шагов между людьми. Год null — отдельная зона «Дата неизвестна».
Границы эпох не домысливать. Невременной рецепт: свободная стабильная раскладка без временной
шкалы. Одинаковые данные и размер окна SHOULD давать одинаковую начальную геометрию.

Масштаб 0.5–2.0. Управление и маргиналии не масштабируются вместе с сетью.

| Режим | Условие | Что видно |
|---|---|---|
| Подробный | z ≥ .85 | Полные знаки; имена и даты, пока нет пересечений |
| Обзорный | z < .85 | Знаки 16–24px на экране; подписи старта/выбранного/фокуса и ближайших соседей по правилам длины GD-07 |

Приоритет размещения подписей: focus → selected → start → соседи selected → остальные в
порядке степени (равенство по id). Наложение подписей MUST приводить к скрытию менее
приоритетной, не к уменьшению кегля ниже 12px. Имя/дата и портрет скрываются как группа
по правилам режима, но выбранная/фокусная подпись остаётся читаемой ≥12px.
Маркировка generated и shape семейства не исчезают. Кольца фокуса и знаки статусов
сохраняют экранный размер. Минимальные экранные hit-area узлов 32×32, кнопок 36×36.

**GD-13. Кластеры.** Кластеризация входит в первую продуктовую версию, но Ф0.2 показывает
визуальный контракт, а не обещает новый API. Фикстура плотного графа: 48 узлов, 3 группы;
две группы свёрнуты. Кластер — три смещённых малых знака, название и «N узлов · Раскрыть».
Нет прямоугольника или непрозрачного пятна вокруг группы. Контур области допускается только
как незамкнутая очень тонкая линия, без заливки; он не нужен для понимания.

Назвать школу/эпоху можно только по данным; структурный кластер — «Группа связей 1».
Если скрыты generated-рёбра, рядом со счётчиком «◇ N сгенерированных связей» (это не число
узлов). Детали доступны в списке. При раскрытии нельзя терять selected/start и статус.
Порог автоматической кластеризации — НЕ решён этим ТЗ; в макете состояние фиксировано
набором данных. Сводка кластера также содержит раздельные количества verified/sourced;
для generated всегда явная строка с ромбом. Нельзя агрегированием скрывать происхождение.
Реальный алгоритм и порог согласуются в OpenSpec, не выбираются молча.

## 8. Маргиналии и управление

**GD-14.** Заметка: короткая линейка 32×1px rule, номер «01 / СВЯЗЬ», заголовок, StatusMark,
точное утверждение, уточнители, атрибуции, цитаты и ссылки. По содержимому не имитировать
цитату реального философа: без проверенного источника писать «Демонстрационная цитата».
Номера — текущая навигация по выбранному, не выдуманная библиографическая сноска.

Заметка на sheet без рамки/тени; вертикальный отступ между смысловыми группами 16px.
Цитата отделена отступом 12px и коротким штрихом 2px; ширина строки 26–34 знака справа,
до 68 знаков в нижней раскладке. Фон generated-tint применяется только к пометке, не ко
всему полю. Список соседей/отношений открывается здесь же, а не новой карточкой поверх графа.

Клик узла — подробности; двойной клик — перестройка от узла. Действие «Сделать началом»
обязательно дублирует двойной клик кнопкой. Enter — выбрать, Escape — снять выбор и вернуть
фокус инициатору; поиск и список дают доступ ко всем узлам, даже без видимой подписи.
Выбор не срабатывает повторно после drag. Удержанный узел/ввод текста не двигает холст.
Фокус и hover должны давать одинаковую информацию. Колесо над полем — масштаб только
при явном взаимодействии с полем; вне графа обычная прокрутка страницы.

## 9. Состояния системы, данные и честность

**GD-15.** Данные макета явно помечены «Демонстрационные данные». Главный сценарий:
старт person Кант, рецепт генезиса; отдельная смешанная фикстура покрывает 5 семейств.
Исторические примеры в технической фикстуре — не утверждения о достоверности. Нельзя
называть граф «Причинность», если узел-старт в нём Кант и причинности в данных нет.

| Состояние | Внешний вид и действие |
|---|---|
| Первичная загрузка | Одна строка «Загружаем сохранённые связи…», без фальшивых узлов |
| Достройка | Сохранённый граф доступен; рядом текст «Достраиваем связи…», без фиктивного процента |
| Генерация выключена | Видимая строка «Достройка выключена»; данные не исчезают |
| Модель недоступна | Граф сохранённого + Notice, повтор только явным действием |
| Ошибка запроса графа | Notice, «Повторить», сохранены параметры; не маскировать под пустой результат |
| Нет связей | Стартовый узел и текст «Связей пока нет», доступный выбор рецепта/достройки |
| Фильтры скрыли всё | «Нет связей с этими фильтрами» + «Сбросить фильтры», не «База пуста» |
| Достигнут лимит | «Показана часть графа» + раскрытие конкретного узла |

RU/EN, BCE/CE и null-даты не меняют геометрию на ложную. Не добавлять редактирование,
сохранение в личное, административные действия и экраны входа: в этом макете их нет.
Медленный ответ старого запроса после смены рецепта не должен подменять текущий граф.
Повторный выбор уже выбранного не дублирует заметки и запросы.

## 10. Движение и экспорт

**GD-16.** Первичный статичный рисунок читаем сразу. Появление 160ms opacity без обязательной
очереди; hover/focus 120ms; переход вида/fit 200ms, верхняя граница 240ms. Нет пружин,
разлёта, draw-on на несколько секунд и вечной анимации. Reduced motion: мгновенная смена.
Для hover не снижать opacity смыслового текста/статусов: несвязанное приглушается до
ink-secondary, не исчезает. Финальный кадр MUST содержать все линии без ожидания таймера.

Экспорт SVG (будущая реализация) содержит граф с подписями, направлением, ключом статусов,
маркировкой generated и областью данных; стол, тени и органы управления не экспортируются.
При отсутствии нужного шрифта — читаемый fallback. Не терять статусы из-за CSS, маски или темы.

## 11. Комплект сдачи и критерии остановки

**GD-17.** Следующий макет сдаётся как отдельная Ф0.2 с переключаемыми сценариями (изолированное
preview, не новый продуктовый сервер), снимками и отчётом. Старый Ф0 не перезаписывать до
фиксации сравнения. Фикстуры, локальные изображения и лицензии — в одном каталоге рядом
с макетом. Объём локального поведения фиксирован таблицей ниже (уточнение DOC-03).
Обязательное локальное действие нельзя заменить отключённой кнопкой. Для будущего API-
контракта не рисовать фиктивную работающую кнопку; использовать выбор сценария или явное
пояснение «В продуктовой версии», без притворного запроса и без отметки pass.

### Объём исполнения Ф0.2

| Возможность | Обязательно в локальном preview | Только будущий продукт, не проверяется макетом |
|---|---|---|
| Тема, RU/EN, сценарии F1–F4 | Реально переключаются, не меняют URL/сервер | Сохранение настроек аккаунта |
| Выбор узла/связи, hover/focus, Escape | Работа с локальной фикстурой и одной маргиналией | Получение подробностей из API |
| Поиск, список, фильтр | По локальной фикстуре; пустой результат и сброс работают | Серверный поиск/дозагрузка |
| Масштаб, pan, fit, мини-карта | Работа с локальной геометрией; TC-16 обязателен | Производительность на полной базе |

| Экспорт SVG | Контракт описан, кнопки экспорта в preview нет | Реальный экспорт и его тест |

Обязательные кадры/действия перечислены в [кейcах](graph-page-qa/cases.md). Измеримые проверки
не заменяют художественную приёмку. Дизайнер/владелец отдельно отвечает «да/нет»:

1. Без фактуры виден **один лист**, а не вложенные контейнеры?
2. С первого взгляда главным объектом является **сеть**, не декор и не легенда?
3. Портреты, предметные знаки и линии выглядят одной печатной системой?
4. Поля и типографика создают достоинство научного атласа, без реквизита «старой книги»?
5. Современные действия узнаваемы, а не замаскированы под орнамент?

Любой MUST-нарушенный критерий → исправление до показа как готового. Нет портретных
материалов/не проверена тёмная тема → явно «не проверено», не pass. Успешный браузерный
smoke-test не равен одобрению дизайна. После макета — независимый dev-cycle, затем решение
владельца; после одобрения — отдельное OpenSpec-изменение продукта.
