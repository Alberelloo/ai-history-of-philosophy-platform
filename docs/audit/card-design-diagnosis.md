# Карточки сущностей: почему пустые и что можно показать

Дата: 2026-11-26. Задача владельца: `PHILO-SPEC-CARDS.md` (редизайн карточек). Изменение OpenSpec: `openspec/changes/archive/2026-11-27-redesign-entity-cards/`.

## 1. Как устроена карточка сейчас

- **Сервер.** `src/philograph/knowledge/cards.py`, `Cards.card()`. Отдаёт `GET /api/knowledge/v1/entities/{id}/card`. Разделы карточки задаёт словарь `SECTIONS`: тип сущности → список `(код, заголовок, типы связей, направление)`. Каждая строка раздела — утверждение онтологии (`Statements.about`). Утверждения, которые не попали ни в один раздел, клиенту не отдаются вовсе.
- **Клиент.** `web/src/FullCard.tsx` — полная карточка в правой панели (`SidePanel`, ширина `--panel: 28rem`). `web/src/CardPopup.tsx` — компактное окно у упоминания (`--popover: 23rem`). Полная карточка выводит все разделы одним шаблоном для любого типа:
  - у персоны — `Lifeline`;
  - сводка «Проверено: N · По источникам: N · Сгенерировано: N»;
  - у каждой строки: текстовая метка статуса (`StatusMark` с подписью), «— так считает: …», «не согласны: …», цитаты-ссылки;
  - внизу «Где читать» и рецепты графа.

## 2. Почему карточки пустые

Проверено на локальной базе `.stack` (только чтение, копия в scratchpad; 30 сущностей). Для каждой сущности построена карточка `Cards.card(generation=False)` и сравнена с утверждениями о ней.

| Тип | Утверждения в онтологии | Строк в карточке |
|---|---|---|
| Произведение (5 из 5) | `dating`, `author`, `expresses`/`discusses`, входящее `influenced_by` | **0** |
| Группа (4 из 4) | `group_kind`, входящее `member_of` (состав) | **0** |
| Учение «Имматериализм» | входящее `discusses` (в каком труде) | **0** |
| Позиция «Методическое сомнение» | входящее `expresses` (в каком труде) | **0** |
| Событие (5 из 5) | `dating`, `event_kind` | 1 (вид события не показан) |
| Персона | `lifespan`, `person_role`, `author` (вх.), `member_of`, `influenced_by` | роль (`person_role`) не показана |
| Эпоха | `dating` | 1 (как и задумано) |

Причины, по убыванию веса:

1. **Карточка отбрасывает данные, которые есть (код).** В `SECTIONS` нет ключей `term`, `group`, `place`: их карточка всегда без разделов. У `work` только `context` («Исторический контекст»), поэтому даже автор и дата труда не видны. Перечисляемые и значимые свойства (`group_kind`, `event_kind`, `person_role`) не входят ни в один раздел. У идей (учение, позиция, понятие) нет входящих `discusses`/`expresses` («в каком труде») и `holds`/`advanced` в понятном виде («к кому относится»). Это прямой ответ на C3–C5.
2. **Онтология редкая (данные).** По диагнозу переизвлечения (`docs/process/spec-ontology-reextraction.md`) на 209 источников 1099 утверждений, 20 557 отброшено; персон 62. У большинства не-персон 1–3 утверждения. Даже после исправления п. 1 часть карточек останется короткой. Тогда карточке нужно честное короткое состояние: «Известно мало: …» и то, что есть. Белого экрана быть не должно.
3. **Описаний нет.** Ни у одной сущности нет утверждения `description`. Описание пишет модель по запросу, только при включённой генерации (`description_pending`). Без генерации карточка начинается сразу с разделов, и «что это» не сказано. Для краткой сводки (как у Wikipedia) карточке нужна строка «что это», собранная из уже имеющихся данных: вид группы, вид события, роль персоны, автор и год труда.
4. **Шум вместо содержания (персона).** Годы жизни показаны трижды: в шапке, `Lifeline` и строкой раздела «Годы и места жизни». У каждой строки повторяется текстовая метка статуса и «так считает: …». Сводка природы знания — счётчики, а не сведения. «Где читать» занимает низ карточки. Узкая панель 28rem (448 px) уплотняет всё это в длинную ленту.

## 3. Что можно показать по типам (из реестра `registry_data.RELATIONS`)

Связи реестра, которые уже извлекаются (все, кроме `synthesizes`, помечены `v0`). «вх.» — утверждение, где сущность стоит объектом.

| Тип | Инфобокс (факты) | Списки | Откуда «к кому/чему относится» |
|---|---|---|---|
| Персона | роль (`person_role`), годы (`lifespan`), основное место (`lived_in` + страна по координатам) | где жил (свёрнуто), повлияли / повлиял на (`influenced_by` и подтипы в обе стороны), школы (`member_of`, `founded`), учения (`holds`, `advanced`), интересы, труды (`author` вх.), эпоха | — |
| Понятие | определение (`definition`), введено (`introduced_by` через термин `denotes` вх.), эпоха | трактовки (`conception_of` вх.), связанные (`narrower`, `opposed_to`, `similar_to`, `presupposes`), в каких трудах (`discusses` вх.) | авторы трудов, где рассматривается; термины (`denotes` вх.) |
| Учение, позиция, проблема, аргумент, концепция | что это (описание), часть чего (`part_of`) | сторонники (`holds` вх., `advanced` вх.), в каких трудах (`expresses`/`discusses` вх.), состав (`part_of` вх.), ответы (`answers`), аргументы (`supports`/`attacks` вх.), влияния, контекст | сторонники и авторы трудов |
| Термин | обозначает (`denotes`), введён (`introduced_by`), происходит от (`derives_from`) | переводы (`translated_as`), в каких трудах (`discusses` вх.) | кем введён, что обозначает |
| Произведение | автор (`author`), дата (`dating`), часть чего (`work_part_of`) | вопросы и сферы (`discusses`, `expresses`), ссылается на (`cites`), написано в ответ (`written_in_response`), влияние (`influenced_by` вх.), контекст | автор |
| Событие, явление, идейное событие | вид (`event_kind`), когда (`dating`), где (`happened_in`) | участники (`participated` вх.), на что повлияло (`stimulated`), идейное событие: материал, результат, в произведении, обстоятельства | участники |
| Группа | вид (`group_kind`) | состав (`member_of` вх.), основатели (`founded` вх.), учения (`holds`), полемика (`debated`), работали в ней (`worked_at` вх.) | состав |
| Место | координаты (`coordinates`), страна по координатам | кто жил (`lived_in` вх.), что произошло (`happened_in` вх.) | кто жил, что произошло |
| Эпоха | датировка — **как есть** | как есть | — |

Чего в онтологии нет:
- поля «интересы» (Wikidata P101) нет. Интересы можно вывести из того, что есть: понятия и проблемы, которые рассматривают труды персоны (`author` вх. → `discusses`), и учения, которых она держится. Такой вывод помечается как вывод, а не утверждение.
- страны у места нет. Её даёт координата места через уже имеющийся клиентский модуль `web/src/map/geo/countries.ts`, либо её нет вовсе.

## 4. Выводы для изменения

- Сервер: разделы по каждому типу, включая `term`, `group`, `place` и полноценный `work`. Свойства-перечисления (`*_kind`, `person_role`) — в инфобокс, а не в списки.
- Клиент: шаблон по типу (инфобокс плюс короткие списки), статус строки цветом с одной легендой, без текстовых меток у каждой строки. У персоны — без `Lifeline` и «Где читать». Карточка шире (C9).
- Пустое состояние: «Известно мало», а при совсем пустой — честная подсказка. Белого экрана быть не должно.
