# ADR-0003: Каталог источников в репозитории вместо автоматического обхода сайтов

**Статус:** принято
**Дата:** 2026-11-06
**Решают:** автор проекта

## Контекст

Библиотеке нужен понятный вход: какие издания загружать, откуда, на каком основании их можно показывать. И правила, что делать, когда источник на сайте меняется, пропадает или переезжает.

Конвейер (получение, извлечение, качество, структура, публикация, версии, перенос ссылок на абзацы) уже есть. Сейчас он запускается только кодом демо-сидов. Ошибка с лицензией — юридический риск. Ошибка с качеством текста портит учебник.

## Решение

- **Каталог.** Источники перечисляются в `sources/catalog.yaml` по схеме `sources/catalog.schema.json`. Запись добавляет человек или агент командой `add`: адаптер сайта собирает метаданные. Одобрение записи — решение по лицензии.
- **Синхронизация.** Команда `sync` приводит библиотеку к каталогу.
- **Проверка обновлений.** Плановая проверка раз в неделю идёт условными запросами. Новая версия публикуется сама, только если изменения малы.

## Рассмотренные варианты

### А. Каталог в git (выбрано)
| Критерий | Оценка |
|---|---|
| Сложность | низкая: файл, схема, четыре адаптера |
| Контроль лицензий | высокий: каждая запись проходит ревью в PR, видно, кто и когда одобрил |
| Воспроизводимость | полная: по каталогу и снимкам библиотека собирается заново |
| Масштаб | сотни записей без труда; тысячи потребуют разбить файл по разделам |

### Б. Автоматический обход сайтов (поиск новых изданий по расписанию)
| Критерий | Оценка |
|---|---|
| Сложность | высокая: поиск, дедупликация, ранжирование |
| Контроль лицензий | низкий: решение принимала бы автоматика |
| Нагрузка на чужие сайты | заметная |

### В. Таблица в базе и страница оператора
| Критерий | Оценка |
|---|---|
| Сложность | средняя: интерфейс, права, история |
| Контроль | без ревью PR и истории git |
| Когда пригодится | когда загружать будут пользователи; страница сможет писать в тот же формат |

## Компромиссы

Метаданные с сайта и правки человека хранятся раздельно. Поэтому повторный сбор не затирает ручные исправления, зато запись длиннее.

Автопубликация ограничена 2% удалённых абзацев. Опечатки обновляются сами, крупная переработка — нет.

Источник не снимается сам, если сайт пропал: у нас есть снимок, а чужой сбой не должен ломать учебник.

## Последствия

- Проще: добавить источник, понять, откуда он, повторить загрузку, отозвать.
- Сложнее: сайт без адаптера требует ручных метаданных (`direct`).
- Вернуться позже: страница оператора поверх того же формата; разбиение каталога по разделам, когда записей станет много.
