# ADR-0001: Технологический стек

**Статус:** принято
**Дата:** 04.11.2026
**Кто решает:** автор проекта

## Контекст

Ограничения из [system-design.md](../../product/system-design.md):
- один разработчик с AI-ассистентом;
- микросервисы на одном сервере, запуск одной командой, без Kubernetes;
- реляционная база со схемами по сервисам и отдельная векторная база;
- очередь для офлайн-работы и отложенной записи;
- около сотни источников и десятки тысяч абзацев;
- сотни одновременных пользователей в худшем случае;
- LLM — DeepSeek по API, эмбеддинги у внешнего провайдера.

Тяжёлая часть работы — тексты: извлечение из PDF и EPUB, распознавание сканов, морфология русского языка, вызовы моделей. Требование к тестам: на каждое требование спецификаций свой тест, который проверяет результат и журнал событий.

## Решение

| Область | Выбор |
|---|---|
| Язык сервисов и офлайн-задач | Python 3.13 |
| Веб-фреймворк сервисов | FastAPI: потоковые ответы, схемы на pydantic, описание интерфейса с версиями |
| Устройство кода | один репозиторий и один пакет `philograph`; каждый сервис в своём подпакете со своим приложением и контейнером; границы между подпакетами проверяет import-linter |
| Реляционная база | PostgreSQL 16, схема на каждый сервис; доступ через SQLAlchemy 2; миграции — небольшой свой механизм с версиями по схемам (`platform/db.py`): Alembic с несколькими схемами и SQLite в тестах сложнее, чем нужно на нашем объёме |
| Векторная база | Qdrant, в отдельном контейнере (решение А2) |
| Полнотекстовый поиск | PostgreSQL, индекс по леммам: нормализация (морфология, «ё», дореформенная орфография) делается кодом до записи в индекс |
| Морфология | pymorphy3 для русского, стеммеры Snowball для остальных языков |
| Очередь задач | своя очередь на PostgreSQL (`SELECT … FOR UPDATE SKIP LOCKED`) и исходящая таблица событий в той же базе |
| Файловое хранилище | локальный том с адресацией по отпечатку содержимого, за интерфейсом; позже S3-совместимое |
| Извлечение текста | PyMuPDF для PDF, разбор EPUB и HTML через zipfile и lxml |
| Распознавание сканов | Tesseract 5 через pytesseract; сравнивается с другими способами на эталонных страницах |
| LLM | DeepSeek через HTTP-интерфейс, совместимый с OpenAI, на httpx без SDK провайдера |
| Эмбеддинги | провайдер выбирается при реализации поиска, за общим интерфейсом; до выбора — тестовый провайдер |
| Журнал | structlog, события в JSON, каталог событий проверяется в тестах |
| Веб-клиент | TypeScript, React, Vite; граф на Cytoscape.js |
| Тесты | pytest; маркер `req` связывает тест с требованием спецификации; скрипт прослеживаемости проверяет покрытие |
| Качество кода | ruff (линтер и форматирование), import-linter |
| Развёртывание | Docker Compose на одном сервере, Caddy как обратный прокси с автоматическим HTTPS |

## Рассмотренные варианты

### Язык сервисов

| Вариант | Сложность | Экосистема для текстов | Знакомство | Итог |
|---|---|---|---|---|
| Python | низкая | лучшая: PyMuPDF, Tesseract, pymorphy3, клиенты моделей | высокое | **выбран** |
| TypeScript на Node | низкая | слабая для распознавания и морфологии | среднее | один язык с клиентом, но тяжёлую часть пришлось бы выносить в Python |
| Go | средняя | слабая | низкое | быстро, но мало библиотек для текстов |

### Очередь задач

| Вариант | Инфраструктура | Исходящая таблица в одной транзакции | Итог |
|---|---|---|---|
| Очередь на PostgreSQL | ничего нового | да | **выбран**: на нашем объёме хватает с запасом |
| Redis и arq или RQ | ещё один контейнер | нет, нужен отдельный отправщик | лишний компонент |
| RabbitMQ | ещё один контейнер и протокол | нет | избыточен |

Очередь стоит за интерфейсом: если её станет мало, заменяется реализация, а не обработчики.

### Полнотекстовый поиск

| Вариант | Морфология и дореформенная орфография | Инфраструктура | Итог |
|---|---|---|---|
| PostgreSQL с леммами, посчитанными кодом | полный контроль | ничего нового | **выбран** |
| PostgreSQL со встроенным словарём russian | только стемминг, «ѣ» и «і» не понимает | ничего нового | грубо |
| OpenSearch | хорошая, но настраивать отдельно | тяжёлый контейнер, память | избыточен |

### Векторная база

Qdrant выбран по решению А2 (отдельная векторная база). Рассматривался pgvector в той же PostgreSQL: проще, но решение А2 принято сознательно, а фильтрация по источнику и видимости в Qdrant есть из коробки. Векторная база производная: при смене решения она пересобирается из абзацев.

### Веб-клиент

| Вариант | Всплывающие окна, поток, граф | Итог |
|---|---|---|
| React и TypeScript | всё есть, Cytoscape.js для графа | **выбран** |
| Серверные шаблоны и HTMX | поток и всплывающие окна возможны, граф труднее | проще, но интерфейс чтения слишком интерактивный |

## Компромиссы

- Один пакет Python на все сервисы упрощает работу одного разработчика: общие инструменты, одна версия зависимостей. Цена — риск, что сервисы начнут лезть друг в друга. Его снимают правило «только через интерфейсы» из `service-runtime` и import-linter в CI.
- Своя очередь на PostgreSQL — немного своего кода вместо готовой библиотеки. Зато транзакционная исходящая таблица получается сама.
- Тесты локально идут на SQLite, а в CI ещё и на PostgreSQL. Код доступа к данным не использует особенностей одной базы, кроме полнотекстового поиска, у которого есть замена для тестов.

## Последствия

- Проще: одна команда запуска, один язык для сервисов и конвейеров, тесты без внешней инфраструктуры.
- Сложнее: два языка в репозитории (Python и TypeScript), Node нужен только для клиента.
- Вернуться позже: провайдер эмбеддингов, способ распознавания сканов, хостинг (сервер выбирается перед этапом 6).
