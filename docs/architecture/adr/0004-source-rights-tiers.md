# ADR-0004: Правовой статус источников и сбор in-copyright

**Статус:** принято
**Дата:** 2026-11-23
**Решают:** автор проекта

## Контекст

Библиотека собирает только издания в общественном достоянии или под открытой лицензией: правило
«70 лет после смерти автора» зашито в код, а понятия «под охраной» и «статус неизвестен» в модели
нет. Вне корпуса остаются свободно доступные в сети издания, которые формально ещё охраняются
копирайтом, но нужны для полноты онтологии — сущностей, связей и утверждений.

Пользователь хочет собирать весь открытый корпус, но раздавать читателям только легально
доступную часть, а правовой статус каждого источника явно и обязательно хранить в базе.

## Решение

- **Правовой статус `rights_tier`** — обязательное поле источника: `public_domain`, `open_license`,
  `in_copyright`, `unknown`. Хранится в столбце `sources.rights_tier` (миграция `library` № 6),
  по умолчанию берётся из тира вида лицензии (`licenses.yaml` → `tier`), перемаркируется
  оператором с доказательством; смена пишется в таблицу `rights_log`.
- **Граница показа.** Читателям отдаются только `public_domain` и `open_license`.
  `in_copyright`/`unknown` скрыты из библиотеки, поиска и ответов ассистента (существующий
  механизм разрешений `display`/`external_processing`/`quoting`, а не новый слой).
- **Онтология по всему корпусу.** `in_copyright` обрабатывается сервисом знаний как производные
  данные (сущности, связи, утверждения); полные тексты и цитаты читателю не отдаются.
  `unknown` не обрабатывается вовсе — консервативно до классификации.
- **Критерии — данные, а не код.** Юрисдикционные пороги (70 лет, США pre-1930/95/120,
  РФ ст. 1281–1282) и соответствие статуса разрешениям — в `sources/rights-tiers.yaml`.

## Рассмотренные варианты

| Критерий | Отдельное событие `source.processed` | Публикация с `display: false` + фильтры (выбрано) |
|---|---|---|
| Сложность | выше: новое состояние версии и событие, свой путь в знании и поиске | ниже: переиспользует `source.published` и существующие фильтры разрешений |
| Риск утечки текста | низкий | низкий: поиск не индексирует `display: false`, читательские интерфейсы уже фильтруют |
| Инкрементальность | нужен учёт «предыдущей обработанной версии» | прежняя версия — как у публикации |

## Компромиссы

- Сбор полных текстов `in_copyright` — **решение и правовой риск владельца**: тексты хранятся
  серверно только для производной онтологии, но их хранение и отправка внешним сервисам
  (эмбеддинги, LLM) для извлечения фактов — отдельный правовой вопрос в каждой юрисдикции.
- `unknown` по умолчанию ничего не делает; источники с неизвестным статусом требуют внимания
  оператора.
- Расширение статуса в более открытый (к читателю) требует доказательства и аудируется.

## Последствия

- Проще: собирать весь открытый корпус для онтологии, не раздавая охраняемый текст.
- Сложнее: оператор должен классифицировать `unknown`; добавлен журнал перемаркировок.
- Вернуться позже: автоматизировать классификацию по Wikidata/лицензиям, добавить страницу
  оператора поверх `rights_log`.
