# ADR-0002: Провайдер эмбеддингов

**Статус:** принято частично: интерфейс и способ выбора приняты, конкретный провайдер выбирается замером
**Дата:** 04.11.2026
**Кто решает:** автор проекта

## Контекст

У DeepSeek нет API эмбеддингов (system design, блок 5). Поиску нужны эмбеддинги абзацев на русском, английском, немецком, латыни и древнегреческом и межъязыковой поиск: запрос на русском должен находить английский абзац. Без ключей провайдеров и без набора для оценки сравнить модели нельзя, а выбор «по описанию» легко ошибочен на философских текстах.

## Решение

1. Эмбеддинги — роль `embeddings` сервиса LLM ([config/llm.yaml](../../../config/llm.yaml)). Провайдер подключается через HTTP-интерфейс, совместимый с OpenAI (`/embeddings`); так работают OpenAI, Jina и большинство других.
2. Индекс хранит модель у каждой коллекции. Смена модели — переиндексация рядом со старым индексом и переключение в конце, без простоя (`paragraph-indexing`, «Версия модели эмбеддингов»).
3. Провайдер выбирается замером на наборе вопросов из `add-evaluation-harness`: recall@k и MRR на русских и межъязыковых вопросах, стоимость полного прохода по библиотеке.

## Кандидаты для замера

| Кандидат | За | Против |
|---|---|---|
| OpenAI text-embedding-3-small / -large | дёшево (small), хороший мультиязычный уровень | текст уходит в США; древнегреческий слабо |
| Jina embeddings v3 | сильный мультиязычный, длинный контекст | отдельный аккаунт |
| Cohere embed-multilingual-v3 | сильный мультиязычный | дороже |
| Локальная bge-m3 или multilingual-e5 | текст не уходит наружу, нет расходов | нужен процессор и память на сервере, отдельный контейнер |

## Последствия

- До замера в настройке стоит заглушка. Поиск по словам работает полностью, смысловой канал проверяется тестовой моделью с понятиями.
- Если победит локальная модель, она подключается как ещё один провайдер за тем же интерфейсом. Разрешение «внешняя обработка» тогда для эмбеддингов не нужно, но для LLM остаётся.
